# 仕様: 整地ボット（SimulatedPlayer）

> 作成日: 2026-08-22
> 実装方針: [../imp.md](../imp.md)
> 関連調査: [../research/05-simulated-player.md](../research/05-simulated-player.md)

## 0. やりたいこと

**スーパーフラットのワールドで、掘れて凸凹になった地面を平らに戻す。**

ボットは**本物のプレイヤーと同じように歩いて**作業する。
コマンドで一瞬で埋めるのではなく、働いている様子が見えることを重視する。

## 1. 方式: `SimulatedPlayer`

**`@minecraft/server-gametest` の `SimulatedPlayer` を使う。**
アドオン（Script API）だけで完結し、外部プログラムも BDS も不要。

> ### これまでの遠回り（記録として残す）
>
> 以下は**いずれも要件を満たさなかった**。同じ道を辿らないため記録する。
>
> | 試したもの | 結果 |
> | --- | --- |
> | `minecraft:npc` | 見た目だけの置物。歩かない・プレイヤー一覧に出ない |
> | `bedrock-protocol` で自作ボット | 接続はできたが `player_auth_input` で移動できず |
> | NetherNet で通常ワールドに接続 | 接続は成功したが、**Xbox Live 認証が必須**で「任意の名前で入れ放題」が原理的に不可能 |
>
> **`SimulatedPlayer` は最初から公式 API として存在していた。**
> `reference/` にローカル取得済みの公式ドキュメントを先に調べるべきだった。

### 1-1. できること

`SimulatedPlayer` は `Player` を継承し、以下を持つ。

| 分類 | メソッド |
| --- | --- |
| **経路探索移動** | `navigateToLocation` / `navigateToBlock` / `navigateToLocations` |
| 直線移動 | `moveToLocation` / `moveToBlock` / `move` / `moveRelative` |
| **ジャンプ** | `jump` |
| **採掘** | `breakBlock`（壊れるまで殴り続ける）/ `stopBreakingBlock` |
| **設置** | `useItemOnBlock` / `useItemInSlotOnBlock` |
| 持ち物 | `giveItem` / `setItem` |
| 視線 | `lookAtBlock` / `lookAtLocation` / `lookAtEntity` |
| その他 | `chat` / `attack` / `fly` / `swim` / `setSkin` / `disconnect` |

**任意の名前で、何体でも生成できる。**

```ts
test.spawnSimulatedPlayer(location, "整地くん", GameMode.Survival)
```

### 1-2. 制約

- **`@minecraft/server-gametest` は beta のみ**（stable 版が存在しない）。
  実験トグル「Beta APIs」が必要
- **`SimulatedPlayer` は `Test` からしか生成できない。**
  `Test` は `register()` のコールバック引数としてのみ得られる
  → **GameTest として起動する必要がある**（[2章](#2-起動のしかた)）
- `spawnSimulatedPlayer` は **restricted execution で呼べない**

## 2. 起動のしかた

`SimulatedPlayer` を作るには `Test` インスタンスが要り、
それは `gametest.register()` のコールバックでしか手に入らない。

```ts
import * as gametest from "@minecraft/server-gametest";

gametest.register("level", "start", (test) => {
  const bot = test.spawnSimulatedPlayer({ x: 1, y: 2, z: 1 }, "整地くん");
  // ここでボットを保持し、以降 system.runInterval で動かす
}).maxTicks(TICKS_FOREVER).structureName("level:empty");
```

ゲーム内で起動する:

```
/gametest run level:start
```

### 2-1. テストが勝手に終わらないようにする

GameTest は既定で一定 tick 後に「失敗」して終了し、**ボットも消える**。

- `.maxTicks(<大きな値>)` で延長する
- `test.succeed()` を呼ばない（呼ぶとその場で終わる）

> - [ ] **未検証**: テスト終了時に SimulatedPlayer が消えるか。
>   消えるなら、実用上どこまで延ばせるかを確認する

### 2-2. 構造（structure）が要る

GameTest は構造ファイルの上で実行される。空の構造を用意する。

`behavior_packs/<名前>/structures/level/empty.mcstructure`

> - [ ] **未検証**: 空構造の作り方。`/structure save` で作れるはず

## 3. 整地の手順

### 3-1. 整地くんの挙動（確定仕様 / 2026-08-22）

**呼び出した時点で自動的に整地を始める。** コマンドで指示する必要はない。

1. **自分のいる場所から最も近い**、埋めるべき場所を選ぶ
2. そこへ歩いて行き、ブロックを置く
3. 1 に戻る（対象が無くなるまで繰り返す）

### 3-2. 埋める対象

**Y = -63, -62, -61 の空気ブロック。**

- `-64` は岩盤なので触らない
- 上限は `GROUND_Y = -61`

### 3-3-0. 担当は「1マス」ではなく「縦3マスの列」（2026-08-22 変更）

**ボットは (x, z) の列を1つ受け持ち、-63/-62/-61 を全部埋めるまで担当する。**

- 次に埋めるべき高さは**毎 tick 数え直す**（他のボットが埋めることがある）
- 列が埋まりきったら完了
- **予約も保留も列の単位**で持つ（`keyOf` は高さを含めない）

穴に落ちたときに自分の足元を埋めて上がってくる動き（3-8）が
「その列を埋める」ことそのものなので、
列を単位にすると**脱出と作業が一致する**。

### 3-3. 優先順位（確定 / 2026-08-22）

| 順位 | 基準 |
| --- | --- |
| 1 | **低い順**（深い穴が最優先） |
| 2 | 同じ高さなら**誰も狙っていない列が先**（相乗りは後） |
| 3 | そこまで同じなら**近いほど選ばれやすい抽選** |

並べるとこうなる。

```
最下層の空き > 最下層の相乗り > 次の層の空き > 次の層の相乗り > ...
```

**高さが先、同じ高さの中で空きが先。**
空いている次の層より、相乗りしてでも最下層を埋める。

**近さより低さが優先。** そのため
「最初に見つかったものを返す」方式では足りず、
**範囲を全部見てから一番低い列を選ぶ**。

**2 は「一番近いマス」ではなく抽選にする。**
常に最も近いマスを選ぶと、複数体が同じ場所に集まってしまう。
重みを `1 / (距離 + 1)` にすると、近くを優先しつつ自然に散る。

> 二乗距離は使わない。近い1マスに偏りすぎて抽選の意味がなくなる。
> **低さは抽選にしない。** 低い順という決めごとは崩さない。

抽選には候補を集める必要があるので、いちばん低い高さのマスを
`CANDIDATE_LIMIT` 件まで溜める。
岩盤の1つ上（`BEDROCK_Y + 1`）の候補が溜まった時点で走査を打ち切ってよい
（それより低い場所は無いので、全部見ても順位は変わらない）。

乱数は `scan.ts` で作り、抽選そのものは `logic.ts` の純粋関数
`pickWeightedByNearness()` に渡す（検証できるようにするため）。

### 3-4. 地形の把握（アドオン側）

**Script API で直接地形を読む。** ボット自身に探らせない。

- `dimension.isChunkLoaded()` で未読み込みを除外する
- **`system.runJob` で分割する**（watchdog 対策）

#### `getTopmostBlock` を使ってはいけない（2026-08-22）

**その列の一番上のブロックを見るやり方は間違い。**
空中にブロックが1つ浮いているだけで「この列は埋まっている」と判定してしまい、
足元の -63 が穴でも見逃す。実際にこれで埋まらなくなった。

**対象の高さ（`BEDROCK_Y+1` 〜 `GROUND_Y`）だけを下から見て、
最初に見つかった空気の高さ**を使う。上に何があろうと関係ない。
3段しかないので `getBlock` 3回で済む。

#### ジェネレータの中で例外を外へ逃がしてはいけない（2026-08-22）

`system.runJob` に渡したジェネレータが途中で死ぬと **`onDone` が呼ばれない**。
呼び出し側は「探索中」のまま固まり、**そのボットは二度と動かなくなる**。

- 走査の1列ぶんは必ず `try`/`catch` で包む
- 保険として、呼び出し側にも見張りを置く（`SEARCH_WATCHDOG_TICKS`）

### 3-5. 移動

`navigateToLocation` で経路探索する。ただし穴だらけの地形では
**経路が見つからないことが多い**（実測: `isFullPath=false`）。

対策:

- 目標は**穴の中ではなく地表の高さ**にする（穴の中には立てない）
- 経路が無ければ **`moveToLocation` で直線移動**する
- **進んでいなければジャンプする**（`isOnGround` を見てから）

### 3-6. 設置

**`useItemOnBlock` の第2引数は「クリックする既存ブロック」**であって、
置きたい空間ではない。空気を指定しても何も起きない。

対象の**真下にある既存ブロック**を探し、その上面（`Direction.Up`）に置く。

### 3-7. サバイバルで動かす（2026-08-22 変更）

ボットは **Survival** で生成する。以前は Creative だった。

Creative なら在庫も体力も考えなくてよかったが、
サバイバルだと次の3つを自前で面倒みる必要がある。

#### ブロックは常に持たせる

**設置の直前に毎回 `setItem` で持ち直す。**
残数を数えたり補充を判断したりしない。毎回入れ直せば必ず足りる。

#### 体力・空腹は常に満タンに戻す

**体力を無限にする。** 落下・窒息・殴り合いで死なせない。

`EntityHealthComponent` は `EntityAttributeComponent` を継承しているので
`resetToMaxValue()` が使える。空腹と飽和も同じ
（空腹が減ると自然回復が止まり、走れなくなる）。

**全ボットぶんを1つの `runInterval` でまとめて処理する。**
ボットごとにタイマーを持つと100体で100本になる。

#### 掘るには道具が要る

**素手だと土を掘るのに約0.75秒かかる**（Creative では一瞬だった）。
埋没からの脱出（3-9）は毎 tick 掘ろうとするので、
道具が無いと**永久に抜け出せなくなる**。

設置と同じ考え方で、**掘る直前に毎回シャベルを持ち直す**。
持ち替えは `setItem` のスロット指定でやる（設置用と掘削用で別スロット）。

### 3-8. 自分の足元を埋める

立っている場所は自分の体が邪魔で置けない。
**ジャンプして浮いている間に置く**（プレイヤーが柱を立てるのと同じ）。

ジャンプから着地までは数 tick かかるので、
「ジャンプした」「置く」を tick をまたいで行う。

> **「ジャンプしてから N tick 後に置く」と決め打ちしてはいけない。**
> `WORK_INTERVAL` を変えると、体がまだそのマスから抜けていないうちに
> 置こうとして失敗し、**ジャンプし続けるだけ**になる（2026-08-22 に実際に発生）。
> `Math.floor(bot.location.y) > target.y` で**実際に抜けたか**を見る。
> 一定時間経っても抜けられなければ跳び直す。

### 3-9. 埋まった / 詰まったとき

**経路は壊してよい。**

- 足元・頭がブロックで塞がれたら、その場を掘って抜ける
- 目標へ進めていなければ、まずジャンプ、それでも駄目なら進路を掘る

掘ってよい範囲には制限がある。

- **真上下左右だけ**（x/z のずれの合計が1以内、y は足元と頭の高さ）。
  離れた場所を壊すと、他のボットの足場や作りかけの地面まで崩れる
- **斜めは掘らない**（2026-08-22 修正）。
  「x も z も1マス以内」だと斜めが通ってしまう。
  ずれの**合計**で見る（0 = 足元、1 = 真横、2 = 斜め）。
  斜めまで許すと、通る必要のない角まで削って地形が荒れる
- 進路を掘るときも、**ずれの大きい方の軸だけ**を1マス進む。
  両方の軸を同時に動かすと斜めのマスを指してしまい、
  弾かれて何も掘れないまま詰まる
- 岩盤は掘らない
- **他のボットの足場は掘らない**

判定は `tryDig()` 1箇所に集約する。掘る場所が増えても条件が散らばらないため。

### 3-9-1. 諦める条件（2026-08-22 追加）

**1マスに 10 秒（`PLACE_TIMEOUT_TICKS`）掛かったら諦めて次へ。**

経路は壊してよいので「到達不可能」は理屈の上では無いが、
それでも**進まないまま張り付く**ことは実際に起きる。
諦めたマスは `DEFER_TICKS` の間だけ候補から外す（3-A-5 と同じ扱い）。

**どいている時間は数えない。** 自分の都合で止まっているわけではないため。

### 3-9-2. 優先順位（2026-08-22 追加）

埋める作業より、**自分が動けなくなるのを避ける方が優先**。
`tickInner` は次の順に見る。

| 順位 | 状況 | すること |
| --- | --- | --- |
| 1 | 足元・頭が塞がっている | 掘って抜ける |
| 2 | どいてと言われている | どく |
| 3 | それ以外 | 埋める |

1〜2 はいずれも**抜けられないまま張り付く可能性がある**ので、上限を持たせる。
上限を過ぎたら通常の作業に戻す。

> 上限で諦めたあと、カウンタを 0 に戻してはいけない。
> 次の tick でまた同じ処理が始まり、往復して何も進まなくなる。
> また、**中断したジャンプの状態は消しておく**。
> 残すと通常経路が跳ばずに置こうとして、自分の当たり判定に阻まれる。

> **高さで動きを変えるルールは置かない**（2026-08-22 決定）。
> 「最下層にいたら抜ける」「地表(-60)にいるときだけ整地する」を
> 順に試したが、どちらも他のルールと条件が重なって挙動が読めなくなった。
> **ボットは自分の高さに関係なく、同じ手順で整地する。**
> 穴に落ちても `wouldBurySelf`（3-8）が足元を埋めて自然に上がってくる。

### 3-10. 設置できたかの確認

`useItemOnBlock` は**失敗しても例外を投げない**。
数えるだけだと「置けていないのに成功」になる。

設置は即時反映されないので、**次の tick で `getBlock().isAir` を見て確かめる**。

## 3-A. 複数体で動かす（確定 / 2026-08-22）

100体規模を想定する。互いの邪魔をしないための調整を
`registry.ts`（共有状態）に集める。

### 3-A-1. 担当の予約（2026-08-22 変更）

予約は**独占ではなく優先の目安**にする。

- **空いている列を優先して選ぶ**
- **空きが1つも無ければ、誰かが狙っている列も取りに行く**（相乗り）
- 相乗り先で相手が邪魔なら、殴ってどかす（3-A-3）
- 1列終えたら予約を解放する。退場時は全て解放する

> 以前は「予約済みは候補にしない」だったが、
> それだと**空きが無くなった時点で全員が止まる**。
> 相乗りを許す方が、最後まで手が空かない。

**空きの優先は高さの次。**
順位は 3-3 のとおり「高さ → 空き → 近さ」。

> 実装では**高さを2倍して相乗りぶんを1足す**と、
> この順序がそのまま1つの数値になる。
> 分岐を並べるより読みやすく、間違えにくい。
>
> ```
> y=-63 空き → -126   y=-63 相乗り → -125
> y=-62 空き → -124   y=-62 相乗り → -123
> ```
>
> 走査を打ち切ってよいのは**最良の順位（最下層の空き）**が
> 十分溜まったときだけ。

### 3-A-2. 着いたら既に埋まっていた

**毎 tick 確認し、埋まっていたら即中止して次を探す。**
向かっている途中に他のボットが埋めることがあるため。

**置く直前にもう一度確かめる。** ジャンプして浮いている間（3-8）にも
他のボットは埋めてくる。そのまま置くと**その上に積んでしまい、地面が高くなる**。

とくに脱出（3-9-2 の 2）や退避で積む経路は、
`tickInner` 冒頭の確認を通らずに設置まで進むので、設置側でも見る必要がある。

### 3-A-3. 埋めたい場所に他のボットが立っている

**届くならぶん殴ってどかす**（2026-08-22 変更）。

ノックバックは無敵時間に縛られないので（3-A-8）、実際にその場から飛ぶ。
**殴ることがそのまま退去手段になる。**

- 対象は**ボットだけ**。人は殴らない
  （`botStandingAt` は登録済みボットしか見ない）
- 殴ったら**次のマスへ行かず、このマスに留まって空くのを待つ**。
  飛んだ直後に空くので、待つ価値がある
- 空かないまま粘っても、諦める期限（3-9-1）で切れるので張り付かない

**ブロックに埋まっている個体は、掘ってでも掘り出してから殴る。**
埋まったままだと吹き飛ばしても動けず、その列が永久に空かない。
**整地対象のマスであっても掘る**（掘るのは相手の体が占める2マスだけ）。

このときだけ「他のボットの足場を崩さない」判定を外す。
掘り出すのが目的なので、足場を守っては意味がない。

**届かないなら口で言う。**「どいて」と伝えたうえで、自分は次のマスへ行く。

- 待って見張るより、その間に別のマスを埋めた方が早い
- **どくために足元にブロックを積んでもよい。**
  四方を囲まれていると歩いて逃げられない。1マス上がれば、
  相手が埋めたいマスからは抜けられる。
  `EVACUATE_PILLAR_AFTER` 歩いても駄目なら積む。**積むのは1段だけ**（塔になるため）
- 相手を直接動かさず**指示を置くだけ**にする。
  相手は自分のループの中で気づいて退避する
  （他のボットを横から操作すると状態が壊れやすい）

**この仕組みは、雑に作ると自分の首を絞める。** 落とし穴が2つある。

1. **退避中は、本人が自分の移動指示を出してはいけない。**
   出した瞬間に、どく動きが打ち消されて一歩も動けない。
   `EVACUATE_TICKS` の間は通常の作業を止める。
2. **頼んだマスは一定時間「保留」にする。**
   優先順位は低い順なので、飛ばしても**次の走査でまた同じマスが最優先**で選ばれる。
   頼んでは飛ばすを繰り返して、頼んだ側も一歩も進まなくなる。
   `DEFER_TICKS` の間だけ候補から外す。

**行き先は依頼側が決めて持たせる。** 相手が毎 tick 行き先を計算し直すと、
そのたび経路が引き直されてその場で揺れるだけになる。
相手はそのマスの上に立っているので「相手から離れる向き」が作れない。
マスの座標から決まった向きを作る（毎回同じ向きになるので指示が揺れない）。

### 3-A-4. 遠くを線で探す（2026-08-22 追加）

四角く走査すると半径 r で (2r+1)^2 列になり、遠くは現実的でない
（半径128 なら 66049 列）。

**ランダムな角度へ線を数本飛ばして拾い読みする。**
`RAY_COUNT`（8）本 × `RAY_LENGTH`（256）= 2048 サンプルで同じ距離に届く。
隙間だらけの探し方だが、**角度が毎回ランダムなので、
何度も試すうちに周囲がまんべんなく当たる**。

> シミュレーション距離（既定4チャンク = 64ブロック）の外は
> チャンクが読み込まれていないので何も見えない。
> ただし**チャンクは各プレイヤーの周りに読み込まれ、
> SimulatedPlayer もプレイヤーとして数えられる**ので、
> 他のボットがいる方向へ伸ばした線は当たる。
> 外れた分は `isChunkLoaded` で弾かれるだけなので、長くしても損はしない。

線で読んだ結果も共有キャッシュに入るので、
**他のボットもその場所を見つけられるようになる**（3-A-6）。

### 3-A-5. やることが無いとき

**止まる前にやることがある。** 順に試す。

| 順 | すること | 届く距離 | 費用 |
| --- | --- | --- | --- |
| 1 | 半径 `AUTO_RADIUS`(8) を四角く走査 | 8 | 289 列 |
| 2 | **線を飛ばして遠くを探す**（3-A-4） | 256 | 2048 サンプル |
| 3 | 他のボットが見つけた場所をもらう | 制限なし | 世界を読まないのでほぼ無料 |
| 4 | それでも無ければ待つ（殴りに行く） | — | — |

**半径を広げる仕組みは廃止した**（2026-08-22）。
四角い走査は (2r+1)^2 列と高くつく割に距離が伸びない。
半径16まで広げても 1089 列で 16 ブロックしか届かないのに対し、
**線なら 2048 サンプルで 256 ブロック先まで届く**。
近場の 8 を見たら、あとは線に任せる方が良い。

**共有は自分で集めた結果より必ず後**（確定 / 2026-08-22）。
自分で1つでも見つかったら、そこで確定して共有は見ない。
共有だけが残ったときの最後の手段として使う。

> 走査そのものは共有キャッシュ（3-A-6）経由で読むので、
> **近場走査でも他のボットが読んだ結果は使う。**
> これは「読む手間を省く」だけで、行き先の優先順位には影響しない。

**遠くの場所を取ったときは、諦めるまでの時間を延ばす**（3-9-1）。
固定のままだと着く前に必ず諦める。

四角い走査は `AUTO_RADIUS`（8）固定。広げない。

> 半径 r で (2r+1)^2 列かかる — 8 で 289、16 で 1089、64 では 16641。
> **費用の伸びに対して距離が伸びなさすぎる。**
> 遠くは線に任せる（3-A-4）。

全部空振りなら、本当にやることが無い。
そのときは**止まっていてよい**。空振りが続くほど走査の間隔を延ばす。

### 3-A-6. 走査結果と「仕事の在りか」を全ボットで共有する

**各ボットが自分で `getTopmostBlock` を呼ぶと、同じ列を何度も読むことになる。**
走査範囲は重なっているので、100体いれば同じ列を 100 回読む。
半径8なら 289 列 × 100体 = 約 3 万回/走査。線の走査も同じだけ重なる。

読んだ結果を `terrain.ts` に置いて使い回す
（列 → **次に埋めるべき高さ**。全部埋まっていれば null）。

**「まだ埋まっていない列」だけを別に持つ**のがもう一つの役目。
これが**仕事の在りかの共有メモリ**で、
自分の周りに何も無いボットはここから場所をもらう（3-A-5 の 2）。
`cache` を全部なめると 2 万件になるので、必要なものだけ分けて持つ。

鮮度の保ち方:

| きっかけ | すること |
| --- | --- |
| 埋めた／掘った | 記録を**捨てる**（新しい高さが分からないため） |
| それ以外 | `TERRAIN_TTL` で期限切れ（人が地形を変えた場合の保険） |

**多少古くても致命的にはならない。**
実際に埋める直前に `getBlock().isAir` で必ず確かめているので、
古い情報で選んでしまっても「飛ばして次へ」で済む（3-A-2）。

記録は `TERRAIN_CACHE_LIMIT` を超えたら期限切れを掃除し、
それでも減らなければ全部捨てて作り直す。

#### 分け前は**ランダムに抜き取る**（2026-08-22 修正）

**先頭から順に取ってはいけない。**
`Map` は挿入順に回るので、毎回同じ古い列ばかり返すことになる。
それが予約済みや保留中だと、**他に何千件あっても毎回空振りする**。
実際これで共有探索がまったく機能していなかった。

全体から等確率で抜き取る（reservoir sampling）。
件数が多いときは `SHARED_SCAN_LIMIT` で途中打ち切りにするが、
抜き取りがランダムなので偏らない。

#### 生きているか確認する

`/level:status` で「共有した列」「うち未整地」を見られる。
未整地の件数が 0 のまま増えないなら、共有が働いていない。

### 3-A-7. 手が止まるもう一つの経路

**「対象は見つかるが、そのマスを埋められない」場合、暇にならないので
3-A-5 の手当てが発動しない。**
優先順位は低い順なので、次の走査でも同じマスが最優先で返ってきて、
埋められないマスを延々と狙い続ける。

そこで**埋められなかったマスは `DEFER_TICKS` の間だけ候補から外す**。
対象は次の3つ。

- 設置したが反映されていなかった（`getBlock().isAir` のまま）
- 足場が見つからなかった
- `useItemOnBlock` が例外を投げた

同じ理由で、「どいて」と頼んだマスも外す（3-A-3）。

### 3-A-8. 暇なボットは殴り合う（2026-08-22 追加）

**探索を全部やり切って何も見つからなかったボットは、
他のボットをとてつもない速度で殴る。**

整地の役には立たない。**止まっているより面白いから**入れている。

- 相手は**自分より低い位置にいるボットを優先**（2026-08-22 変更）。
  わざわざそこまで移動して殴りに行く。

  > **これは救助になっている。**
  > 下にいるボットは穴から出られなくなっている可能性が高い。
  > ノックバックは無敵時間に縛られないので（下記）、
  > 殴れば上に押し出せる。暇つぶしがそのまま役に立つ。

  下にいるボットが複数いればランダムに選ぶ（全員で1体に群がらないため）
- **誰も下にいなければ、横にいる（＝同じか上の）誰かを殴る。**
  ここもランダムに選ぶ。
  近い相手にすると、たまたま隣にいる2体だけで殴り合って絵が固まる
- **待機中も止まらない。** 相手のところまで移動し続ける
- ただし**毎 tick 選び直さない**（`BRAWL_RETARGET_TICKS`）。
  毎 tick 変えると、どこにも着かないまま向きだけ変わり続ける
- 届かなければ近づく（`navigateToEntity`。座標を渡さないので相対座標の問題が無い）
- 届いたら**毎 tick 殴る**（`BRAWL_INTERVAL`）。
  `runInterval` は 1 tick が下限なので、
  それ以上速くするには**同じ tick の中で繰り返す**（`BRAWL_SWINGS_PER_TICK`）
- 向くのは `LookDuration.Instant`。
  既定だと向き終わるまでの数 tick を無駄にする
- 届いていない間は殴れないので、**追いかけるのも全力で**（`BRAWL_CHASE_SPEED`）
- **仕事が見つかったら即やめる**

やることが無いボットは `IDLE_RESCAN_TICKS`（100 tick）ごとに探し直し、
**その 100 tick の間はずっと殴っている**。

#### 殴る速さについて（調査結果 / 2026-08-22）

**Bedrock のプレイヤーには攻撃クールダウンが存在しない。**
Java の攻撃力チャージに当たるものは無く、`player.json` にも該当する
component は無い（`minecraft:attack` は damage だけ）。
よって**もともと毎 tick 殴れる**。0 tick 化のような設定は要らない。

`minecraft:attack_cooldown` という component はあるが、これは別物。
公式ドキュメントいわく
*"prevent the entity from attempting to acquire new attack targets"* で、
**次の標的を探すまでの間隔**。バニラでも axolotl / breeze / goat /
hoglin / piglin / warden にしか付いていない。

#### 無敵時間（殴られた側）について（調査結果 / 2026-08-22）

実際に殴る速さを縛っているのは**殴られた側の無敵時間**（BE では約10 tick）。

**無敵時間そのものを設定する手段は無い。**

- エンティティ component に該当するものが無い
  （`ComponentList.md` 全件を見て、cooldown を含むのは `attack_cooldown` のみ）
- Script API にも無い
- Molang の `query.hurt_time` は**読むだけ**

**Java の No I-Frames 系 MOD はすべて Java 版**で、BE には移植できない。
外部も当たったが、BE 向けの「無敵時間を消す」手段は見つからなかった。

**そこで迂回する。** 3通り確認した。

| 手 | 内容 | 確度 |
| --- | --- | --- |
| `EntityHealthComponent.setCurrentValue()` | 体力を直接書く。ダメージ処理を通さないので無敵時間に一切かからない | **確実**（型定義で確認） |
| `Entity.applyKnockback()` | **ダメージ処理を通らないので無敵時間に縛られない。毎 tick 効く。** 殴り合いはこれを使う | **確実**（実装済み） |
| `minecraft:damage_sensor` の `deals_damage: "no_but_entity_effects_apply"` | 公式ドキュメントいわく「ダメージは入らないがノックバックとエンチャントは適用され、**赤く光らない**」。赤く光らない＝負傷状態に入らない＝無敵時間が始まらない。`on_damage` で自前のダメージを与えれば毎回入る。バニラでは `sulfur_cube.json` が使用 | 未検証 |

プレイヤーに適用したい場合、**`player.json` はビヘイビアーパックで上書きできる**
（bedrock-wiki の `disabling-team-damage.md` が実際にやっている）。

#### 疑似的に「無敵時間ゼロ」に見せる

**無敵時間は消せない。消すのではなく、当たって見えるものを毎 tick 出す。**

「殴られた」と分かる要素は4つあり、**赤く光る演出だけが damage 処理の中**にある。

| 要素 | damage 処理を通るか | 毎 tick 出せるか |
| --- | --- | --- |
| 赤く光る | **通る** | **不可**（約10 tick に1回） |
| ノックバック | 通らない（`applyKnockback`） | 可 |
| 効果音 | 通らない（`dimension.playSound`） | 可 |
| パーティクル | 通らない（`dimension.spawnParticle`） | 可 |

つまり**赤く光る以外は全部毎 tick 出せる**ので、それで連打に見せる。

使う ID（`reference/bedrock-samples` で確認したもの）:

- 当たり音: `game.player.attack.strong`
- 悲鳴: `game.player.hurt`
  （`resource_pack/sounds.json`）
- パーティクル: `minecraft:critical_hit_emitter`
  （`resource_pack/particles/critical_hit.json` の identifier）

**音は1回の `punch` につき1回だけ鳴らす。**
殴る回数（`BRAWL_SWINGS_PER_TICK`）ぶん鳴らすと、ただの雑音になる。
毎 tick × ボットの数だけ鳴るので、音量も控えめにする。

#### 人間のプレイヤーにも同じ手当てをする

**振る速さそのものは変えられない。** 攻撃入力はクライアント側なので、
アドオンから「もっと速く振れ」とは言えない。
そもそも BE に攻撃クールダウンは無いので、連打すればその回数だけ振れている。

遅く見える原因はやはり**殴られた側の無敵時間**なので、
ボットと同じく**ノックバック・音・パーティクルを当たるたびに出す**。

拾い方は `world.afterEvents.entityHitEntity`。
公式の説明は "fires when an entity hits (that is, melee attacks) another entity" で、
**ダメージが入ったかどうかではなく「殴った」イベント**。

**SimulatedPlayer もプレイヤーとして数えられる**ので、
登録済みのボット名を除いてから処理する（ボットは自前で演出済み。二重にかけない）。

吹き飛ばしはボット同士より控えめにする（`PLAYER_PUNCH_KNOCKBACK`）。
強すぎると普通に遊べなくなる。

ボットは体力を戻し続けている（3-7）ので死なない。

#### 100体でも重くしないために

**相手を選び直すのは時々でよい**（`BRAWL_RETARGET_TICKS`）。
毎 tick 全員の距離を測ると 100体で 1万回/tick になる。

### 3-A-10. 通知

**進捗をチャットに出さない。** 状況は `/level:status` で見る。

## 3-B. 反応の速さ

「探索してから動き出すのが遅い」を避けるため:

| 箇所 | 値 | 理由 |
| --- | --- | --- |
| `WORK_INTERVAL` | 2 tick | 作業ループの間隔 |
| `SCAN_CHUNK` | 400 | `AUTO_RADIUS=8` の 289 列を **1 tick で走査しきる**。小さいと走査が何 tick にも分かれて動き出しが遅れる |
| `NEXT_TARGET_DELAY` | 1 tick | 0 にはしない。設置の反映前に走査すると同じ場所を狙う |
| `RETRY_DELAY` | 2 tick | 予約がぶつかったときの探し直し |
| `EVACUATE_TICKS` | 30 tick | どき続ける時間。この間は自分の移動指示を出さない |
| `EVACUATE_DISTANCE` | 4 | どく距離 |
| `DEFER_TICKS` | 60 tick | 「どいて」と頼んだ／埋められなかったマスを候補から外しておく時間 |
| `TERRAIN_TTL` | 300 tick | 共有した走査結果を信じる時間 |
| `TERRAIN_CACHE_LIMIT` | 20000 | 共有する列の記録の上限 |
| `PLACE_TIMEOUT_TICKS` | 200 tick | 1マスに掛けてよい時間。10 秒 |
| `CANDIDATE_LIMIT` | 32 | 抽選のために溜める候補の数 |
| `EVACUATE_PILLAR_AFTER` | 20 tick | どくのに歩くのを諦めて積み始めるまで |
| `STALL_LIMIT` | 300 tick | 何も進まないまま放置してよい時間。超えたら蹴り起こす |
| `SUPERVISOR_INTERVAL` | 40 tick | 止まっているボットを見張る間隔 |
| `RAY_COUNT` | 8 | 遠くを探すときに飛ばす線の本数 |
| `RAY_LENGTH` | 256 | 線を伸ばす距離 |
| `SHARED_JOB_LIMIT` | 64 | 他のボットが見つけた場所を一度に見る件数 |
| `SHARED_SCAN_LIMIT` | 2000 | 共有記録から抜き取るときに走査する上限 |
| `IDLE_RESCAN_TICKS` | 100 tick | やることが無いときに探し直す間隔。延ばさない |
| `TRAVEL_TICKS_PER_BLOCK` | 10 | 移動に見込む時間。制限時間に足す |
| `SEARCH_WATCHDOG_TICKS` | 200 tick | 探索が返ってこないまま放置してよい時間 |
| `BRAWL_INTERVAL` | 1 tick | 暇なときに殴る間隔。BE に攻撃CTは無いので毎 tick 殴れる |
| `BRAWL_REACH` | 3 | 殴れる距離 |
| `BRAWL_RETARGET_TICKS` | 40 tick | 殴る相手を選び直す間隔 |
| `BRAWL_SWINGS_PER_TICK` | 20 | 1 tick に殴る回数。1 tick より速くする唯一の手 |
| `BRAWL_CHASE_SPEED` | 3 | 殴りに行くときの移動速度 |
| `BRAWL_KNOCKBACK` | 2.5 | 吹き飛ばしの強さ。無敵時間に縛られない |
| `BRAWL_KNOCKBACK_UP` | 0.7 | 吹き飛ばしの上向き成分 |
| `BRAWL_HIT_SOUND` | `game.player.attack.strong` | 当たり音。毎 tick 鳴らせる |
| `BRAWL_HURT_SOUND` | `game.player.hurt` | 悲鳴 |
| `BRAWL_HIT_PARTICLE` | `minecraft:critical_hit_emitter` | 当たったときのパーティクル |
| `BRAWL_SOUND_VOLUME` | 0.35 | 音量。数が多いので控えめに |
| `PLAYER_PUNCH_KNOCKBACK` | 1.2 | 人間が殴ったときの吹き飛ばし |
| `PLAYER_PUNCH_KNOCKBACK_UP` | 0.35 | その上向き成分 |

### 3-B-1. 移動指示は1マスずつ

**遠くの目標を一度に指示しない。また、毎 tick 出し直さない。**
出し直すたびに経路が引き直され、歩き出せずにその場で揺れる。

**隣の1マスを目標にする。** 隣なら経路はほぼ必ず見つかり、
着けば目標が変わって自然に次の1マスへ進む。
出し直すのは「目標のマスが変わった」「詰まった」ときだけ。

## 4. コマンド

| コマンド | 動作 |
| --- | --- |
| `/gametest run level:start` | ボットを生成して常駐させる |
| `/level:scan <半径>` | 走査して、埋める対象の数を報告する（埋めない） |
| `/level:go <半径>` | 走査して整地を開始する |
| `/level:stop` | 中止する |
| `/level:dismiss` | ボットを退場させる |
