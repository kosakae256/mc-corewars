# 調査: 作業ワーカーを作れるか（木こり・農夫などの自動作業体）

調査日: 2026-08-22 / `@minecraft/server` 2.9.0 の型定義で確認

## 0. 結論

**作れる。** ただし「ワーカー」の作り方は**3通り**あり、性質がまるで違う。
木こりワーカーはどれでも実現できるが、選ぶ基準は
「**本物のプレイヤーらしさが要るか**」と「**常設したいか**」の2点。

| | A. SimulatedPlayer | B. カスタムエンティティ | C. エンティティ無し |
| --- | --- | --- | --- |
| 見た目 | プレイヤー | 好きなモデル | 無し（ブロックが勝手に消える） |
| 移動 | **経路探索あり** | JSON behavior 頼み | 無し |
| ブロック破壊 | 本物と同じ | スクリプトで置き換え | スクリプトで置き換え |
| 道具・耐久・エンチャント | **効く** | 効かない | 効かない |
| ワールド再読込後 | **消える** | 残る | 残る（常駐スクリプト） |
| プレイヤーとして数えられる | **される** | されない | されない |
| 必要なもの | beta + GameTest | 通常のアドオンのみ | 通常のアドオンのみ |

整地くんは A。**サバイバルの常設ワーカーとしては B が本命**。

## 1. 方式A: SimulatedPlayer

整地くんで使っている方式。木こりに必要なものは全部揃っている。

`@minecraft/server-gametest` の `SimulatedPlayer` で確認できたもの:

```
breakBlock(blockLocation, direction?): boolean
navigateToBlock(blockLocation, speed?): NavigationResult
useItemOnBlock(...)          苗木を植える
giveItem(itemStack, selectSlot?)  斧を持たせる
attack() / attackEntity(entity)
```

**`breakBlock` は本物の破壊。** 斧を持たせれば速くなり、耐久も減り、
ドロップも通常どおり出る。シルクタッチや効率強化も効く。
「サバイバルで便利なワーカー」という趣旨には一番近い。

### 1-1. ただしサバイバルの常設には向かない

制約は [05-simulated-player.md](05-simulated-player.md) に詳しいが、
**常設ワーカーとして見たときに効いてくるのは次の3つ**。

1. **ワールドを読み込み直すと消える。**
   GameTest が終わると一緒に消えるので、入り直すたびに再召喚が要る。
2. **プレイヤーとして数えられる。**
   湧き上限・睡眠（全員寝ないと朝にならない）・
   周囲のチャンクを読み込み続ける、といった影響が出る。
   100体置くと、その全部が効いてくる。
3. **beta モジュール + 実験機能が要る。**

> 2 は木こりワーカーだと**むしろ有利に働く場合がある**。
> ワーカーの周りのチャンクが読み込まれ続けるので、
> プレイヤーが離れていても作業が進む。
> 逆に言えば、それだけ常時負荷がかかる。

## 2. 方式B: カスタムエンティティ + Script API

ビヘイビアーパックで独自エンティティを定義し、Script API から操作する。
**通常のアドオンの範囲**で作れる（beta も GameTest も不要）。ワールドにも残る。

### 2-1. 落とし穴: エンティティには移動命令が無い

**`Entity` クラスに `navigateTo` / `moveTo` に相当するメソッドは無い**（2.9.0 で確認）。
`EntityNavigationComponent` は取得できるが、
`avoidWater` / `canJump` などが並ぶだけで**全て readonly、メソッドは1つも無い**。

つまり **`SimulatedPlayer` のような「そこへ歩け」は、普通のエンティティには言えない。**
`Entity` にあるのは以下のような、位置を直接いじる手段だけ。

```
applyImpulse(vector)     速度を足す（経路探索は無い）
teleport(location)       瞬間移動
lookAt(targetLocation)
triggerEvent(eventName)  JSON 側のイベントを起こす
runCommand(commandString)
```

### 2-2. ではどう歩かせるか

**移動は JSON の behavior に任せ、スクリプトは「目的地」だけを与える。**
バニラにある使えそうな behavior（`reference/bedrock-samples` で確認）:

```
minecraft:behavior.move_to_block          特定のブロックへ寄っていく
minecraft:behavior.follow_mob             特定のエンティティについていく
minecraft:behavior.follow_owner
minecraft:behavior.move_to_random_block
```

定番のやり方は **「見えないマーカーエンティティを置き、それを追わせる」**。

1. スクリプトで目的地を決める
2. そこへ**マーカーを teleport する**
3. ワーカーは `follow_mob` でマーカーを追う（経路探索はゲーム側がやる）
4. 着いたらスクリプトが作業させる

`triggerEvent()` で「作業モード」「移動モード」を切り替えれば、
behavior の優先度を JSON 側で入れ替えられる。

> **未検証。** マーカー追従方式は BE のコミュニティで広く使われている手法だが、
> 実際に組んで確かめてはいない。作るときはここを最初に検証する。

### 2-3. ブロックを壊す

エンティティは「ブロックを殴る」ことができない。スクリプトで置き換える。

```ts
// ドロップも出したい場合
const stack = block.getItemStack();        // Block.getItemStack() で確認済み
dimension.setBlockType(loc, "minecraft:air");
if (stack) dimension.spawnItem(stack, loc);
```

コマンド経由でも同じことができる（こちらはドロップの計算をゲームに任せられる）。

```ts
entity.runCommand(`setblock ${x} ${y} ${z} air destroy`);
```

**どちらも道具・耐久・エンチャントは関係しない。**
斧を持たせても速くならないし、シルクタッチも効かない。
「速さ」はスクリプト側の待ち時間で表現することになる。

## 3. 方式C: エンティティを出さない

そもそも姿を出さず、常駐スクリプトが範囲内の木を勝手に処理する。
一番軽く、一番壊れにくい。ただし**見ていて面白くない**。

「便利さ」だけが目的ならこれが最適。
「ワーカーが働いている絵」が欲しいなら A か B。

## 4. 木こりワーカー特有の論点

方式によらず、木を切るには次を決める必要がある。

### 4-1. 「1本の木」をどう認識するか

原木ブロックを1つ見つけたら、**そこから連結した原木を全部たどる**
（flood fill）。上方向と斜めも見ないと、シラカバ以外（ジャングル・ダークオーク）で
半分だけ残る。

たどる範囲に上限を設けないと、大木で走査が止まらなくなる。
整地くんと同じく `system.runJob` で分割する必要がある。

### 4-2. 葉をどうするか

放置すると宙に浮いた葉が残る。時間で自然に消えるが見た目が悪い。
消すなら、原木を全部消したあとに周囲の葉を判定する。

### 4-3. 苗木を植え直すか

植え直さないと1回で終わる。植えるなら:

- 方式A: `useItemOnBlock` で本物と同じように植える
- 方式B/C: `setBlockType(loc, "minecraft:oak_sapling")`

**土/草の上でないと苗木は残らない。** 置く前に下のブロックを確かめる。

### 4-4. ドロップの回収

原木は落ちたままだと消える。

- 方式A: プレイヤーなので**歩けば勝手に拾う**
- 方式B: 拾わせるには JSON に `minecraft:behavior.pickup_items` が要る
- 方式C: `dimension.getEntities({ type: "minecraft:item" })` で拾って処理する

### 4-5. チャンクが読み込まれていないと何もできない

整地くんで踏んだのと同じ問題。
`dimension.isChunkLoaded()` を必ず確かめる。

方式A はワーカー自身がプレイヤーなのでチャンクを読み込むが、
方式B/C は**プレイヤーが近くにいないと止まる**（ticking area を張れば別）。

## 5. 整地くんから流用できるもの

木こりを作るなら、整地くんの以下はほぼそのまま使える。
[03-terrain-leveling.md](../spec/03-terrain-leveling.md) の 3-A に、
複数体で動かすときの落とし穴をまとめてある。

- 走査を `system.runJob` で分割する
- 担当の予約（複数体が同じ木に殺到しない）
- 走査結果の共有キャッシュ
- 手詰まりのときに範囲を広げる / 失敗したマスを一時保留にする

**共通化はしない。** アドオンは1つずつ独立させる方針なので、
必要なら**考え方を写す**（コードは各アドオンが自前で持つ）。
