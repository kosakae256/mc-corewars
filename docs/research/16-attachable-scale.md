# 調査: 持ち物の模型が、画面の端で巨大化する

**2026-09-07 に当たった。** Minecraft 1.26.44、リソースパックの持ち姿（attachable）。

## 何が起きたか

> **弓を持っている人を、画面の端に捉えたときだけ、弓が 4 倍になる。**
> 正面で見ている間は正しい大きさ。

## 1. 原因——**縮小をアニメーションに頼っていた**

### 1-1. `texture_meshes` は「絵 1 ピクセル ＝ 模型 1 単位」

**絵から立体を起こす仕組み**（`texture_meshes`）は、**絵の解像度がそのまま模型の大きさ**になる。

| 絵 | 起きる模型 |
| --- | --- |
| 16 × 16 | **1 × 1 ブロック**（正しい） |
| 32 × 32 | 2 × 2 ブロック |
| **64 × 64** | **4 × 4 ブロック**（**4 倍**） |

**細かく描きたくて 64×64 にすると、模型も 4 倍で生まれる。**

### 1-2. だから持ち姿で縮めていた

```jsonc
// animations/…animation.json
"animation.pve3_bow.wield": {
  "loop": true,
  "bones": { "rightitem": { "scale": 0.25, … } }   // ← ここで 1/4 に
}
```

### 1-3. **アニメーションは、画面の外だと止まる**

> ### これが本体
>
> **Bedrock は、視界の外にある実体のアニメーションを更新しない。**
> **止まった瞬間、`scale` は既定の 1.0 に戻る。**
> **＝ 縮小が外れて、素の 4 倍が出る。**

**「画面の端に来たときだけ」**という出方は、**視界の判定の境目**にいるため。

## 2. 直し方

### 2-1. 応急——**画面の外でも骨を動かし続ける**

```jsonc
// attachables/….json の description
"scripts": {
  "should_update_bones_and_effects_offscreen": true,
  "should_update_effects_offscreen": true,
  "animate": [ … ]
}
```

**アニメーションが止まらなくなるので、`scale` も外れない。**

### 2-2. 本筋——**縮小をアニメーションに置かない**

> ### **大きさは、模型の側で決まっているべき**
>
> **アニメーションは「動き」を書く所。** 大きさを預けると、
> **止まった瞬間に化ける。**

| やり方 | 引き換え |
| --- | --- |
| **絵を 16×16 で描く** | **確実。** 描き込みの細かさは落ちる |
| **立方体で模型を書く**（`texture_meshes` を使わない） | 大きさを自分で決められる。**手間が増える** |

## 3. **これから作る持ち物すべてに効く**

**弓だけの話ではない。** **`texture_meshes` で持ち物を作るときは、必ず次を確かめる。**

| 確かめること | |
| --- | --- |
| **絵の解像度** | **16×16 なら縮小は要らない。** それ以外なら**必ず縮小が要る** |
| **縮小をどこに書いたか** | **アニメーションに書いたなら、`should_update_bones_and_effects_offscreen` を必ず付ける** |
| **横目で見て確かめる** | **正面だけ見て「直った」と言わない。** 画面の端に入れて確かめる |

**同じ穴に落ちるのは、模型を絵から起こすもの全部**——**持ち物・飾り・看板の類。**
