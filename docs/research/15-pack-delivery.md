# 調査: パックが参加者に配られる条件

**2026-09-05。** 「manifest の版は上げたのに、他の人に反映されない」を追った記録。

## 1. 結論

> ### **開発用パックは、参加してきた人に配られない。**
>
> `development_behavior_packs/` `development_resource_packs/` に置いたものは、
> **その端末でしか読まれない。**

だから、こういう食い違いが起きる。

| | 他の人に届くか | なぜ |
| --- | --- | --- |
| **ビヘイビア**（スクリプト・AI・実体の定義） | **届く** | **ホストが動かしている。** 結果だけが全員に見える |
| **リソパ**（モデル・テクスチャ・アニメ・音） | **届かない** | **各自の端末が描く**もの。パックが無ければ描けない |

**「AI は効いているのに、モデルが古い／出ない」はこれ。**
**manifest の版は関係ない**——そもそも配られていない。

## 2. なぜそうなっていたか

**`npm run local-deploy` は Microsoft の公式ひな形（`ts-starter`）の既定の口**で、
**`development_*_packs` へ置く。** 手元で試すには速い（再梱包が要らない）が、
**配布のことは考えられていない。**

**pve-v2 から移植したときに、そのまま引き継いだ。**

## 3. 直し方

| | やり方 | 引き換え |
| --- | --- | --- |
| **A. 配る** | `npm run mcaddon` で `.mcaddon` を作り、各自に入れてもらう | **更新のたびに配り直し** |
| **B. 正式なパックとして当てる** | `resource_packs/` `behavior_packs/` に置き、ワールドに当てる | **入り直しのたびに再ダウンロード** |
| **C. BDS で配る** | サーバーの `resource_packs/` ＋ `world_resource_packs.json` ＋ `texturepack-required=true` | サーバー運用にするなら |

**B を選んだ**（2026-09-05）。**普段から正式版で置く。**

```bash
cd worlds/pve-v3/packs/pve_v3
npm run deploy        # 組み立てて、正式なパックとして当てる
```

道具は [tools/mc-install.mjs](../../tools/mc-install.mjs)。やっていること:

1. `behavior_packs/<名>` ＋ `dist/scripts` → `com.mojang/behavior_packs/<名>`
2. `resource_packs/<名>` → `com.mojang/resource_packs/<名>`
3. ワールドの `world_*_packs.json` に **uuid と版を書く**（同じ uuid の行は入れ替え、**他人の行は残す**）

## 4. 覚えておくこと

| | |
| --- | --- |
| **同じ uuid を 2 か所に置かない** | 開発用と正式版の両方にあると、どちらが読まれるか分からない。**正式版にしたら開発用は消す** |
| **ゲームを閉じてから置く** | 開いていると、ワールドの json を上書きし返される |
| **ここで初めて版が効く** | 正式なパックは **uuid ＋ 版**で保管される。**版を上げないと、参加者は古いものを使い続ける**（`docs/imp.md` 10-10） |
| **ワールドに残る行は消さない** | `world_*_packs.json` には他のパックの行もある。**触らない**（消すとその世界が壊れる） |
| **開発用パックはワールドの json に出ない** | 選択は `level.dat` 側に入る。**`world_*_packs.json` を見ても分からない** |

## 5. 手元で試すだけなら

**`npm run local-deploy`（開発用）のほうが速い**——再ダウンロードが要らない。
**人を呼ぶ前に `npm run deploy` へ切り替える**、という使い分けもできる。
**ただし両方に置いたままにしない**（4 章）。

## 6. リソパが「依存」を持つと、参加者に出ない

**2026-09-05。正式なパックとして当てたのに、まだ他の人に出なかった。** 原因はこれ。

```json
リソパの manifest.json
"dependencies": [{ "uuid": "…（ビヘイビアパックの uuid）" }]
```

> ### **リソパから、ビヘイビアパックを要求してはいけない。**
>
> **依存は「そのパックが無ければ、自分も読み込まない」という意味。**
> **ビヘイビアパックは参加者の端末に配られない**（1 章）。
> だから**参加者側では依存が満たせず、リソパごと弾かれる。**

**ホストは両方持っているので出る。** 「自分では見えるのに、他の人には出ない」の正体。

### 向きが逆だった

| | 正しい向き |
| --- | --- |
| **ビヘイビア → リソパ** | **よい。** 「このゲームには、この見た目が要る」。BP はホストにしか要らないので、要求も満たせる |
| **リソパ → ビヘイビア** | **駄目。** 参加者は BP を持っていない |
| どちらも無し | 動く。ただし `.mcaddon` で配ったとき、片方だけ入れられる |

**この向きは `addons/_template/` から来ていた。** ひな形を直したので、
**`node tools/new-addon.mjs` で作る新しいものは正しい向きになる。**

**まだ逆のまま残っているもの**（**マルチで遊ぶなら直すこと**）:

| | |
| --- | --- |
| `worlds/pve-v2/packs/pve_v2` | リソパ → BP |
| `worlds/core-wars/packs/game` | リソパ → BP |
| `worlds/core-wars/packs/kit` | リソパ → BP |

## 7. **`min_engine_version` は、参加者の版で決める**（2026-09-05）

「**リソースパックの読み込みに失敗しました**」で**一部の人だけ弾かれた。**
1 人だけ入れた——**その人の Minecraft が新しかった**から。

> ### リソパの `min_engine_version` は、**参加者の端末**が満たす必要がある
>
> **ビヘイビアはホストが動かす**ので、ホストの版だけ見ればよい。
> **リソパは各自の端末が読む。** ここを高く書くと、**古い版の人が丸ごと弾かれる。**

| | 何に合わせるか |
| --- | --- |
| **ビヘイビア** | **ホストの版。** Script API の版に合わせて高くてよい（いまは 1.26.40） |
| **リソパ** | **いちばん古い参加者の版。** **中身が要求する最低限まで下げる**（いまは 1.21.80） |

**pve_v3 のリソパは 1.26.40 を要る中身を持っていない**——
面ごとの UV（1.16〜）、実体の値の `q.property`（1.21〜）、`anim_time_update`、チェスト UI。
**1.26.40 → 1.21.80 に下げた。**

> ### ひな形も直す
>
> `node tools/new-addon.mjs` が作る**リソパの `min_engine_version` は低めにする。**
> **上げるのは、上げないと動かないものを入れたときだけ。**
