# 構想: ローカル LLM をマイクラのチャットに解き放つ

> 作成日: 2026-08-22
> 状態: **構想。実装前。** 仕様が固まったら `docs/spec/` に落とす

## 1. やりたいこと

**ローカルで動く LLM（Qwen3.8）を、Minecraft のチャットに参加させる。**

プレイヤーがチャットで話しかけると LLM が応答する。
ワールド名を `LLM実験場` としているとおり、まずは実験場としての位置づけ。

## 2. なぜ BDS が要るのか

Script API 単体では**外部と通信できない**。
ローカルの LLM（Ollama）を叩くには HTTP が必要で、それができるのは
**`@minecraft/server-net` だけ**。そしてこのモジュールは **BDS 限定**。

そのため構成は必然的にこうなる。

```
  プレイヤー
     │ チャット
     ▼
  BDS (bedrock_server.exe)
     │  behavior pack / Script API v2
     │  world.beforeEvents.chatSend でチャットを拾う
     ▼
  @minecraft/server-net で HTTP POST
     │
     ▼
  Ollama (localhost:11434)
     │  qwen3.8 (27B)
     ▼
  応答テキスト → world.sendMessage でチャットに返す
```

すでに整っているもの:

- BDS 1.26.44.3（`C:\MinecraftServer\1.26.44.3`、`flatworld` で稼働確認済み）
- Ollama 0.32.14（インストール済み）
- アドオンのビルド・配置経路（`tools/mc.mjs deploy`）

## 3. モデルの選定

### 3-1. Qwen3.8 は 27B のみ

2026-08 時点の Qwen3.8 は **27B dense（64層・262K context・Apache 2.0）** のみ。
8B などの小型版は出ていない。

> 参考: Qwen3 世代には 0.6B / 1.7B / 4B / 8B / 14B / 32B があったが、
> 3.5 以降は世代ごとにサイズ構成が変わっている。

### 3-2. このマシンでの現実（重要）

| | 実測値 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 5070 |
| **VRAM** | **12 GB**（12227 MiB） |
| システム RAM | 31.1 GB |
| CPU | AMD Ryzen 7 7700（8C/16T） |

Qwen3.8-27B の必要メモリ:

| 量子化 | 必要メモリ | 12GB VRAM |
| --- | --- | --- |
| BF16 | ~56 GB | ✗ |
| FP8 | ~28 GB | ✗ |
| **Q4_K_M** | **~16.4 GB**（8k context 込みで ~19 GB） | ✗ |
| Q3_K_M | ~13 GB | ✗ |

> **「27B が 8GB メモリで動く」という情報は誤り。** 裏付けが取れなかった。
> 4bit でも 14〜16 GB は要る。一般には 24GB カードが快適ラインとされている。

**ただし動かないわけではない。** システム RAM が 31GB あるので、
Ollama が VRAM に載りきらない層を CPU にオフロードして実行する。
**問題は速度のみ。** これは実測して判断する。

### 3-3. 候補と代替

| モデル | サイズ | VRAM に載るか | 状態 |
| --- | --- | --- | --- |
| **qwen3.8 (27B)** | ~18 GB | ✗ CPU オフロード必須 | **本命。ダウンロード中** |
| qwen3:14b | 9.3 GB | ○ | 導入済み |
| **qwen3.5:9b** | 6.6 GB | ○ 余裕 | 導入済み。**代替の第一候補** |
| gemma3:12b | 8.1 GB | ○ | 導入済み |
| phi4:14b | 9.1 GB | ○ | 導入済み |

**チャット用途では応答速度が体験を決める。**
27B が実用に耐えない速度なら、`qwen3.5:9b` に落とす判断をする。

### 3-4. 判断基準（実測して決める）

- [ ] 27B の生成速度（tok/s）と、初回応答までの時間
- [ ] 短い応答（50〜100 tokens 程度）に何秒かかるか
- [ ] 同時に Minecraft と BDS が動いている状態でのメモリ余裕

**目安**: チャットの返事が **5秒以内**に返るなら実用。
10秒を超えるならモデルを落とすか、応答を短く制約する。

## 4. 設計上、先に決めるべきこと

### 4-1. どのチャットを拾うか

全発言に反応すると、複数人がいるときに騒がしくなる。候補:

- **接頭辞方式**（例: `@ai こんにちは`）← 素直
- メンション方式
- 特定範囲・特定ディメンションでのみ反応
- カスタムコマンド方式（`/llm:ask`）

### 4-2. 応答が返るまでの間

LLM の応答には数秒かかる。その間:

- 「考え中…」を出すか
- 何も出さないか
- **重要**: `beforeEvents.chatSend` は **restricted execution**。
  ここで world を変更できないので、`system.run` で逃がす必要がある。

### 4-3. 会話履歴

- 履歴を持たない（毎回単発）← 最初はこれ
- プレイヤーごとに直近 N 往復を保持
- 保持するなら、どこに置くか（メモリ / dynamic property）

### 4-4. 応答の安全性

- **長すぎる応答をチャットに流さない**（行数・文字数の上限）
- `§` を含む応答で表示が壊れないようエスケープする
- 応答が来なかった / タイムアウトした場合の挙動

### 4-5. BDS 側の設定

`@minecraft/server-net` は**既定では許可されていない**。
`config/<スクリプトモジュールUUID>/permissions.json` で明示的に許可が要る
（[../research/03-bds-and-friend-join.md](../research/03-bds-and-friend-join.md)）。

また **experimental** なので、ワールドで「Beta APIs」実験トグルが要る。
