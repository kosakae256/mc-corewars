# 企画: 戦場のマップ

**2026-09-04 決定（仮案）。** **組み立て方は [spec/14-map-build.md](spec/14-map-build.md)。**
ここは**何を作るか**だけ。

## 1. 毎ウェーブ、別のマップになる

| | |
| --- | --- |
| **枚数** | **20 通り**を用意する |
| **選び方** | **完全にランダム。ただし直前 1 回に出たものは選ばない** |
| **いつ変わるか** | **ウェーブごと**（＝1 戦ごと） |
| **隠すか** | **隠さない。最初から 20 通りとも出る** |

> ### 除外するのは「直前の 1 つ」だけ
>
> **同じマップが 2 連続で来ると、変わった感じがしない。**
> **それだけを避ける。** 使い切るまで出さない、といった管理はしない。

## 2. 大きさと位置

```
        z = −50
          ┌──────────┐
x = −50   │          │   x = +50
          │  0, 0, 0 │
          └──────────┘
        z = +50
```

| | |
| --- | --- |
| **広さ** | **100 × 100**（x・z ともに **−50 〜 +50**） |
| **中心** | **マップごとに `x ＝ 1000 × 番号`**（2026-09-07 変更・[spec/19-map-store.md](spec/19-map-store.md) 0 章） |

> ### **0, 0, 0 は作業台**
>
> **マップは 1000 マスずつ離して常設する。**
> **図と座標は「マップの原点からの相対」として読む。**
| **実際に使う所** | **中央の 60 × 60 ほど**。外側は壁・景色・落ちる所 |

> ### 位置は動かさない
>
> **どのマップも同じ座標に置く。**
> **ずらすと「マップがずれる」類の分かりにくい事故が起きる。**

## 3. 高さ（**暫定。要確認**）

**ユーザーの指定は縦横だけ。高さは決まっていない。**

| | 暫定値 | なぜ |
| --- | --- | --- |
| **範囲** | **y = 0 〜 63**（64 マス） | **構造物 1 枚の上限が 64**。段を増やすと枚数が倍々になる |

**空中戦のマップも、この 64 マスの中で床を高い位置に置いて作る**——
**下を空にすれば「雲の上」に見える。**

> ### ここは変えられる
>
> **高さを 128 にすると、1 マップの構造物が 2 倍になる**（[spec/14-map-build.md](spec/14-map-build.md) 2 章）。
> **足りなければ増やす。** まず 64 で作ってみる。

## 4. 向きと、置くもの

**どのマップも、この決まりだけは共通にする。**

```
          奥（z ＝ +50）
        ┌──────[ ポータル ]──────┐
        │                        │
        │      中央 60 × 60      │   ← ここで戦う
   x=−50│         (0,0,0)        │x=+50
        │                        │
        └────[ 湧く場所 ]────────┘
          手前（z ＝ −50）
```

| | 場所 | 何のため |
| --- | --- | --- |
| **プレイヤーの湧く場所** | **手前（0, 地面, −40）** | **どのマップでも同じ所に立つ**——迷わせない |
| **ポータル** | **奥の端（0, **0**, ＋40）** | **必ず置く。** 遠くから見えて、向かう先になる。**裏は塞ぐ**（`spec/14-map-build.md` 0-3） |
| **敵の湧く場所** | **奥寄り**（z ＝ ＋10 〜 ＋40 のうち、立てる所） | 手前から押し寄せる形 |

> ### ポータルは「奥に必ずある」ことが大事（2026-09-04 決定）
>
> **どのマップでも、奥を向けばポータルが見える。**
> **地形がどう変わっても、向かう方向は変わらない。**
>
> **役割はまだ決めていない**——休憩所へ戻る出口になる想定だが、
> **いまは「置く」ことだけを決める。**

**地形の都合で真ん中に置けないときは、奥の端でいちばん平らな所へずらす。**

### 5-0. `stronghold` は「ポータル部屋だけ」にしない

> **ポータル部屋 1 つでは狭すぎる**（2026-09-05）。
> **石レンガの迷宮ぜんぶ**を戦場にする——**部屋・通路・図書室・牢**。
> **ポータル部屋は奥の見どころ**として置く（枠だけ。**ゲートの箱には触らない**）。

### 5-0-1. `sanctum` は休憩所と同じ意匠

> **ダンジョンらしいものが少ない**ので足した（2026-09-05）。
>
> **休憩所の神殿**（[spec/14-map-build.md](spec/14-map-build.md) 6 章、`core/rest-temple.ts`）
> **と同じ材料・同じ空気**——**クォーツ、市松の床、列柱、ステンドグラス、シーランタン。**
> **休憩所が「安全な神殿」なら、こちらは「戦う神殿」。**
>
> **同じ見た目の場所が 2 つある**ことで、**世界に筋が通る。**

  ────────────────────  ──────────────────  ████

| | |
| --- | --- |
| **外周** | **垂直な壁で囲う。円形。** 浮島にしない |

### 5-0-4. マップごとの設定（2026-09-06 追加）

**倉庫の覚え書きに持つ**（`19-map-store.md`）。**運営メニューから入切する。**

| 設定 | 何が起きるか |
| --- | --- |
| **出るか**（`on`） | 試合に出る／出さない |
| **大ジャンプ**（`bigJump`） | **そのマップに居る間だけ、跳べる高さが 20 マスになる** |

> ### 大ジャンプ
>
> **足場が離れているマップのためのもの。** いまは **`cloudsea`（雲海）でだけ使う。**
>
**跳んだ瞬間に、上向きの勢いを足す**（`services/jump.ts`）。

| 採らなかったやり方 | なぜ |
| --- | --- |
| **跳躍力上昇（効果）** | **高さが読めない。** 粒が出る。他の効果と混ざる |
| **`minecraft:jump.static`** | **モブ AI の部品。** プレイヤーの跳躍は**client 側の物理**なので効かない |
| **`minecraft:jump.dynamic`** | **`minecraft:movement.skip` が要る**（ウサギ・スライム用） |
| **属性で決める** | **プレイヤーに跳躍の属性は無い**（馬の `jump_strength` は馬だけ）。`@minecraft/server` にも `isJumping` しか無い |

**`Player.isJumping` で跳び始めを捕まえ、`applyKnockback` で velocity を足す。**
**押すのは「地面を蹴った、その tick」**——`isJumping` が立った最初の 1 回だけ。
**地面を離れてから押すと、跳んだ弧の途中でもう一度蹴られて気持ち悪い**（2026-09-06 の直し）。
**毎 tick 見る**——跳び始めを取り逃がすと、そこだけ跳べない。

> ### 高さの当て方
>
> **高さは初速の 2 乗。** ふつうの跳躍は初速 0.42 で約 1.25 マス。
> **20 マスなら初速 1.68 ＝ 足すぶんは 1.26**（`services/jump.ts` の `UP`）。
> **10 マスなら 0.77、5 マスなら 0.42。**

**落下ダメージは、大ジャンプの間だけ止める**（`entities/player.json` の
`minecraft:damage_sensor`）——20 マス跳べば 20 マス落ちるため。
**それ以外のマップでは普通に痛い。**

### 5-1. ばらけ方

**同じ形が続かないように、骨で分けてある。**

| 骨 | どれ |
| --- | --- |
| **平ら**（撃ち合い） | 4・8・14・17 |
| **高低差**（登る・見下ろす） | 1・5・8・12・14・16 |
| **足場が切れる**（落ちる） | 2・3・6・7・12・13 |
| **屋根がある**（屋内） | 7・10・15・16・17 |
| **建物が遮る**（迷路） | 4・5・10・16 |

> ### 落ちたら死ぬのは 4 つ（2・3・6・9）
>
> **緊張の質が変わる**ので、絞ってある。

> ### 屋内が 5 つある
>
> **天井の高さを間違えると、弓が当たらない。**
> **最初の 1 つ**（`crypt` あたり）**で高さを確かめてから**、残りを作る。

### 5-1. **落ちたときの扱い**（2026-09-06 決定）

**落ちても死なない。** **y −30 まで落ちたら、湧く所へ戻す。**
**代償として、いまの HP の 25% を削る**（HP 3 以下なら削らない）。

表の「奈落＝死」は、**この形で読む**——落ちれば戻され、HP を持って行かれる。
決まりは [spec/17-state.md](spec/17-state.md) 3-5。
