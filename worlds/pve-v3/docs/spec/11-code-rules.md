## 2. 層（**設計図は [12-architecture.md](12-architecture.md)**）

```
features / events  →  services  →  state  →  core
```

**逆向きの import は ESLint が落とす。** 決まりの本体は設計図、ここは**守らせ方**。

| 何を見張っているか | どう見張るか |
| --- | --- |
| **core が Minecraft を知らない** | `no-restricted-imports`（`^@minecraft/`） |
| **層を逆に呼ばない** | 同上（`^\.\.?/.*(services|features|events)/` など） |
| **feature どうしを import しない** | 同上（`^\.\./(?!\.\.)[^/]+/`） |
| **1 ファイル 300 行まで** | `max-lines`（例外は `services/fx.ts` だけ。理由つきで設定に書く） |
| **輪は 1 本** | `no-restricted-syntax`（`system.runInterval` は `loop.ts` 以外で禁止） |

> ### glob ではなく正規表現で書いている
>
> `no-restricted-imports` の `group` は **gitignore の書き方**で照合するため、
> **相対パターンが意図しない所まで拾う**（`..` を巻き込む）。
> **`regex` なら、相対指定の形をそのまま見られる。**

## 3. 名前の付け方（v3 固有）

| 何 | 接頭辞 | 例 |
| --- | --- | --- |
| **実体・道具・ブロック・粒** | **`pve_v3:`** | `pve_v3:bow` / `pve_v3:grunt` / `pve_v3:arrow_trail` |
| **動的プロパティ** | **`pve3:`** | `pve3:hp` / `pve3:hp_max` |
| **コマンド** | **`pve:`** | `/pve:spawn` |
| **テクスチャのファイル名** | **`pve3_`** | `textures/particle/pve3_spark.png` |

> ### コマンドだけ短いのは意図的
>
> **実体や道具の名前は、ゲームが衝突を検出する。**
> **コマンドは毎回手で打つ**——短さのほうが効く。
>
> **その代わり v2 とぶつかる。** **両方を同時に有効化しない。**

> ### テクスチャは「参照」と「ファイル名」を揃える
>
> v2 から移すとき、**JSON の参照だけ書き換えて、PNG のファイル名を変え忘れる**と、
> **絵が出ないのに何のエラーも出ない。** 移植のときは必ず突き合わせる。

## 4. ディレクトリ

```
packs/pve_v3/
├ behavior_packs/pve_v3/    blocks / entities / items / manifest.json
├ resource_packs/pve_v3/    particles / textures / models / attachables / entity
├ tests/                    core 層のテスト（**ゲーム無しで回る**）
└ scripts/
   ├ main.ts                合成ルート。配線だけ
   ├ features.ts            動かすものの一覧（**並びが tick の順番**）
   ├ loop.ts                輪は 1 本
   ├ types.ts               Feature の宣言
   ├ core/                  **純粋。Minecraft を知らない**
   ├ state/                 保存するもの（鍵は state/keys.ts）
   ├ services/              土台の振る舞い（API に触る）
   ├ features/<機能>/       入口。機能ごとに 1 つ
   └ events/                イベント購読（1 イベント 1 か所）
```

**中身の一覧は [12-architecture.md](12-architecture.md) 2 章。**

## 5. 直したら、必ず通すもの

```bash
cd worlds/pve-v3/packs/pve_v3
npm run check         # 型 → lint（層・行数・輪）→ テスト
npm run local-deploy  # ビルドしてゲームへ
```

**`check` が通ってから `local-deploy`。**
**入れていないものは、確認できない。**

### 5-1. 忘れても、止まる（ハーネス）

**`.claude/settings.json` の PostToolUse フック**が、
**`.ts` を書き換えるたびに `npm run check` を走らせる**（`tools/hook-check.mjs`）。

| | |
| --- | --- |
| **通れば** | 何も出ない |
| **落ちれば** | **そこで作業が止まる**（終了コード 2）。**直すまで次へ進めない** |

> ### 決まりは、書いただけでは守られない
>

## 6. ゲームに反映されないときに見る所

| 症状 | たいていの原因 |
| --- | --- |
| **ブロックが `/setblock` で「見つからない」** | **カスタムブロックはワールド読み込み時にしか登録されない。** `/reload` では足りない——**入り直す** |
| **粒が出ない・変な形** | 識別子は合っていても、**参照している PNG が無い**。エラーは出ない |
| **`blocks/` が読まれない** | **BP の manifest に `"type": "data"` のモジュールが要る**（script だけでは読まれない） |
| **スクリプトが動かない** | **content log を見る**。読み込み時のエラーはここにしか出ない |
| **数字が合わない** | **`hit()` を通っているか。** 通り道は 1 本なので、そこに `console.warn` を 1 つ置けば分かる |
