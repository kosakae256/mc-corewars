# 仕様: 戦場の組み立て

**何を作るかは [../02-map.md](../02-map.md)。ここは組み立て方。**

## 0. どのマップにも共通の決まり（2026-09-05）

**ここに書いたことは、20 マップすべてで同じ。** マップごとに変えてよいのは**地形と意匠だけ。**

### 0-1. 座標と大きさは、全マップで同じ

| | 座標 | |
| --- | --- | --- |
| **スポーン** | **(0, 0, −40)** | 手前。**着いた瞬間 ＋z（奥）を向く**。人は **y ＝ 1** に立つ |
| **ポータル** | **(0, 0, ＋40)** | 奥。**遠くから見えて、向かう先になる** |
| **地面の高さ** | **y ＝ 0 で固定** | **どのマップでも同じ。** 揃っていないと同じ動きで戦えない |
| **地形の底** | **y ＝ −50** | ここに岩盤を敷き、その上に積む。**上へは自由** |
| **生成する範囲** | **x・z ともに −50 〜 +50**（100 × 100） | **土台も含めて、これより外に 1 ブロックも置かない** |
| **バリア** | **x・z ともに −60 〜 +60** | **手で張る。** 生成では触らない。ここから外へは出られない |

**座標は `core/places.ts` の `FIELD` に置いてある。** マップ側はそこを読む——
**数値を写すと、直したときに片方だけ古くなる。**

**0.5 ずらしを忘れない**——飛ばすときは `core/places.ts` の `center()` を通す
（`17-state.md` 2 章）。**整数のままだとブロックの角に立つ。**

### 0-2. 飛ばす先には、必ず足場がある

> ### 空中に出したり、地形に埋めたりしない
>
> **スポーンの足場は「たまたま地面があった」では駄目。**
> **そのための場所を、地形より先に確保する。**

| | |
| --- | --- |
| **足場** | スポーンの真下に**不透過ブロック**。周りも平らにならす |
| **頭上** | **空ける。** 埋まって窒息しない |
| **順番** | **地形を削ったあとに、足場を置き直す**——地形生成に消させない |

### 0-2-1. **ゲートの箱は決まっている**（2026-09-05 追加）

```
(1, 1, 39) 〜 (-1, 5, 39)
```

> ### **マップにポータルを立ててはいけない**
>
> **ゲートは、敵を倒し切ったときに進行の側が置く**（`20-portal.md` 0-2）。
> **この箱は空けておく**——枠の飾りは置いてよい。

**着いたと見なすのは、その手前（z ＝ +40）に寄ったとき。**

### 0-3. ポータルは**見えて、裏へは回れない**

> ### 湧いた所からポータルが見えること
>
> **間に岩や起伏があると、どこへ行けばいいのか分からない。**
> **湧く所とポータルを結ぶ帯（|x| ≤ 6）は平らにして、遮るものを置かない。**
> 岩も草も、この帯には置かない。

**特に理由がない限り、ポータルの裏は不透過ブロックで構成し、奥へは行けないようにする。**
**回り込めるポータルは、置く意味がない。**
**浮島なら、裏は縁の外＝奈落でよい。**

### 0-4. 外壁は「登れない」ことが条件

> ### 登れる外壁を作らない
>
> **いちばん外側の壁を登られると、盤面の外へ出られる。**

| コンセプト | どう閉じるか |
| --- | --- |
| 崖・岩山 | **ネズミ返し**（上ほど張り出す）。足がかりを作らない |
| 建物・遺跡 | **垂直な壁。** 段差・出っ張り・階段を外側に付けない |
| 浮島 | **壁を取り払って奈落にする。** 落ちれば戻される |

### 0-5. 物理的に正しい形にする

**浮いている岩を作らない。** 出っ張りは**下から支えが続いていること。**
**支えのない張り出しは、ネズミ返しの意図があるときだけ**——それも岩盤から続けて彫る。

### 0-6. 似た形を並べない

> ### 同じ岩が並ぶと、作り物に見える
>
> **岩・壁・建物、どれも「同じ型を置き直しただけ」にしない。**

| 散らすもの | |
| --- | --- |
| **大きさ** | 半径・高さを 1 つずつ変える |
| **形** | 丸・角・傾き・欠けを混ぜる。**同じ関数に同じ引数を渡さない** |
| **向き** | 回す。左右を返す |
| **並び** | **等間隔に置かない。** 間隔そのものを散らす |
| **材質** | 同じ石でも、混ぜる割合を場所ごとに変える |

### 0-7. 自然地形は**まばらに**（2026-09-05）

> ### 一様に塗らない
>
> **地面が一面の粗い土、壁が一面の石**だと、**塗り絵**に見える。
> **自然のものは、まだらに混ざっている。**

> ### **まばら ＝ 1 マスごとに違う**（2026-09-05 に言い直した）
>
> 「区画ごとに主役の材を決めて塗り分ける」ではない。**それは塗り絵の升目が大きくなっただけ。**
>
> **隣り合うマスが、しょっちゅう違う材になっている**状態を指す。
> **引くのは 1 マスごと。**

| | |
| --- | --- |
| **引き方** | **1 マスごとに乱数を引いて、材を決める。** 区画では決めない |
| **寄り** | そのうえで、**ゆっくり変わる「寄り」**を足す——場所によって混ざり方が変わる |
| **材の数** | **4〜6 種**を混ぜる。2 種だと市松に見え、多すぎると濁る |
| **壁・岩肌** | 同じ石でも、**苔・ひび・凝灰岩の入り方を 1 マスごとに引く** |
| **草・苔** | **一様に撒かない。** 湿った側・日陰の側に寄せる |

**建物・遺跡は別**——人が作ったものは揃っていてよい。

### 0-8. 島の上は、**どこでも登れる**（2026-09-05）

> ### **敵も登る**
>
> 遮蔽の岩に登れないと、**敵が回り込めず、そこが安全地帯になる。**
> **戦えない場所を作らない。**

| | |
| --- | --- |
| **段差** | **1 マスまで。** 2 マス以上を作らない |
| **高い岩山** | **作らない。** 遮蔽は低くて広いものにする |
| **壇・階段** | **1 段ずつ。** 縁が崖になっていたら、そこは登れない |
| **例外** | **外周**（0-4。外へ出られないことが優先）と、**1 マスの柱・門などの装飾**（歩いて回り込める） |

> ### 「段差 2 マスが 1 つでもあれば駄目」ではない
>
> **1 マスの柱は回り込める。** 見るべきは
> **歩いて行けない面が、まとまって残っていないか。**

> ### 地形と構造物を別々に積むと、足し算で段差が出る
>
> 地形の傾きが 1 マス以内でも、**その上に高さ 1 の岩を置けば、隣との差は 2 になる。**
> **最後に高さの表を見て、隣より 2 マス以上低い所を埋める**（`smooth`）。
> **埋めるだけ**なので、削って形が崩れることはない。

**地形そのものにも効く。** 起伏の傾きが 1 マスを超えないように、
**揺らぎは「波長を長く、振幅を小さく」取る。**

### 0-9. **組む前に数えて確かめる**

```
node tools/pve3-map-check.mjs
```

**範囲の食み出し・登れる外壁・浮いたブロックは、中に立っていても分からない。**
**目で見て気づけないものを、数で止める。**

| 見るもの | 落ちる条件 |
| --- | --- |
| **0-1** | 空気以外を **±50 より外**に置いている（空気は「消す」側なので外まで抜いてよい） |
| **0-3** | **湧く所の目の高さからポータルへ線を引いて**、途中に何か有る |
| **0-4** | どの向きも、**島が切れる（奈落）か、2 マス以上の段差**で閉じているか。どちらでもない向きがある |
| **0-5** | **塊が 2 つ以上ある**（いちばん大きい島から切り離されたものがある） |
| **0-8** | **湧く所から歩いて行けない面**が、**4 マス以上まとまって**残っている（1 マスずつ上り下りできるとして塗り広げる。門と衝立の上は除く） |

**`tests/` に置けない**のは、`scripts/` が `./build.js` の形で読み合っていて
**Node が `.ts` のまま辿れない**ため。**esbuild で束ねてから読んでいる。**

## 1. 構造物はビヘイビアーパックに入れる

```
behavior_packs/pve_v3/structures/pve3/<マップ>_<区画>.mcstructure
                                    ↓
                       識別子  pve3:<マップ>_<区画>
```

> ### **パックに入れると、直したものが必ず反映される**（2026-09-04 決定）
>
> **`StructureManager.delete()` は、パック同梱の構造物では投げる**——
> **つまりワールド側に焼き付かない。** **パックを更新すれば、次からは新しい版が出る。**
>
> ワールドに保存する形（`/structure save`）だと**古い版が残り続け**、
> 「直したのに変わらない」という追いにくい事故になる。

**一覧は `world.structureManager.getPackStructureIds()` で取れる**——
**マップの登録表をコードに二重で持つ必要がない。**

## 1-1. 手直しを焼き付ける（2026-09-05）

```
/pve:build ok            建築モードに入る（idle からだけ）
   ↓  生成器で下地を組み、手で直す
/pve:mapsave basin ok    いまの xz = 0,0 の地形を、区画に分けて保存する
   ↓
node tools/pve3-map-freeze.mjs basin    ワールドからパックへ移す
```

> ### 実際に戦う場所で直す
>
> **別の場所で作ると、置き直したときにずれる。**
> **xz ＝ 0, 0 で直し、そのまま同じ座標で保存する。**

### 区画の割り方

**構造物 1 枚は 1 辺 64 マスまで。** いまの窪地の実寸は
**x・z が −50〜+50（101 マス）、y が −33〜+11（45 マス）。**

| | |
| --- | --- |
| **平面** | **2 × 2 に割る。** x・z それぞれ −50〜0 と +1〜+50（51 マスと 50 マス） |
| **高さ** | **割らない。** 45 マスは 1 枚に収まる |
| **枚数** | **4 枚** |
| **識別子** | `pve3:<マップ>_<0〜3>` |

### なぜ 2 段階なのか

**スクリプトはパックにファイルを書けない。**
`structureManager.createFromWorld()` が保存できるのは**ワールドの中**まで。

そこから**パックへ移すのは道具の仕事**（`tools/pve3-map-freeze.mjs`）。
パックに入れて初めて、**直したものが必ず反映される**（1 章）。

## 2. 分割

**構造物 1 枚は 1 辺 64 マスまで。** 101 × 101 × 64 は 1 枚に入らない。

| | |
| --- | --- |
| **1 枚** | **26 × 26 × 64**（x・z を **4 分割**、y は割らない） |
| **1 マップ** | **16 枚** |
| **識別子** | `pve3:<マップ>_<0〜15>` |

```
        ┌──┬──┬──┬──┐
        │12│13│14│15│   ← 各 26×26×64（y は −34〜+29）
        ├──┼──┼──┼──┤
        │ 8│ 9│10│11│
        ├──┼──┼──┼──┤
        │ 4│ 5│ 6│ 7│
        ├──┼──┼──┼──┤
        │ 0│ 1│ 2│ 3│
        └──┴──┴──┴──┘
```

**なぜ 4 分割なのかは 2-2。** **1 枚を置いている間、サーバーが止まる**ためで、
**1 辺 64 マスの制限とは別の理由。**

### 2-1. 置くのは **`system.runJob`** に任せる（2026-09-05）

**4 枚（65 万ブロック）を 1 tick で置くと、サーバーがその間止まる。**
止まると**暗転の掛け直しが届かず、走り切って明るくなる**（`13-flow.md` 2 章）。

> ### 自分で毎 tick 刻まない
>
> **`system.runJob` は、ジェネレータに毎 tick の時間枠を配ってくれる。**
> **`yield` するまで進めて、そこで返す**——**刻み幅をこちらで決めなくてよい。**
>
> ```ts
> function* placeJob(name) {
>   for (const piece of PIECES) {
>     structureManager.place(id, dim, piece.from);
>     yield;                    // ← ここでエンジンに時間を返す
>   }
> }
> system.runJob(placeJob(name));
> ```

**段には割らない。** 平面を割る。**1 枚ずつ `yield` すれば足りる。**

### 2-2. **1 枚を小さくする**（2026-09-05）

> ### `yield` で刻めるのは、**枚と枚の間**まで
>
> **`place()` の 1 回は、どうしてもその間サーバーが止まる。**
> **1 枚 51 × 51 × 64 ＝ 16 万ブロックでは、約 1 秒止まった。**
> 暗転は**時間で走る**ので、**0.5 秒の保ちが切れて一瞬明るく見えた**
> （「チェスト UI が開く 2〜3 tick 前に、ちらっと見える」）。

| | 前 | いま |
| --- | --- | --- |
| 割り方 | **2 × 2** | **4 × 4** |
| 1 枚 | 51 × 51 × 64（**16 万**） | **26 × 26 × 64**（**4 万**） |
| 枚数 | 4 枚 | **16 枚** |
| 1 枚あたりの停止 | 約 1 秒 | **その 1/4** |

**暗転が保つのは、掛け直してから 0.85 秒**（保ち 0.5 ＋ 明転 0.35）。
**1 枚ぶんの停止が、そこに収まればちらつかない。**

> ### 掛け直しは**枚の前後**でしかできない
>
> ```ts
> darkRefreshAll();   // 置く直前
> structureManager.place(id, dim, piece.from);
> yield;              // ← ここで初めてクライアントに届く
> ```
>
> **同じ tick の中で呼んでも、その tick が終わるまで届かない。**
> だから**掛け直しだけでは足りず、枚を小さくする**必要がある。

> ### 保つ時間を延ばして凌いではいけない
>
> 延ばした分だけ**明転が遅れる**（`13-flow.md` 2 章「Combining fades」）。
> **止まる時間のほうを短くする。**

**足りなければ、さらに割る**——`GRID` を上げるだけでよい。

### 2-3. 割り方は**マップごとに覚える**

**割り方を変えると、前に焼いたものが読めなくなる**（枚数も範囲も変わる）。
だから**覚え書きに `grid` を持たせる。**

| | |
| --- | --- |
| **`grid` が無い** | **2**（4 × 4 にする前に焼いたもの）として置く |
| **保存したとき** | そのときの `GRID` を書く |

**焼き直せば新しい割り方になる。** 古いマップも置ける。

## 3. 前のマップの消し方

> ### **消さない。上から置くだけで消える**（2026-09-04 決定）
>
> **`place()` は「構造物の空白（structure void）」だけを置かずに飛ばす。**
> **本物の空気は、ちゃんと空気として置かれる。**
>
> **だから、マップを保存するときに structure void を使わず、空気のまま保存する。**
> **そうすれば、置いた瞬間に前のマップは消えている**——
> **`/fill` で 64 万ブロックを消す工程が丸ごと要らない。**

**ただしブロック以外は残る。** 置く前に**範囲の中を片付ける**。

| 残るもの | 始末 |
| --- | --- |
| **前の戦闘の敵** | 消す |
| **落ちているアイテム・矢** | 消す |
| **自前の弾（あれば）** | 消す |

## 6. 休憩所は、構造物にしない

**戦場と違って、休憩所は毎回同じ**（`../00-concept.md` 2 章）。

> ### 形が変わらないなら、手順を書くほうが短い
>
> **20 枚の戦場は毎回入れ替わるから構造物に焼く。**
> **休憩所は 1 つきりなので、手順（`scripts/core/rest.ts`）を書いて、
> 必要なときに組み直す。** 直すのも、そこを書き換えるだけで済む。

### 6-1. 形——**空の下の円形広場**（2026-09-04 決定）

> ### 天井で塞ぐと、地下室にしか見えない
>
> **柱を並べて空を開ける。** 見上げれば空、周りは列柱。

```
              z ＝ +46   [ ポータル ]
              z ＝ +30   強化 強化 ショップ 強化 強化
  円の中心 →   z ＝ +24        ·
              z ＝ +18   宝箱  宝箱  宝箱
              z ＝   0   ▲ 立つ所（円の手前の縁）
```

**立つ所は円の中心ではなく、手前の縁。** 奥へ進むほど、先の物が出てくる。

| | |
| --- | --- |
| **場所** | **−2000, 0, −2000**（**床が y ＝ 0**） |
| **広さ** | **床は半径 26 の円**、列柱 24、尖塔 29、神殿の間 32 |
| **素材** | **クォーツとガラス。** 砂岩は使わない |
| **明かり** | 海のランタン・端の棒・淡青のガラス |
| **組み方** | `/pve:buildrest`。**1 tick に 8,000 マスぶん**進める（約 66 万マス） |

> ### 円は「角度で刻む」と隙間が空く（2026-09-04 に直した）
>
> 半径 60 の円を 2 度ずつ刻むと、**1 マスおきに穴が空く**——
> **実際に「柱が雑い」形で出た。**
>
> **x で走らせた点と、z で走らせた点を合わせる**（`core/build.ts` の `circlePoints`）。
> これなら必ず繋がる。

> ### 壁は左右対称にしない（2026-09-04 決定）
>
> **16 区画それぞれに違う意匠を書く**（`core/rest-shaft.ts` の `BAYS`）——
> 縦長・帯・双子・丸窓・無窓の 5 種と、**10 色のガラス**。
> **輪をぐるっと自動で回すのではなく、区画ごとに置く。**

### 6-2. 囲いは「壁」ではなく「柱とガラス」

> ### 高い壁を回すと、井戸の底に見える（2026-09-04 決定）
>
> **太い柱を数本立てて、その間をガラスで塞ぐ。**
> 参考にした絵もそうだった——**壁という壁は無い。**

| | |
| --- | --- |
| **太い柱** | **8 本・3 × 3・高さ 17**（半径 33） |
| **その間** | **色ガラスを 1 枚ずつ**（8 色）。**入口とポータルの正面は開ける** |
| **その外** | **すり鉢の斜面**（半径 42 → 66 で、高さ 0 → 60 を 12 段） |

```
                                     ┌── 地表（y ＝ 60）
                             ┌───────┘
                     ┌───────┘          すり鉢
  ‖ ‖   ‖ ‖  ┌───────┘                  ‖ ＝ 太い柱
  ───────────────────────────────────   y ＝ 0
```

> ### 埋め戻しに石を使わない（2026-09-04 決定）
>
> **石で埋めていたら、外から生の石の山として見えた。**
> **地面が神殿より低い所では、そのまま壁になって残る。**
> **神殿と同じ石材（磨きクォーツ）で埋める。**

> ### 掘る半径と、置く半径をずらさない
>
> **掘るのは切り捨て、壁は四捨五入**で位置を決めていたので、
> **その差の 1 マスに石が残って、内側から見えた**（2026-09-04）。
> **掘る半径 ＝ 置くものの外側**に揃える。
>
> **組み上げて「空気に面した石」を数える道具**で確かめてある。
