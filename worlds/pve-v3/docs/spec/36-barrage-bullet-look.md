# 弾幕の玉の見た目

## 追加修正: ランダム移動の復元

共通遠距離AIの生成処理が弾幕の`random_hover`も削除していたため復元する（spec/38）。
射程内で射線があるときは静止せず低空をランダム移動しながら放射する。標的不在時も移動する。
射程外・遮蔽時は攻撃位置への接近を優先。高度・弾速・頻度・粒数は維持する。

2026-09-10: ユーザー希望は東方の弾幕のように見える弾。16方向の放射・発射間隔・速度・射程・当たりの太さは既存仕様を使い、玉の描画を作り直す。

## 原因

現行 `geometry.pve3.orb` は10×10×10の立方体へbox UV `[0,0]` を使うが、テクスチャは16×16。
必要な展開図が画像の範囲に収まらず、丸い画像が6面へ分断されている。

## 変更

- 東方風の読みやすい丸弾を新規制作する。白い芯、明るいシアン、青緑の外周、細い濃紺の輪郭。
- 暗い場所・明るい場所のどちらでも一粒の形を見分けられるようにする。細長い残像は付けない。
- 元画像は画像生成ツールで作成し、採用原稿とプロンプトを `user/barrage-bullet/` へ保存。
- ゲーム用は低解像度32×32の透過PNG。発光用の素材を使用する。
- 追加指定: 弾エンティティは重いため使わない。`orbit.body` を外し、`orbit.sprite` で専用の丸弾パーティクルを指定する。旧orbアセットは他の利用を壊さないよう保管したままにする。
- 当たり・壁・射程の処理は既存の `bullet.ts`。表示のためのspawnEntity／teleport／removeは行わない。
- `BulletSpec.sprite` を追加。4tickごとに1粒だけ生成し、寿命を次の表示までの4tick（0.2秒）とする。
  その間はクライアントで弾速に合わせて直進する。カメラを向く板で描き、固定した残像を連ねない。
- 粒へ速度（マス／秒）と寿命を渡す。射程終端では残り距離で寿命を短縮する。
  壁接触時はパーティクル自身も消える。人への命中後の描画は最大0.2秒で消える（当たりは既に終了）。
- 表示の直径は既存模型と同じ0.625マス。発光を大きくにじませない。
- 専用のパーティクルJSON・PNGを読み込む16方向の確認画面を作り、自分でも確認する。
- 通常の最大滞空弾は約224個／敵。表示更新は毎tickの実体移動から4tick間隔の粒に減らす。
  スクリプトの毎tickの区間当たり判定は維持する。フレームレート改善の実測は実機で行う。

`npm run check` 後、RPの版を上げてローカルへ配置。実機の描画とプレビューは区別する。

原稿: `user/barrage-bullet/generated.png`、生成指示: 同フォルダの `prompt.txt`（built-in image_gen）。
導入: `tools/pve3-barrage-texture.ps1`。確認画面: `python tools/pve3-barrage-preview.py` → `out/barrage/index.html`。
上空／斜め、明暗の背景を切り替えられる。ブラウザ上の画像読み込み・再生を確認した。

実装をAPIの代替環境で動かし、16発を30マス飛ばして弾エンティティ生成0回、
粒の更新544回（1発34回）、射程終了時に弾の状態が0個になることを確認した。
これはFPSの実測ではなく、生成経路と更新数の検証。

### 追加調整: 弾幕の低空飛行と描画負荷

弾幕は飛行を維持し、足元と地面の間を約1〜2マスに保つ。プレイヤーの高さではなく、
自身の真下を64マスまで調べた衝突面を基準にする。上下速度を減衰させながら補正し、
横移動と20マスまで近づくAIは維持する。未ロード・地面が見つからない場合は上昇を止めて緩やかに降りる。
既存の他の飛行モブは従来のプレイヤー基準の高度制御を使う。

弾幕は10体で最大約2,140発が同時に飛び、4tick更新では粒生成が毎秒約10,880回になる。
一発一回生成への変更は、命中後に見た目だけ残るためユーザーの希望に合わず採用しない。
短寿命方式にも最大0.2秒の残像があり、完全な即時消去を保証できる方式ではない。
今後の負荷対策は、実際の弾数・発射頻度を混雑時に減らす案を提示する。
見えない弾のダメージを残す間引きはしない。今回、攻撃密度は勝手に変更しない。
エンジンの粒上限や描画更新遅延は実機計測が必要であり、PC性能だけを原因と断定しない。

### 負荷対策の採用設定

ユーザー指定で弾速を0.225→0.45マス/tick（毎秒9マス）、発射間隔を10→20tickへ変更。
1回16発・射程30マス・命中処理・4tickごとの短寿命表示は維持。
飛行時間が半分、発射回数も半分なので、定常時の同時弾数と粒生成数は概ね従来の1/4。
10体で同時最大約640発（発射直後）、平均約533発。生成は1発17回、毎秒約2,720回。
実機FPSとちらつき改善はゲーム内確認が必要。

検証結果（今回）: `npm run check` は100テスト・BP62件・RP61件・アニメーション61件・姿勢33件すべて成功。
実装を使った10体×30秒の無障害物シミュレーションでは、同時最大640発、粒生成81,600回
（発射期間1秒あたり2,720回）、弾エンティティ0体、全弾終了後の残り0発。
実機FPSは未計測。攻撃間隔は個体に保存されるため、変更前からいる弾幕は再出現させて確認する。
BP 1.0.1 / RP 1.0.205を開発パックへ配置。
