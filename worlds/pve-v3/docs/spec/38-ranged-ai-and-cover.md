ユーザー指定の調整。パワー系の速度を0.4、ゴーレムは0.5のまま。
追尾弾の発射間隔を10tick（0.5秒）へ変更し、呪いの攻撃速度段も同じ間隔を基準にする。
追加指定: 恵み・鼓舞の移動速度を0.5から1.0へ変更。支援・逃走条件は維持する。
既存個体はAI移行版2で移動値を一度だけ2倍にして呪い倍率を保持し、新規個体は版2を記録する。
同じ移行版で急所の移動速度を1.0→0.7（既存移動値×0.7）、チェンバーのノックバックを3.0→1.0へ変更する。
チェンバーの上向き成分0.35、威力・間隔は維持する。
チェンバーと妖狐の攻撃力・射程・溜め時間・追尾・頻度は維持。

## 遠距離の共通判断

射撃・beam・遠距離sweep・lob・orbitを持つ16種類が対象。
同じ次元の生存・非クリエイティブ・非観戦プレイヤーを100マスまで索敵。
射程は各攻撃の定義を参照し、近接用reachを誤って使わない。
射程外、または射線なしならネイティブのnavigationで目標へ近づき、壁を迂回する。
射程内かつ射線ありなら移動を止めて既存の攻撃を行う。
ブレイズは`charge.approach`により、攻撃開始15マス・接近停止10マスを分ける（spec/40）。
溜め中は接近を継続でき、連射中の停止のみ`rangedBusy`で共通接近より優先する。
従来のランダム移動・距離維持・近接接近がこの判断と競合しないよう部品群を統一する。
ただし弾幕は例外として、攻撃可能時と標的不在時に低空でランダム移動を行う。
baseに`random_hover`（priority 6、interval 1、xz_dist 8、y_dist 1、hover_height [1,2]）を残す。
射程外・遮蔽時はpriority 0の接近を優先し、攻撃可能になれば接近を解除してランダム移動へ戻る。
弾幕の放射攻撃はScriptから並行して行い、地面から1〜2マスの高度制御は維持する。
射線は0.5秒ごとに確認し、実際の攻撃開始でも再確認。溜め中は移動しない。
壁が完全に閉じていて到達不能なら迂回経路は作れない。瞬間移動や壁抜けでは解決しない。
追尾弾だけは例外で、射線を見ずに撃つ。弾が壁で消えず、壁の手前で向きを変えて迂回する
（`25-enemy-kit.md` 6-1）。動かない敵なので、射線を作りに行けないため。
従来速度0だったカウボーイ・チェンバー・追尾弾は、位置取り中だけ速度1.0で移動できるようにする。
構えて撃つときは従来どおり停止。追尾弾以外の発射頻度は変更しない。
既存個体は旧基準の攻撃間隔・移動速度を倍率を保って一度だけ移行する。

## 遮蔽物

発射点から対象の胴へ衝突ブロックのレイを引き、妖狐の遮蔽対象にはダメージを与えない。
追加のバランス調整（spec/34）により、妖狐の命中後の炎上は遮蔽の有無によらず撤廃する。
ガラス・半ブロック等は実際の衝突形状を使う。草など通過可能な物と水は遮蔽物に含めない。
未ロードなど判定できない場所は命中させない。チェンバーも対象ごとの遮蔽を確認する。
狐の炎の見た目は広がる演出として維持し、当たりと分ける。

## 全モブ監査と表示

全rosterについて実際にspawnするBPを追い、follow_range・nearest_attackable_targetの
within_radius・entity_types.max_distが100マスであることを検査する。
ウシ・ヒツジの中立性は維持し、反撃時の範囲を確認する。索敵100はチャンクの稼働範囲を拡張しない。
名前に `[★1]` 〜 `[★5]` を付ける。★1〜4は既存の帯ごとの色、★5は各モブの固有色と太字を維持。
既存個体の名前も更新する。

専用生成・監査ツールを追加し、全個体の監査結果をout/enemy-aiへ保存。
JSON・状態分岐・遮蔽と炎上・★表示を検査し、check後にパックを配置する。

## 生成・検証

`node tools/pve3-ranged-ai.mjs` でBPへ反映。`--check` はソースを変更せず差分を検知し、`npm run check` から毎回実行する。
他のモブ生成ツールでBPを再生成した際も、このツールを通す。監査対象は48種類・47実体（クリーパーの通常／帯電が同じ実体）。
中立のウシ・ヒツジを除く46種類は能動索敵100、2種類は反撃の範囲100。
ネイティブ射撃の移動倍率は正数必須のため0.0001にし、優先度0の共通接近が移動を担当する。
狐の旧fox_walk群は模型生成ツールとの互換のため定義だけ残し、共通AI・姿勢イベントからは有効にしない。

APIを置換したserviceテストで、射程／遮蔽による切り替え、溜め中停止、次元・生存状態、遮蔽時のダメージと炎上0、旧追尾間隔の一度だけの移行を検査。
経路探索そのものと最終的な歩き方はBedrockの実機で確認する。

## 接近停止への対応

### 2026-09-11 弾幕の召喚不能修正

ContentLogで`random_hover -> hover_height: expected an object`により弾幕全体が読込失敗していた。
format_version 1.26.20の公式schemaに合わせ、`hover_height`を`{"min":1,"max":2}`へ変更する。
低空1～2マスのランダム移動は維持。生成ツールと部品検査も同じ形式に揃える。

### 2026-09-10 テレポートの火力調整

テレポート（blinker）の素の攻撃力を20から10へ変更する。既存個体は移行版3で保存攻撃力を一度だけ半減し、呪いなどの倍率を維持する。新規個体は最初から版3として生成する。

### 現在の方式: 攻撃を無効にした継続追跡

半径100のmove_towards_targetでも、ユーザーがランダム歩行のような動き・遠距離での停止を確認。
この部品は接近から外し、spec/25の14章にある既存方式へ戻す。
接近群では`melee_box_attack`を`track_target: true`、`require_complete_path: false`、
`random_stop_interval: 0`、速度倍率1、優先度0で使用する。
`minecraft:attack.damage: 0`、`horizontal_reach: 0`、`can_spread_on_fire: false`とし、
Scriptの`hitsInMelee`も全遠距離種を除外して、この追跡から追加ダメージ・炎上を出さない。
射程内かつ射線あり、または溜め中なら追跡群を外す。既存の遠距離攻撃だけを行う。
2秒間進まない時の再試行は維持。全16種へ適用し、射撃の呪い段とは別の部品群にする。
以下のwithin_radius変更は、継続追跡への切り替え前の記録。

ユーザーが妖狐の接近停止を実機で確認。共通接近の`move_towards_target.within_radius`を
1から100へ変更し、索敵範囲に合わせる。攻撃距離で止める判断は引き続きScript側が担当する。
接近中に2秒間0.5マス以上進まなければ、接近部品群を外して付け直し経路探索を再試行する。
移動中は再起動せず、溜め中・攻撃可能な場所での停止中も対象にしない。
瞬間移動や壁抜けは行わない。追尾弾の壁越し発射の例外は維持する。
全16遠距離種の接近半径と、停止時の再試行・移動中と溜め中の除外を検査する。
