# 自分のHPとエメラルドを表示する

## 味方プレイヤーの頭上HP（2026-09-11）

ユーザー指定: 味方は名前・HP量に加えてゲージも必要。敵と同じような見え方にする。
プレイヤー名札を「プレイヤー名」「HPゲージ」「HP 現在値/最大値」の3行にする。
敵と同じplateText・bar・hpNumberを使い、ゲージは20目盛り、残量に応じて緑・黄・橙・赤へ変化する。
名前にはPlayer.nameを使い、生成済みnameTagを再利用してHP行を二重追加しない。
独自HPを持つオンラインプレイヤーを更新対象に含め、通常HUDと同じ2tick周期で変化時だけ更新する。
満タン・被弾・回復・HP0・4桁・最大HPの強化・ロビー復帰に追従する。
待機・建築・クリエイティブでも名札データは更新し、表示距離やしゃがみ時の見え方は通常の名札に従う。
敵のDebugTextと味方の的等の既存3行名札は維持する。

## 赤いHPゲージ（2026-09-10・以下の旧文字バー仕様を更新）

### 2026-09-11 実機の空表示・太さ・配置の修正（この節を優先）

#### 満タンでも赤くならない不具合：画像切り替えへ変更（最新）

修正版を読み込んだ実機でも100/100で赤が出ない。文字・所持金は出ているため、残量の算術式とclip bindingを使う方式を置き換える。
ゲージ内部は96×8px。ScriptがHP比率から塗る幅0～96pxを決定し、生存中は最低1pxを表示する。
同じ赤いグラデーションを左から指定幅だけ描いた97枚の透過PNGを生成する。表示するimageは従来と同じ1つ。
通信は`pve3:money:f96_______K:§a8`（満タン・所持金8）の形式にする。
先頭3文字f00～f96を画像名にし、残り7文字は旧欄長を保つ予約領域。所持金のK/L/M/Nと先頭12文字除去は変更しない。
JSON UIは先頭3文字を画像パスへ文字列結合して`#texture`へ渡す。数値変換・残量算術・clip_ratioは使わない。
titleのHP数値、枠、余白、HPと所持金の全体幅、字体は維持する。
0・満タン・半分・4桁・微小HPを検査し、全97画像のアルファ範囲を確認する。最後に再読み込み後の実機で赤い満タン表示を確認する。

#### 数字・残量が依然出ないことへの対応

実機で表示は出たが、数字が上寄り・所持金のサイズ段が重なっていた。数字labelの高さは`default`、アンカーは中央（所持金はright_middle）にする。
所持金の文字サイズはScript側で7/10/14/21文字に応じてK/L/M/Nから1つ選び、残量ビット直後に1文字を付ける。例:`pve3:money:abcDeFGHIJK:§a8`。
UIはその大文字の有無だけで1つのlabelを表示する。所持金は先頭12バイトを取り除いて表示する。UIで数字文字列を切って比較してサイズを決める処理は使わない。

文字表示は色コードを含む文字列のまま渡す。titleは`pve3:hp:§f200/200`、subtitleは`pve3:money:<10文字の残量ビット>:§a8`。
残量0～1000は下位ビットからA～Jで表し、0のビットをa～jとする（固定10文字）。UIは大文字の有無をboolとして重み付き加算し、文字列を数値へ暗黙変換しない。
所持金は先頭11バイトを除去するが、表示文字列の§aは消さない。桁数判定だけ色コードを除いた文字列を使う。
この変更の最終確認は実機表示で行い、独自式評価の成功だけを実機成功とは扱わない。

満タンでも赤と数字が見えない実機スクショを確認。HP数字はtitleの`pve3:hp:`以降を直接表示する。
残量はsubtitleへ移し、`pve3:money:0500:§a8`とする。HPを更新する場合も同時送信する。
画像のclipは「消す割合」なので`1.0 - 残量/1000.0`を渡す（満タン0・死亡1）。
ゲージ全高14px、内部96×8・原点(18,3)。文字は標準1.0倍とする。
クラシック系はHPの左端を-1、所持金の右端を181とし、ホットバーの左右端へ揃える。
上端offset=-40を保ったまま薄くして下に4pxの余白を作る。
所持金は幅58px（アイコン12・間隔2・数値44）を確保し、数値を右揃えにする。HPとの間は4px。
カンマを含む文字数が7桁までなら文字倍率1.0、10文字まで0.71875、14文字まで0.5、それ以上0.34375。最大安全整数の21文字も全桁表示し、HPへ重ならない。短い数値の倍率はHPと揃える。
プレビューは実際のJSON bindingの式を評価して縮小幅を決める。数字・素材だけを別計算する旧プレビューでは空表示の検査になっていなかった。

狩猟RPG風の赤いゲージ内に白いHP数値を中央配置する。幅120・高さ18 UIピクセル。
古金色の細い金属枠、左の赤い紋章、暗い溝、赤い残量。外側は完全透明で、半透明の背景板は付けない。
内部は96×10・原点(18,4)、数値は影付き・倍率1.0625。4桁同士でも中心と枠の位置を固定する。
PCとクラシックタッチはoffset(-21,-40)。経験値バーを非表示にしてHPと所持金を4px下げ、ホットバーに重ならない位置まで詰める。所持金は(0,-40)。ポケットの上部表示は(10,8)のまま。
経験値表示は `HudElement.ProgressBar` を既存のHealth・Hungerと一緒に非表示にする。経験値の値自体は変更しない。

通信を `pve3:hp:0500:100/200` に変更する。先頭4桁は残量0～1000、コロン以降が表示数値。
`%.4s` で抽出した残量を1000.0で割り、バニラ経験値バーと同じ `clip_direction: left` の `#clip_ratio` に接続する。
数値は先頭5バイトを除去して中央labelへ。空白パディングと縦棒は廃止する。
最大HP0・非数値は空ゲージ。生存中の小さい残量は最低1/1000とする。
独自HP処理、2tickの確認周期、5秒再送、クリエイティブ表示、通常タイトルの扱いは維持する。

`tools/pve3-hp-ui.py` が幾何図形からテクスチャとUI定義を生成し、同じ画像で満タン・半分・瀕死・死亡・4桁のプレビューを `out/hp-ui/` に出す。
プレビューはオフラインでの見た目確認であり、Bedrockのバインディング動作の保証とは区別する。
通信・残量境界・4桁・レイヤーと画像参照を検査し、全体チェック後に配置する。

## 旧文字バー仕様（変更履歴）

ユーザー指定: 背景の半透明板を付けず、`200/200 ||||||||||||||||||||` の順で表示する。
数字は白と灰、残量のバーは既存の緑→黄→橙→赤、減った部分は暗い灰にする。
既存の独自HPを参照し、バニラのハートは従来どおりScript APIで隠す。

## 配置と通信

RPのJSON UIで専用labelを追加する。バニラのHUD全体やタイトルの枠は置換しない。
PC／クラシックタッチ／ポケットの各healthの親panelへcontrolsの差分追加を行い、
それぞれのハートと同じ原点へ置く。HUD非表示やUI倍率は親の設定に従う。
labelは背景imageを持たず、文字の小さな影だけを使う。文字の倍率はHP・所持金とも1.0625倍。HP欄は幅92・高さ14 UIピクセル。
大きなHPでも収まるよう、数字の桁数に合わせてバーの本数を最大20から短くする。

Script APIには任意のHUDラベルへ独自HPを直接バインドする機能がないため、
`onScreenDisplay.setTitle`をデータ伝達だけに使う。`/title`コマンドは実行しない。
専用接頭辞`pve3:hp:`が付いた文字列だけ、JSON UIで接頭辞を除去してHP欄へ表示する。
この接頭辞のタイトルはバニラのタイトル表示を抑え、画面中央へ出さない。
通常のタイトルの構造・背景・アニメーションは維持する。
タイトルは当面HP通信に予約する。将来の中央通知は同じ窓口を通して調停する必要がある。

2tickごとにHPを確認し、表示内容が変わった時と5秒ごとの再送だけ送信する。
独自HPのあるプレイヤーには待機中・建築中も表示する。死亡時は0、復活・最大HP変更も追従。
退出時に送信キャッシュを捨て、再入場・リロード時は送信し直す。
狙っている敵のアクションバー表示は維持するが、自分のHPは重複させない。
クリエイティブ・観戦を理由に隠さない。UI側にも`#show_survival_ui`の条件を付けない。

## エメラルド（追加指示）

追加指示により食料ゲージを非表示にし、その位置をエメラルド欄に使う。
PC／クラシックタッチではホットバー上の右側、ポケットでは右上へ置く。
左のHP、右の所持金という並びにする。ゲームモードで非表示にしない。
バニラの`textures/items/emerald`を12×12 UIピクセルのimageで表示し、その右へ所持数を緑（§a）で表示する。
カスタム文字は不要。背景はHPと同じく付けない。
独自通貨`state/growth.emeraldOf`を参照し、`12,345`のように3桁区切りにする。
インベントリのアイテム個数ではなく、ショップで使う所持金を表示する。
setTitleのsubtitleへ`pve3:money:`付きで同時送信し、2つの表示が食い合わないようにする。
HPまたは所持金が変わった時だけ更新し、5秒ごとの再送も共通。既存の報酬通知は維持する。
食料ゲージの非表示はHealthと同じ`setHudVisibility`でHungerを指定する。ゲーム内の空腹値や消耗のルール自体は変更しない。

## 検証

HP数値・残量・バー長の計算を単体テストし、UI追加先を同梱バニラ定義と照合する。
背景imageがないこと、専用接頭辞以外のタイトルを隠さないことを検査する。
`npm run check`後に開発用パックへ配置。最終的な位置と表示は実機で確認する。

## 表示サイズの調整

HPと所持金の文字を従来の1.25倍へ統一する。HPは中央寄りへ8px移動し、PCでは上へ4px、ポケットでは下へ6px移動する。
所持金も高さを合わせる。横並びで重ならないよう、HPの文字列は拡大前72pxに収める目盛り数にする（200/200なら13本）。
背景なし・桁区切り・クリエイティブ表示は維持する。

### 文字サイズの再調整

1.25倍は大きすぎるとの指示により、HP・所持金とも元の1.125倍へ変更する。位置・色・アイコン・バーの本数計算は維持する。

さらに少し小さくする指定により、HP・所持金とも1.125倍から1.0625倍へ変更する。位置・色・アイコンは維持する。

### HP増減時の位置ずれ修正

数値とバーを別labelへ分け、数値は右端46px、バーは左端50pxへ固定する。
HPは4桁まで使用する。数値の桁数が増えた分は左へ伸ばす配置でよく、バーを右へずらして欄内へ収める調整は行わない（ユーザー確認済み）。
現在HPの桁数が変わっても、同じ最大HPなら斜線・最大値・バーの開始位置は動かさない。
バーは13本固定とし、HP増減では色の内訳だけ変える。倍率・親panelの位置は維持する。
通信は既存のtitleを使い、先頭の数値欄をASCII空白でパディングした39バイト、その後を色付きバーとする。
数値欄は書式コード込み（§fと§7が計6バイト）。JSON UIの`%.39s`で分離し、右揃えで描画する。
空白が折り返されない幅220pxの数値labelを使い、右端を固定する。背景は付けない。
