# 妖狐の溜めと狐火

## 最新調整: 命中後の炎上を撤廃

強すぎるとのユーザー指定により、妖狐の`sweep.igniteSeconds: 5`を外し、命中後の5秒間の炎上を付与しない。
直接ダメージ・遮蔽判定・射程・溜め・狐火のパーティクルと音は維持する。
以下に残る5秒炎上の記述は過去の仕様であり、この調整を優先する。

### 最新調整: 攻撃の炎の見た目を半速にする

ユーザー指定により、主炎・先端の炎・火の粉の移動速度を粒ごとに30〜90マス／秒へ変更する。
従来の60〜180マス／秒のちょうど1/2。速度のばらつき、寿命、粒数、溜め演出、ダメージ・射程・炎上は維持する。
以下の60〜180マス／秒は変更前の記録。

2026-09-10 ユーザー指定。妖狐の旧即時射撃を置き換える。

## 行動

### 最新調整: 遠距離の発射音の減衰を抑える

音量4だけでは遠距離でほぼ聞こえなかったため、狐専用のサウンド定義を追加。
`pve_v3:foxfire.ignite` と `pve_v3:foxfire.blast` は同じバニラ音源を参照し、
`min_distance: 64.0`、`max_distance: 96.0`、3D音とする。
60マス以内へ音量4で再生する既存処理は維持し、音源の方向は実際の発射位置を使う。
バニラの炎音そのものの定義は上書きせず、他の敵や着火操作の音には影響させない。
実機の聞こえ方は音量設定にも依存するため、配置後の聴感確認が必要。

### 最新調整: 炎ごとの速度差

主炎・先端の炎・火の粉の速度を、粒ごとに60〜180マス／秒へばらつかせる。
平均は従来と同じ120マス／秒。生成時に決まる `particle_random` を使い、
同じ粒の速度は寿命まで保つ。途中停止や毎フレームの速度変化は入れない。
方向用の乱数1・2、寿命用の乱数とも分け、速度によって一斉に消えないようにする。
最大2秒の寿命、溜め演出、当たり判定と炎上時間は維持。
追加のユーザー指定: 消えるまでの時間も粒ごとにランダムとし、見た目より当たり判定が狭くてもよい。
主炎0.45〜2秒、先端の炎0.35〜1.45秒、火の粉0.5〜2秒という既存のばらつきを維持し、
新しい速度用乱数と寿命用乱数を独立させる。当たり判定は30マスの円錐のまま。
以下に残る一律120マス／秒の記録は、この調整前のもの。

### 最新調整: 止まらない放射と5秒の炎上

- ユーザーが炎の広がりを確認。途中停止が不自然なため、主炎・先端の炎・火の粉はすべて
  発射点から120マス／秒で直進し、寿命が尽きるまで止まらない。距離による位置の上限を外す。
  最大約2秒のランダムな寿命・消え方は維持する。見た目は最大約240マスまで広がりうる。
- 当たり判定は射程30マス・全角100度の円錐に維持する。見た目が当たりより広いことはユーザー了承済み。
- 命中した生存プレイヤーへ5秒の炎上を付ける。`sweep.igniteSeconds: 5` を妖狐だけに指定し、
  単発のダメージ後に `setOnFire(5, true)` を1回呼ぶ。範囲外・別ディメンション・クリエイティブ・観戦者は対象外。
- 燃焼ダメージは既存の `events/hurt.ts` / spec/17-state.md 3-7へ通す。別の継続ダメージ時計は追加しない。
  水・雨・耐火などはバニラの炎上条件に従う。
- プレビューに広域表示を加え、0.5秒以降も止まらず移動することを確認する。

### 2026-09-10 追加調整（以下の旧数値より優先）

最新の数値検査では、発射後0.05秒で6マス、0.10秒で12マス、0.25秒で30マスへ到達。
1.5秒後に207粒、1.95秒後に13粒、2.01秒後に0粒になった（固定乱数の確認用描画）。
体を囲う青紫の溜め炎と、発射直後の広がりを実データの画像で確認済み。

- 攻撃開始距離を30マスへ延長。遠くから開始しても届くよう、炎と当たりの射程も30マスへそろえる。
- 移動速度は0.5から1.0へ変更。通常の接近先9〜10マス、溜め中の静止と追尾、3秒の溜めと呪い短縮は継続。
- 溜め中は手元に加え、胴体の周囲を青紫の炎が螺旋状に巡る。体周りの半径約0.65〜0.85マス、足元から頭付近まで。
- 発射の粒は発射点から120マス／秒で進み、最遠30マスへ約0.25秒で到達する。
  最初から円錐全域へ置く方式をやめ、各粒が円錐内部の別々の距離で止まって燃える。
- 主炎と火の粉は寿命を最大2秒まで個別に乱数化し、サイズ・透明度も寿命に応じて消える。
  一斉に消えないようにする。先端の炎も寿命を乱数化する。
- 当たりは従来どおり発射時の一撃。残留する炎は演出であり、持続ダメージを追加しない。
- プレビューは0〜5.2秒、発射直後は0.05秒刻みで観察できるようにする。射程30マスに合わせてカメラも拡張。
- 追加指定の炎音: 溜め中は `fire.fire` を0.6秒間隔で小さく鳴らす。発射時は `fire.ignite` と
  `mob.ghast.fireball` を発射点から鳴らす。30マス以内の同じディメンションのプレイヤーへ、発射音は音量2.0で再生する。
- 速度1.0はこのワールドの速度単位。BPの `minecraft:movement` は共通係数0.2875を掛け、属性上限は既存の7倍を保つ。

- プレイヤーとの距離がおよそ10マスになるまで近づく。通常の移動先は9〜10マス。
- 10.5マス以内で溜め開始。3秒（60 tick）静止し、狙ったプレイヤーの方を見続ける。
- 溜め完了時の正面を軸に、射程15マス・全角100度（軸から上下左右50度）の立体的な円錐へ炎を1撃だけ放つ。
  炎の残像に持続ダメージはない。基本攻撃力30・押す強さ2は維持。近接攻撃はしない。
- 呪いの攻撃間隔倍率を溜め時間にも掛ける。2倍速なら30 tick。
  発射後は通常10 tickの戻り動作（同じ倍率で短縮）を挟んで次の溜めへ。
  最短はどちらも2 tick。振る舞い更新は既存の2 tick周期。
- 溜め中に相手が射程外へ逃げても溜め切って発射し、射程外の人には当てない。
  相手が死亡・退出・別ディメンションへ移動した場合だけ、射程内の別の有効な人へ狙いを変える。
  代わりがいないときは最後の向きへ放つ。

## 当たり・移動・演出

2026-09-10 追加指定: 水平の扇形に高さをばらつかせる方式から、三次元の放射へ修正する。
当たりは発射点（足元+1.3マス）から標的の胴体（足元+1.0マス）までの三次元距離と、
照準方向との三次元の内積で判断する。距離15マス以内、軸との角度50度以内。
溜め中の照準は標的の上下移動にも追従し、従来の高さ2.5マスの固定制限は用いない。
他の敵の水平扇形・全周攻撃は従来どおり。
同じディメンションの生存プレイヤーだけを1回処理する。クリエイティブと観戦者には当てない。
障害物の扱いは従来の `sweep` と同じ。

歩行AIは `pve_v3:fox_walk` 部品群へ分け、溜め・発射中だけ外す。
移動速度の値を0へ書き換えないため、呪いの移動速度補正を復元する必要がない。
溜め開始時のXZへ固定しつつ、Y座標は現在値を保つ（落下を宙で止めない）。
初回更新や再読み込み時には姿勢と歩行群を初期化し、途中状態に固着させない。
死亡・消滅・アンロードした個体の時計は掃除する。

模型・耳・三尾・指定テクスチャは継続使用。両腕を前へ集めて溜め、発射で前方へ押し出す。
尾の既存アニメーションを残し、旧回転斬りのアニメーション配線だけを狐火の姿勢へ置き換える。
姿勢の通知は既存実績のある `minecraft:mark_variant`（0=通常、1=溜め、2=発射）を使う。
溜めの進行は同期整数プロパティ `pve_v3:fox_charge`（0〜100）でアニメーションの時刻へ渡し、
呪いで短縮された場合も両腕の溜め動作が同じ割合で進む。

炎の原形は公式同梱 `bedrock-samples/resource_pack/particles/basic_flame.json` の
8×8 UV（`textures/particle/particles.png` の [0,24]）を使う。
ユーザー指定の色調変換として、画素配置・透明度・明暗を保って青／紫へ色相を変え、専用PNGへ保存。
新しい炎の形を画像生成せず、PowerShell/System.Drawingで決定的に変換する。
追加のユーザー希望として、バニラ以外の粒も併用し、派手な演出へ広げる。
溜めには青紫の渦と光球、発射には閃光・長い火の粉を重ねる。
これらの形はパック内の既存の光球・火花テクスチャを使い、新しい粒の動きと組み合わせる。
溜め中は手元に小さな青紫の炎、発射時は前方の円錐の内部へ大きい炎が一斉に現れて消える。
発射は主炎2個（青240粒＋紫240粒）、外へ広がる炎84粒、火の粉96粒、閃光1粒の計5エミッター。
極角のcosを均等、軸周りの角度を0〜360度、半径を乱数の立方根で分布させ、体積を一様に埋める。
外へ広がる炎は同じ立体方向に移動し、球面で切った円錐の先端へ届く。
Molangへ渡す前・右・上の直交基底、射程・角度を当たり判定と共用する。
