# 企画: AI 建築当てゲーム

**2026-09-21 決定。** 同日に 2 回改訂（[decisions/01](decisions/01-use-existing-3d-model.md)・[decisions/02](decisions/02-no-setter-fixed-words-live.md)）。

> ### 出題者は要らない（2026-09-21 仕様変更）
>
> 最初は「参加者から 1 人が文章を送り、AI が建てる」だったが、**出題者を無くした。**
> **お題はこちらで固めた単語リストから、システムがランダムに選ぶ。** 全員が当てる側。
> 理由は [decisions/02](decisions/02-no-setter-fixed-words-live.md)。

## 1. 何を遊ぶのか

**システムが単語を 1 つ選び、AI がその場で建てる。全員で、置き終わってから 30 秒以内に当てる。**

```
ラウンド開始
   │
   ▼
単語リストから 1 語 ──→ AI が画像 → 3D → ブロック（約 3 秒。毎回その場で生成）
                                          │
                                          ▼
                        下から N 個/tick で「ポポポポ」と置いていく
                                          │
                                          ▼
                        置き終わり → 30 秒以内にチャットで当てる → 正解発表 → 次のラウンド
```

| | |
| --- | --- |
| **出題** | **システム**。固定リスト（[docs/spec/12-words.md](spec/12-words.md)）からランダム |
| **建築** | AI がその場で生成。**事前生成はしない**（見せ物として「その場で作られる」ことが要る） |
| **当てる人** | **全員** |
| **当たり** | 置き終わってから **30 秒以内**に、チャットで正解（表記ゆれ込み）を言う。**10 秒経ったらカテゴリ（動物・乗り物…）をヒントに出す** |

## 2. 建築ができるまで（4 段）

**単語 → 画像 → 3D → ブロック**。[docs/spec/08-genlab.md](../../../docs/spec/08-genlab.md) で作って確かめた構成。

| # | 段 | 何をするか | AI を使うか | 実測 |
| --- | --- | --- | --- | --- |
| 0 | 単語 | リストから 1 語。**生成に渡す英語は、翻訳ではなく人が書いた裏プロンプト**（`en` 列。「スティーブ」→ `Minecraft Steve`、「毒キノコ」→ `red fly agaric mushroom`）。実行時に言語モデルは使わない | — | 0 秒 |
| 1 | 画像 | 単語 → 1 枚の絵（sd-turbo, 4 step） | **使う** | 0.2〜0.7 秒 |
| 2 | 3D | 絵 → 立体の格子（**Hunyuan3D-2mini turbo**）。色は絵を投影 | **使う** | 2.6 秒 |
| 3 | ブロック | 格子 → 羊毛・コンクリート・テラコッタ（**固定ルール**） | **使わない** | 0.05 秒 |

> ### 3 段目に AI を使わない理由
>
> **同じモデルなら同じブロックになる**ようにするため。置き換えルールが揺れると、出来上がりの質を追えなくなる。

> ### 2 段目の AI は自作しない。既存のものを使う（[decisions/01](decisions/01-use-existing-3d-model.md)）
>
> **形の精度は要らない**（ブロックに潰すので細部は消える）。**単語の読み取りは正しく**（人が書いた裏プロンプトで固定する）。

> ### 裏プロンプトは人が書く。画像モデルが知らない物は落とす（2026-09-21・本人）
>
> 「単語だけ」では絵にならない語がある（スティーブ → マインクラフトの、という文脈が要る）。
> **固定リストの語は、文脈と見た目の特徴を `en` に書き込んでおく**ので、実行時に言語理解モデルを通す必要は無い。
> 画像モデルがその物を知らなければ生成は失敗する。**そういう語は直さず、リストから外す。**
> **裏モード（自由入力）だけは言語理解モデルでプロンプトを組む**（後回し。仕様変更として記録）。

## 3. 大きさと時間

| | 決まり |
| --- | --- |
| **大きさ** | **60 × 60 × 60 の箱。(0, 0, 0) を中心**（本人の定義、2026-09-21）。最初は 20³ だったが 40³ で「象が象に見える」ので大きくした。実装は定数 |
| **生成にかかる時間** | **約 3 秒**（[research/29 7-5](../../../docs/research/29-text-to-blocks-feasibility.md)）。予算の 10 秒に対して余裕 |
| **回答の制限時間** | **置き終わってから 30 秒** |

## 4. 演出

**クローンで一発で出さない。下の方から 1 tick に N 個ずつ「ポポポポ」と置いていく。**

- 置いている間も見える（当てる側は、途中から考え始められる）
- 「置き終わり」がはっきり分かる必要がある（30 秒はそこから数える）
- 60³ は最大 21.6 万個（40³ の実測は象で 1 万、家で 2 万。60³ はその 3.4 倍）。**N は仕様で決める**（[spec/14-build.md](spec/14-build.md)）

## 5. 技術（決定済み）

| 段 | どうやるか | 確度 |
| --- | --- | --- |
| 実行基盤 | **BDS なし。通常ワールド（クライアントホスト）**。ホストの PC で生成サーバーと `wsbridge` も動かす | 決定（[research/29 6 章](../../../docs/research/29-text-to-blocks-feasibility.md)） |
| 外との口 | ホストが `/wsserver` で `tools/wsbridge` に繋ぐ。ブロックは `/scriptevent`（2,048 文字 × N 回）で BP へ | `/scriptevent` は公式仕様。**wsbridge → scriptevent の疎通は最初に確かめる** |
| 生成 | `tools/genlab` のサーバー（Python）。**1 語 3 秒・VRAM は Minecraft 込み 8.7 GB** | 実測済み |
| 置く | BP スクリプトが `setBlockType` を輪 1 本の中で毎 tick N 個 | 実績あり（pve-v3 の組み立て係） |
| 答え合わせ | BP がチャットを読み、リストの正解・表記ゆれと照合 | 実績あり（`chatSend`） |

**出題者が居ないので、「文章を外に出す口」（research/29 6-4）は要らなくなった。** 単語は wsbridge 側が選び、BP へ渡すだけ。

制約として覚えておくこと:

- **ゲーム中は LLM チャット（`tools/bots`）を止める。** 同じ GPU を取り合う
- **生成サーバーと Minecraft を同じ GPU で動かす。** VRAM 12 GB のうち 8.7 GB。他の GPU を使うものを同時に動かさない（溢れると 1 語 100 秒になる）
- Hunyuan3D は**非商用ライセンス**（Tencent Hunyuan Community License）

## 6. 決まったこと・まだ決めていないこと

**本人の定義（2026-09-21）で決まったもの:**

| | |
| --- | --- |
| **状態** | 4 つ: 開始していない / ゲーム中 / 出題中 / 生成中（[spec/11-flow.md](spec/11-flow.md)） |
| **開始・停止** | アドミンが手動（`/quiz:start` `/quiz:stop`）。開始したら「生成 → 回答」を**止めるまで繰り返す** |

| **場所** | 60³ を原点中心。行動範囲 200×200。**常に飛べる（サバイバル）**（[spec/16-world-rules.md](spec/16-world-rules.md)） |
| **境界** | Core Wars の境界をそのまま |
