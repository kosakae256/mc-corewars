# 仕様 11: 進行

> 作成日: 2026-09-21 / 企画: [../00-concept.md](../00-concept.md)
> 状態の 4 つと遷移は**本人の定義**（同日）。時間は仮で、定数にして遊んでから変える。

## 1. 状態は 4 つ（BP が持つ。ワールド 1 つ）

| 状態 | 意味 | scoreboard `quiz` の `phase` |
| --- | --- | --- |
| **`idle`** | ゲームを開始していない | 8 |
| **`game`** | ゲームを開始している（下の 2 つの親。**`generating` ⇄ `quizzing` を繰り返す**） | — |
| **`generating`** | 生成中。bridge が genlab に頼み、BP が受け取り、下から置いている | 0（お題待ち）→ 1（置いている）。**出題モードでは 0（出題者待ち）→ 4（お題あり）→ 1**（[17-modes](17-modes.md)） |
| **`quizzing`** | クイズを出題している。30 秒の回答 → 発表 | 2（回答中）→ 3（発表） |

```
idle ──アドミンが /quiz:start──▶ generating ──置き終わり──▶ quizzing ──発表が終わった──▶ generating ──▶ …
 ▲                                                                                       │
 └──────────────────────── アドミンが /quiz:stop（いつでも。置きかけは片づける） ◀────────┘
```

- **開始の演出**: `/quiz:start` で全員に title「§a§lAI 建築当てゲーム」＋ subtitle「はじまり！」、`random.explode`（爆発の音）を鳴らす（本人・2026-09-21「始まったことが伝わる演出」。最初は `raid.horn` だったが「うるさすぎる」→ 爆発の音に）
- **開始は手動。** アドミン（オペレーター）が **`/quiz:start`**（カスタムコマンド。`CustomCommandPermissionLevel.Admin`）。ワールドを作ったら最初に一度 **`/quiz:ring`**（観覧の輪。[16-world-rules 1 章](16-world-rules.md)）
- **bridge が繋がっていなければ始めない**（本人・2026-09-21）。bridge の `quiz:ping`（[13-transport](13-transport.md)）を **5 秒以内**に受けていないときは `/quiz:start` を失敗にし、**発行者にだけ**繋ぎ方を返す:
  「bridge が繋がっていません。1) PC で `worlds/ai-build-quiz/bridge` → `npm start`  2) このチャットで `/wsserver ws://127.0.0.1:8766`  3) もう一度 `/quiz:start`」
  （コマンドの結果メッセージは発行者にしか見えない）
- 開始したら**「生成 → 回答 → 生成 → 回答」を自動で繰り返す。問数の上限は無い**
- **止めるのも手動。** `/quiz:stop` で `idle` へ戻る。それまでループし続ける
- bridge は **`phase` が 0 のときだけ**次のお題を作って送る（[13-transport.md](13-transport.md)）。**アドミンの操作は BP だけで完結**し、bridge はそれを scoreboard で知る

## 2. 時間

| --- | --- | --- |
| 生成の待ち | 約 3 秒（genlab） | 「AI が考え中…」を出して見せる。**隠さない**（見せ物） |

| 発表 | 5 秒 | 正解・正解者を title で出す |
| 1 ラウンド | 約 50 秒 | |

### 3-1. ヒント（本人の案、2026-09-21。2 段目は同日の追加指示）

| いつ | 何を | 例 |
| --- | --- | --- |
| **お題が届いた時点**（置き始める前。本人・2026-09-21「生成時点で伝える」） | **カテゴリ**（単語の `kind`）。**ヒントではなく前提**なので、回答中の actionbar にも出しっぱなし | 「§e第 3 問 §fカテゴリ「キャラクター」」 |
| 回答開始 **10 秒**後 | **ジャンル**（単語の `hint` 列。カテゴリより一段細かい） | 「§eヒント: §fジャンルは「マイクラのキャラ」」 |

ジャンルの粒度は [12-words.md 4-1](12-words.md)。**「細かすぎてバレる」を避ける**ため、ジャンル 1 つにつきリストの語が 3 つ以上あるものだけ使い、足りなければ広いジャンルに寄せる。
**ジャンル名にその語の正解（別名を含む。「木」のような 1 文字も）が含まれてはいけない**（「キャンディ」に「お菓子・キャンディ」と出ていた——本人。`npm run words` がエラーにするので、リスト側でジャンル名を付け替える）。
**ジャンル名そのものを答えても当たらない**（りんごの木に「木」は不正解。上位語は受けない——[12-words.md 2-3](12-words.md)）。
文字数・頭文字のヒントは出さない（それは答えそのもの）。

## 4. 得点

**当てた人に 1 点**（本人の定義。「裏で適当に 1 ポイント」）。早い者勝ちなら最初の 1 人だけ。**対戦 × 全員回答は、当てた時点の残り秒数が点**（本人・2026-09-21。[17-modes.md 1-1](17-modes.md)）。**置いている途中に当てたら 2 倍**（早い者勝ちは +2、全員回答は制限時間 × 2 ＝ 60 点）。

- scoreboard 目標 `quiz_score`（対戦モードだけ。**サイドバーには出さない**——サイドバーは現在のルール。[17-modes.md 6 章](17-modes.md)）。累計 `quiz_total` は tab とランキング板（[17-modes.md 7 章](17-modes.md)）
- **誰かが当てたら（全員回答なら全員が当てたら）30 秒を待たずに発表へ**（置いている途中なら、置き終わってから）
- 誰も当てられなければ 0 点。発表で正解だけ出す
- `/quiz:start` で得点を消す（ゲーム単位）。途中参加は 0 点から
