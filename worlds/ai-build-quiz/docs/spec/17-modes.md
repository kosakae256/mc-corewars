# 仕様 17: ゲームモードと運営のコンパス

> 作成日: 2026-09-21 / 本人の定義（同日）をそのまま仕様にした。
> 「フリー・対戦・出題」の 3 モード。運営はコンパスの UI で切り替える。

## 1. モード

| モード | 何をする | 得点 | お題 |
| --- | --- | --- | --- |
| **フリー** | 今までの遊び方。始めたら「生成 → 回答」をずっと繰り返す | 付けない（累計だけ増える） | 単語リストからランダム |
| **対戦** | **N 問**で何回当てたかを競う（N は運営がコンパスで**任意の数**を決める。既定 10。本人・2026-09-21） | **対戦スコア**（そのゲームの正解数）。正解のたびにチャットで「◯◯ 正解！（3 点）」、**N 問目の発表のあとに結果**（title「優勝: ◯◯」＋ チャットに順位表）→ 自動で止まる | 単語リストからランダム |
| **出題** | プレイヤーがお題を決める | 付けない（累計だけ増える） | **ボタンを押した人**が UI で書き、**キュー**に入る（3 章） |

- **累計**（`quiz_total`）: モードに関係なく、当てるたびに +1。**消さない**（ワールドに残る）。tab（list）に常に出し、**ランキング板**（7 章）に上位 10 人を出す
- **対戦スコア**（`quiz_score`）: 対戦モードを**始めるたびに 0**。**サイドバーには出さない**（サイドバーは「現在のルール」——6 章。本人・2026-09-21「右のスコアボードは不要」→「現在のルールを書いておいて」）。見せ方は上の表
- **対戦の問数**（`rounds`）: 運営がコンパスで決める（1 以上の整数。上限なし）。ワールドに残る。ゲームの途中で変えても、いまのゲームには効かない（次から）
- モードは `/quiz:start` の前にコンパスで選ぶ。**ゲーム中にモードを変えると、いま出ている問題が終わってから**新しいモードになる
- 状態（モード・固定カテゴリ・対戦の問数・回答のルール・生成モデル）は scoreboard `quiz` の偽プレイヤー `mode` `kind` `rounds` `rule` `gen` に持つ（ワールドに残る。bridge は `mode` `kind` を読む——[13-transport](13-transport.md)）

### 1-1. 回答のルール（早い者勝ち／全員回答。本人・2026-09-21）

モードとは別に、**回答のルール**をコンパスで切り替える（scoreboard `quiz` の偽プレイヤー `rule`。0 早い者勝ち / 1 全員回答。ワールドに残る。既定は早い者勝ち）。どのモードにも効く。

| | **早い者勝ち**（既定） | **全員回答** |
| --- | --- | --- |
| 正解 | **最初に当てた 1 人だけ** | **当てた人みんな**（1 人 1 回） |
| 発表へ | 誰かが当てたらすぐ（置いている途中なら置き終わってから） | **答えられる人が全員当てたら**すぐ。それまでは制限時間まで |
| 正解の発言 | **そのまま全員に見える**（決まった後なので） | **他の人には打ち消す**（答えが見えない）。本人には自分の発言をそのまま見せ、直後に「正解！」 |
| 正解した人のその後の発言 | **「[正解者] 名前: …」で正解者同士と出題者にだけ**（判定しない） | 同じ。まだ当てていない人には見えないので答えは漏れない（「もう正解しています」は出さない——本人） |
| 対戦の得点 | 最初の 1 人に +1。**置いている途中に当てたら 2 倍（+2）** | **当てた時点の残り秒数**（本人・2026-09-21「残り時間がスコア」。早く当てるほど多い。最低 1）。**置いている途中に当てたら制限時間の 2 倍**（30 秒なら 60 点。本人「建てられてる途中に答えたらスコア 2 倍」） |

## 2. カテゴリの固定（フリー・対戦）

コンパスの UI で **カテゴリを 1 つに固定**できる（動物だけ、キャラクターだけ …）。既定は「すべて」。
bridge は `kind` を読み、固定されていればそのカテゴリの語からだけ引く。出題モードには関係ない。

## 3. 出題モード（キュー方式。2026-09-22 に抽選方式から変更）

> 本人・2026-09-22: 「ゲーム終了後に入力して生成する流れだと入力時間が無駄。**ボタンを押したら出題を設定でき、複数人で一斉に入力できるキュー方式**に。
> 時間制限は無くす。生成はリアルタイムで。**リロードしてもキューが消えないように。ワールドから抜けたらその人の分はキューから消す。** 順番はプロンプトを確定した順。`/reload all` はしない」

```
誰でも・いつでも（ゲーム中でも）: 石のボタンを押す
  │ **選ぶ**（ActionForm）: 「お題を出す」／「自分の出題を取り消す」／「やめる」（本人・2026-09-22「ボタン押したときに選択式」）
  │ 「お題を出す」→ UI（お題・詳細。CustomForm。時間制限なし。閉じたら何も起きない）
  ▼
「出題する」→ キューの末尾に入る（確定した順）。板に名前が並ぶ（お題は出さない）
  │ BP は先頭が変わるたびに scoreboard `quiz_topic` に先頭を書く（0:<id> 1:<お題> 2..:<詳細片>）
  ▼
bridge: 待ち（phase 0）で先頭があれば生成して送る。**ゲーム中（phase 1〜3）に先頭を見たら先読みして生成し、保持**（リアルタイム）
  ▼
go: BP は header の topicId の件をキューから外し、その人を出題者に → building → answering → reveal → 待ち（次の先頭へ）
```

| | |
| --- | --- |
| **押す物** | **`minecraft:stone_button` だけ**（どこに置いてもよい。運営が観覧の輪の近くに置く。コマンドブロックは要らない——本人・2026-09-22。コマンドブロックを拾うと出題モード中に運営が編集できなくなる）。`playerInteractWithBlock`（before）で拾い、押した本人に UI を出す。**`/reload` だけで効く**（manifest を触らない。本人「reload all はしたくない」） |
| **キュー** | 確定した順（FIFO）。**1 人 1 件まで**（本人・2026-09-22。2 件目は「あなたの出題はもうキューにあります」）。**ワールドの dynamic property に保存**（`quiz:queue`＝id の並び、`quiz:queue:<id>`＝1 件の JSON。`/reload` で消えない。本人）。**抜けた人の分は消す**（`playerLeave`。本人）。運営はコンパス「出題キューを空にする」で全部消せる。**受付の停止**: コンパス「出題の受付を止める／再開する」（本人・2026-09-22）。止めている間はボタンを押しても「いまは出題を受け付けていません」で UI を出さない（既に入っている分はそのまま進む）。板の見出しの下に「§c受付停止中」、ルール欄も「出題の受付は停止中」。dynamic property `quiz:queue:open`（`/reload` で消えない） |
| **板** | **(0, 2, 68)、−z（中心）向き**（本人・2026-09-22）。ランキング板と同じ `DebugText`。「§6§l出題キュー」＋ 1 行 1 件「§e1. §f名前」（**お題は出さない**）。空なら「（空）ボタンを押して出題」。出題モードのときだけ出す |
| **案内** | **(-18, 3, 66)、−z（中心）向き**の空中の文字「お題はボタンから出せます」（本人・2026-09-22。ボタンの近く）。受付を止めていれば「出題の受付は停止中」。出題モードのときだけ出す |
| **時間制限** | **無し**（3 分の放置対策・確認・テレポートは廃止。キューなので他の人を待たせない） |
| **出題者に自分のお題を見せる** | **出題が始まったとき（go）に本人にだけチャットで「あなたのお題: ◯◯」**、さらに**その回の間ずっと本人の actionbar にお題を出す**（本人・2026-09-22「自分の入れたお題が分からなくなる」。キューに並んでいる間に忘れる・チャットが流れる）。他の人には見えない |
| **出題者** | その件を入れた人。go の時点で決まる（`Round.setterId`）。答えられない・`[出題者]` チャット・発表に名前、は前のまま。抜けた人の件は消えるので、抜けた人が出題者になることは無い（生成中に抜けたら、その回は出題者なしで進める） |
| **生成に失敗したら** | bridge は**同じ件を 30 秒は作り直さない**（毎秒 genlab を叩いて詰まっていた。2026-09-22）。その間 actionbar は「お題の生成に失敗しました…」。直らなければ運営が「出題キューを空にする」 |
| **先読み** | bridge は phase 1〜3 の間も `quiz_topic` を読み、未生成の id なら**裏で生成して保持**。待ちになったとき先頭の id と一致すれば即送る（生成待ちゼロ）。一致しなければ捨てて作り直す。genlab は 1 件ずつなので、先読みは 1 件 |
| **空のとき** | 待ちのまま。actionbar「出題を待っています — ボタンを押すと出題できます」 |
| **廃止したもの** | 抽選の場（4 か所の円・案内文字・ダイヤ）、CD、指名、やめますか確認、3 分、(61,1,10) へのテレポート、phase 4（`topic`）。2026-09-22 |
| **下ネタ** | お題・詳細に下ネタが入っていたらキューに入れない（赤字で打ち直し。[18-moderation.md](18-moderation.md)） |
| **選択** | ボタンを押すと**まず選ぶ**（`ActionFormData`）。上に自分の状態（「キュー 3 件中 2 番目」「お題: ◯◯」／「出していません」）。ボタンは **「お題を出す」**（もう出していれば押しても「もうキューにあります」）・**「自分の出題を取り消す」**（出していれば）・「やめる」 |
| **取り消し** | **自分の 1 件だけ**外せる（運営以外は他人の分を触れない）。外すと全員に「◯◯ さんが出題を取り消しました」。**先頭を外したら次の件が先頭**になり、bridge の先読みは id が違うので捨てられる。**生成中に外した場合はその回だけ出題者なしで進む**（絵と答えは出来ているので流す。2026-09-22） |
| UI | **`CustomForm`**: 上にチャットの最新 8 行（開いている間も更新）、「お題」（**ひらがなと数字のみ**・必須・20 文字まで。ラベルに「ひらがな・数字のみ」）、「詳細」（任意・3000 文字まで。**英語推奨**。画像モデルが読むのは先頭 77 トークン ≒ 英語 50〜60 語）、ボタン「出題する」「やめる」。ひらがな・数字以外・空で「出題する」→ 閉じずに赤字で打ち直し |
| BP → bridge | scoreboard `quiz_topic` の偽プレイヤー名: `0:<id>`、`1:<お題>`、`2:` `3:` … に詳細を 50 文字ずつ（最大 60 個）。**先頭が変わるたび**（追加・go・抜けた・空にした）に書き直す。空なら全部消す |
| **お題の解釈 → 生成用プロンプト** | **既定は言語モデルを使わない**（`config.json` の `llmEnabled: false`。本人・2026-09-22「やたらと狐が出てくる」——1.5b が知らない言葉に例の fox を当てはめていた）: **まず単語リスト**（787 語の検証済み裏プロンプト。読み・別名で引く。かーびぃ → "Kirby, pink round…"、定型もそのカテゴリのもの。2026-09-22）、次に辞書（JMdict）に載っていれば辞書の英語（きつね → fox）、次に **Wikipedia の対訳**（[08-genlab 2-0b](../../../../docs/spec/08-genlab.md)。ジバニャン → Jibanyan、アルセウス → Arceus）、無ければ **ヘボン式ローマ字（長音潰し・頭文字大文字）**（じばにゃん → Jibanyan、ととろ → Totoro。本人・2026-09-22「ローマ字でいい」。機械翻訳の音写は "Zivagnan" のように崩れる。外来語由来の名前——あるせうす → Aruseusu、正しくは Arceus——は当たらない）。画像モデルが名前を知っていればワンチャン。**画像モデル（SDXL 含む）は日本語を読めない**（英語の説明文で学習。日本語はバイト片に砕けて意味を持たない）ので、日本語のまま渡す手は無い。日本語対応の SDXL 派生（Japanese Stable Diffusion XL 等）は別モデル・別途 7 GB なので今は入れない。**定型（style）は「どの経路で英語にしたか」ではなく、英語の中身で決める**（本人・2026-09-22「a toy figurine of a って毎回ついてる？物体がちょっとむずかしくなってるかも」）: 生き物・キャラを指す語（girl / boy / character / robot / monster / cat …）があれば `creature`、食べ物なら `food`、植物なら `plant`、乗り物・建物・道具などの語があれば `object`、どれでもなければ `auto`（genlab が WordNet で決める）。**`creature` の定型は「a toy figurine of a ◯◯」で、物に付けると主語を乗っ取る**（本 → ロボットのおもちゃ、剣 → 騎士。[08-genlab 2-0](../../../../docs/spec/08-genlab.md)）ので、**英語の詳細だけで描くときも、辞書に無い名前のときも、中身を見て選ぶ**（前は一律 `creature` だった）。**手がかりがどこにも無ければ今まで通り `creature`**（詳細が無い名前——ジバニャン等）——中立の定型だと顔のアップやグリッドになった（かーびぃ・2026-09-22）。**詳細は主語と別に genlab へ渡し、別々に機械翻訳**して繋ぐ（まとめると壊れる。英語ならそのまま通る）。**詳細が英語で、お題が単語リストにも辞書にも無い**とき、または**英語の詳細が girl / boy / character / anime / robot / monster 等を含む**（＝キャラを描いている。「ふぇねっく」を辞書が fennec fox にしても捨てる）ときは、主語を捨てて**詳細だけ**を描く（`Kabi, Kirby pink…` より `Kirby pink…` のほうが通る。定型は生き物）。**辞書にある語なのに詳細が人・キャラを指す言葉（少年・キャラクター・ロボット …。1 文字の「人」「犬」は数えない）を含んでいたら、作品名の同音異義とみなして辞書を使わず、詳細だけを描く**（「わんぴーす（麦わら帽子をかぶった少年）」が辞書で dress になった・2026-09-22。詳細 → "a boy wearing a straw hat"、定型は creature）。「ひこうき（飛んでいる人工物）」で「人」に当たって airplane を捨てた事故（2026-09-22）を受けて、1 文字語は外し、辞書に無い語では名前（ローマ字）＋詳細のまま。取り違えは起きないが、似た物との区別は出題者が詳細に書く。**注意: 機械翻訳（Marian）も小さい言語モデルも、ひらがなだけの文は苦手**（「きいろとしろ」→ "Stay with me."、「黄色と白」→ "Yellow and White"）。詳細は漢字・カタカナ交じりで書いてもらう（UI にそう書く）。**`llmEnabled: true` にすると以下**: 言語モデルだけで作る（本人・2026-09-22「LLM 解釈だけで良い。思考コスト高くてもいいので、しっかりしたプロンプトを」）。Ollama の **`qwen2.5:1.5b`**（1 GB・0.2 秒。`qwen3.5:9b` は精度は上だが 6.6 GB で genlab と GPU を取り合い「重すぎる」——本人・2026-09-22。使うなら `config.json` の `llmModel`。**思考モードは切る**——`think: true` だと JSON が空で返る）。日本語の指示で `{ subject: 正式な英語名, en: 12 語以内の名詞句（対象名 ＋ 見た目の決定的な特徴をカンマ区切り。**定義文・説明文は不可**）, style, confusable }` を JSON で返させる（例を 3 つ添える）。**長文は逆効果**: genlab の定型が `{x}` を包み、画像モデル（CLIP）は 77 トークンで切れるので、「Slime is a slimy, gelatinous substance…」のような説明文だと定型の後半が消える（2026-09-22 に発覚）。18 語を超えて返ってきたら bridge が 12 語に詰める。**辞書の英語がどれも描写に入っていなければ、言語モデルが名詞を取り違えたとみなして辞書の英語を使う**（1.5b が「どらえもん」を donut にした・2026-09-22）。**辞書に無く、言語モデルも「知らない」（`known: false`）と言った言葉は、詳細の見た目だけで描く**（「あるせうす（きいろとしろ）」を fox と当てはめていた——本人・2026-09-22）。
**限界**: 画像モデル（sd-turbo）が知らない物は、どんなプロンプトでも絵にならない（マイナーなキャラ・新しい物）。出題者が**詳細に見た目を書く**のが唯一の手で、UI にそう案内する。日本のゲーム・アニメで有名な意味があれば優先（すらいむ＝ドラクエのモンスター）。**お題の意味を取り違えないこと**（きつね＝fox であって cat ではない）、**詳細はお題の意味を上書きしない**、をルールとして書く。和英辞書（JMdict）に載っていれば「辞書では せんしゃ = tank」と**ヒントとして添える**（これで 1.5b でも きつね → fox、せんしゃ → tank になる。ヒント無しだと 9b でも「せんしゃ」を wheelchair と読んだ）。genlab の `/build` は 200 文字までなので、それを超えたら語の切れ目で切る。言語モデルが落ちていればお題をそのまま genlab へ（辞書＋機械翻訳） |
| 正解の条件 | **発言にお題が入っていれば正解**（本人・2026-09-23「はるくだああああ → はるく が答え、ということが起こるので、そういう回答は答えとする」）。発言は**ひらがな（数字可）だけ**（カタカナ・漢字・ローマ字は不正解。本人・2026-09-22。全角数字は半角に揃える）。語尾「かな」「です」は落とす。**お題が 1 文字のときは完全一致だけ**（どんな発言にも当たってしまうため）。**逆向き（お題が発言を含む）は不正解**（「きつ」で「きつね」は当たらない）。打ち間違い・別名・英語は無し（「解釈は必要ない」——本人） |
| 出題者の発言 | **判定しない**（答えられない・得点も無し）。ただし**お題そのものを言ったら流さない**（本人・2026-09-23「口を滑らしたときはチャットされないように。回答一致の条件判定と一緒でいい」）: **正解の判定（`isExact`）と同じ条件**で見て、当たったら `ev.cancel` のまま誰にも見せず、本人にだけ「お題そのものは言えません」。部分一致も同じ（「はるくだよ」もお題「はるく」に当たるので流さない）。発表（`reveal`）に入ってからは答えが公開済みなので止めない。当たらなければ **`§6[出題者] §f名前: 発言`** の形で全員に流す（本人・2026-09-21「ヒントみたいなのはそれでできるように」）。選ばれてから発表が終わるまで。同じ文の連投は 1 回だけ（[11-flow 3 章](11-flow.md)） |
| 回答時間 | **60 秒**（フリー・対戦は 30 秒。本人・2026-09-21）。ジャンルのヒントは無い（`hint` は空）ので、ヒントは出題者の発言で |
| 発表 | 「正解: ◯◯」に加えて「出題: ◯◯さん」、**お題と詳細、画像モデルに渡したプロンプト**（`quiz:prompt`。[13-transport 2 章](13-transport.md)）。お題が届いたときのカテゴリは「出題者のお題」 |

## 4. 運営のコンパス

| | |
| --- | --- |

## 8. 途中で抜けたとき（本人・2026-09-21「軽くでいい」）

**止めない・待たない・戻ってきたら続きから。** 状態は player.id と scoreboard に付いているので、抜けても消えない。

| 誰が・いつ | どうなる |
| --- | --- |
| 回答者が回答中に抜けた | 何もしない（早い者勝ちなので、居る人の誰かが当てるか時間切れで発表） |
| 回答者が戻ってきた | 正解済みなら正解済みのまま（id で覚えている）。対戦スコア・累計も残っている |
| 対戦中に抜けた | 対戦スコアは残り、**結果発表にも出る**（当てた分は当てた分）。戻れば続きから |
| キューに入れた人が抜けた | **その人の件をキューから消す**（本人・2026-09-22）。板からも消える |
| 出題者が（生成中・回答中に）抜けた | **そのまま進める**。ヒントは出ない。発表に「出題: ◯◯」は出る |
| 運営が抜けた | ゲームは進む（BP は運営に依らない）。戻ればコンパスを渡し直す |
| 誰も答えられない（出題者しか居ない） | 制限時間まで待って発表 |
| 誰か戻ってきた（参加時） | コンパス（運営）・飛行・羽をもう一度渡す（16-world-rules） |
