# 仕様: パックの作り

書き方の決まりは [docs/imp.md](../../../../docs/imp.md)（**10 章がこのワールドの形**）。
**ここには「このワールドで何をどこに置くか」だけ**を書く。

## 1. 置き場所

```
scripts/
  main.ts          FEATURES を回すだけ。**ロジックを置かない**
  features.ts      機能の一覧。**足すときはここに 1 行**
  loop.ts          輪は 1 本（imp.md 10-1）
  types.ts         Feature の型
  lib/             純粋な計算。**Minecraft API に触らない**
    charge.ts        ため → 倍率
    damage.ts        最終攻撃力 × (1 − 防御率)
    attack.ts        最終攻撃力の組み立て（10-damage.md 3-1）
  state/           保存と読み出し
    keys.ts          動的プロパティの鍵（imp.md 10-5）
    hp.ts            独自 HP
  events/          1 イベント 1 購読（imp.md 10-2）
    hurt.ts          バニラのダメージを打ち消す
  features/        振る舞い
    <機能>/index.ts  宣言だけ。50 行以内
```

**feature どうしは import しない**（imp.md 10-4）。
**共有したくなったら `state/` か `lib/` に置く。**

## 2. 増えるものを、どこで受けるか

**この 3 つは必ず増える。** 増えたときに**触る場所が 1 か所**であること。

| 増えるもの | 足す場所 | 触らない場所 |
| --- | --- | --- |
| **武器** | `features/<職業>/weapons.ts` の一覧 | 撃つ処理・ダメージ |
| **エンチャント** | `features/enchant/list.ts`（予定） | 武器・ダメージ |
| **属性** | `features/element/list.ts`（予定） | 武器・エンチャント |
| **職業** | `features/<職業>/` を 1 つ足す | 既存の職業 |
| **モブ** | `features/mob/list.ts` の一覧 | 湧かせる処理 |

### 2-1. 「一覧」と「処理」を分ける

**一覧はデータ。処理はコード。**

```
weapons.ts   ← 武器 50 種。**表を写しただけ**
shoot.ts     ← 撃つ処理。**武器の数を知らない**
```

**50 種のうち 49 種は、`weapons.ts` に 1 行足すだけで済む**ようにする。
**残り 1 種**（星が降る、など**新しい挙動**）だけが、処理を足す。

### 2-1-A. 武器は固有の音と絵を持つ（2026-08-29 決定）

> ### 武器を作るときは、**その武器だけの音と絵**を必ず 1 つずつ用意する。

| 何 | どこに書くか |
| --- | --- |
| **軌跡の音** | `features/<職業>/weapons.ts` の `trailSound`（**放つ音はバニラ共通**） |
| **飛んだ跡** | 同 `trail`（＋ `spark`） |
| **固有効果の音** | その効果の中（例: 星が落ちるたびの `pve.weapon.stardust_land`） |
| **固有効果の絵** | 同上（`features/bow/stardust.ts` の粒） |

**数字だけ違う武器を作らない**（[archer-weapons.md](../drafts/archer-weapons.md) 1 章）——
**音と絵が違えば、拾った瞬間に分かる。**

### 2-1-B. 属性の見せ方も武器の種類ごと

**属性の効き方は共通**（[17-element.md](17-element.md) 3 章）だが、
**見せ方は武器の種類で変わる。**

| | |
| --- | --- |
| いま在るもの | **弓の分だけ**（`features/element/looks.ts` の `bow`） |
| 増やすとき | **その種類の段を 1 つ足す**（剣・杖…） |

> 同じ火でも、**弓は矢が燃え、剣は刃が燃える。**
> **弓のいまの絵は「弓の分」であって、共通の絵ではない。**

### 2-2. 効果は「フック」で足す

**当たった後に起きること**は、ダメージの通り道に挿す
（[10-damage.md](10-damage.md) 4-1）。

| 挿すもの | 例 |
| --- | --- |
| 属性 | 火が付く・冷気が溜まる |
| エンチャント | 炸裂・連鎖・吸血 |
| 武器の固有効果 | 星が降る |

**挿す側は「削った値」と「誰が誰に」だけを受け取る。**
**どこから来た攻撃かを知らなくてよい。**

## 3. いま在るもの（2026-08-28）

| 機能 | 何をしているか |
| --- | --- |
| `vanilla` | **バニラのダメージを全部打ち消す。** 体力を満タンに保つ |
| `damage` | **削る 1 本道**（[10-damage.md](10-damage.md)） |
| `bow` | 弓を撃つ（ため → 線で当てる） |
| `mob` | ゾンビを湧かせる・殴らせる |
| `hud` | **自分の HP バー・モブの名札・ダメージ表記**（[15-hud.md](15-hud.md)） |
| `element` | **属性**（蓄積・効き方・粒。[17-element.md](17-element.md)） |
| `item` | **武器の名前と説明欄**（[18-item-view.md](18-item-view.md)） |

**まだ無いもの**——職業の切り替え・属性・エンチャント・ウェーブ・ショップ。

## 3-A. 絵と音は自分たちで作る（2026-08-28 決定）

**バニラのものを借りない。**

| | |
| --- | --- |
| アイコン | **描く**（`textures/items/pve_*.png`） |
| 粒 | **定義から書く**（`particles/*.json` ＋ `textures/particle/pve_*.png`）。**例外は下** |
| **字（アイコン）** | **描く**（`font/glyph_E2.png`。属性の印。[17-element.md](17-element.md) 5-1） |
| モデル | **作る**（いまはまだ無い） |

> **借りると、他の場面と同じ絵になって見分けが付かない。**
> 「拾った瞬間に分かる」ことが、この遊びの肝
>（[03-content.md](../03-content.md) の「絵で差を付ける」）。

**いま借りているもの**（**後で置き換える**）:

| | |
| --- | --- |
| モブの見た目 | **ゾンビ**（`runtime_identifier`）。「とりあえずゾンビでいい」ため |
| **炎の粒** | **バニラの `minecraft:basic_flame_particle`**（2026-08-29 決定）。**自分で描いた炎より炎に見えた**——揺らぎ・明滅・上昇が作り込まれている。**数と置き場所はこちらで決める** |
| 音 | **自分たちで合成する**（`tools/pve-sounds.py` → `sounds/pve/*.ogg`）。[16-feedback.md](16-feedback.md) 3-1 |
| 殴られた音 | **バニラを借りている**（`game.player.hurt`）。差し替えはまだ |

## 3-B. 粒は、絵にして確かめる（2026-08-28 追加）

**粒は書いてもその場では見えない。**
ゲームを起動し、ワールドへ入り、撃って、ようやく分かる——
**1 回の確認に数分かかる。**

```bash
python tools/particle-preview.py <particles/*.json> -o 出力.png
```

**同じ計算をこちらで回して、静止画を並べる**（時間の進みを横に）。

| 見えるもの | |
| --- | --- |
| 大きさ・色 | 式（`v.particle_age / v.particle_lifetime`）も評価する |
| 散り方 | 形・初速・加速度・抗力 |
| 寿命 | 何秒で消えるか |
| 合成 | `particles_add` は**加算**で描く |

**再現するのは使っている部品だけ。** 足りなくなったら足す。

> **ゲームの中で見るのが正。** これは**当たりを付けるための道具**で、
> 色味や重なりは実機で確かめる。
