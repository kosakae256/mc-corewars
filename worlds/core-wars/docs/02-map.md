# マップ・レベルデザイン

> 建てる前にここに書く。**建ててから仕様を決めない。**

ルールは [01-rules.md](01-rules.md)。

---

## 1. マップが満たすべきこと

**ルールから逆算すると、マップは次を満たす必要がある。**

| ルール | マップへの要求 |
| --- | --- |
| 1〜15人が同じルールで遊ぶ | **人数で広さを変えられない。** 1v1 でも 15v15 でも成立する形 |
| コアは即再生、張り付き勝負 | **コア前に「留まれる場所」と「引き剥がす経路」**が要る |
| 中央のダイヤ・エメラルドを奪い合う | **中央が魅力的で、かつ危険**であること |
| 死ぬとその場に落ちる | **帰り道が存在する**こと。中央から拠点まで距離が要る |
| チェストは表に置き、奪われる | **拠点に「守るべき場所」が2つ**（コアとチェスト）ある |
| 5秒でリスポーン、敗退なし | 復活地点からすぐ戦線へ戻れる。ただし**即座では守りが強すぎる** |

**とくに重い制約は「人数不定」。**
広すぎると 1v1 で誰にも会わない。狭すぎると 15v15 で身動きが取れない。

## 2. 全体の形

**3つの島が浮いていて、間と下はすべて奈落。** 完全対称。

> **2026-08-24 に 9島から 3島へ変更した。**
> 横の6島（拠点左右・中央左右）は**なかったことにする**。
> 経緯は [decisions/03](decisions/03-three-islands.md)。

```
      自チーム側          中央          敵チーム側

   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │  自拠点  │   │   中央   │   │  敵拠点  │
   └──────────┘   └──────────┘   └──────────┘
      x=900          x=1000          x=1100

        島の間・島の下はすべて奈落
```

| 種類 | 数 | 大きさ |
| --- | --- | --- |
| 中央 | 1 | 81 x 81 |
| 拠点 | 2（各チーム1） | 41 x 41 |
| **合計** | **3** | |

**180度回して重なる完全対称。** 2チームが完全に同条件。

### 一直線になったことの意味

**経路が1本しかない。** これは良し悪しの両方がある。

| | |
| --- | --- |
| **良い点** | どこで戦うかが明確。1v1 でも相手を見失わない。**人数が少なくても成立する** |
| **良い点** | 橋が狭いので、[2-A-4](#2-a-4-人数不定との相性) の人数差の緩和がそのまま効く |
| **懸念** | **迂回できない。** 守りが固まると膠着しやすい |

> **懸念は認識したうえで進める。**
> 膠着するようなら、中央の形（門が四方にある）で経路を分岐させるか、
> それでも足りなければ島を足す。**足す方が、あとから減らすより安い。**

## 2-C. 座標（確定 / 2026-08-22）

**実際のワールド上の位置。**

| 場所 | 座標 |
| --- | --- |
| **地面の高さ（全島共通）** | **y = -10** |
| 中央島の地面の中心 | (1000, **-10**, 1000) |
| **拠点A のコア** | **(900, 0, 1000)** |
| **拠点B のコア** | **(1100, 0, 1000)** |

### 構造物を置く座標

**置く Y は島ごとに違う。** 構造物の中で地面がどの高さにあるかが違うため。
どちらも置いた結果、**地面は y=-10 に揃う**。

```

  /structure load corewars:mid_nw_v4  960 -44  960
  /structure load corewars:mid_ne_v4  987 -44  960
  /structure load corewars:mid_sw_v4  960 -44  987
  /structure load corewars:mid_se_v4  987 -44  987

拠点（41x41）
  /structure load corewars:base_v3  880 -32  980 270_degrees   → コア (900, 0, 1000)
  /structure load corewars:base_v3 1080 -32  980  90_degrees   → コア (1100, 0, 1000)
```

**構造物は `kit` アドオンに同梱してある**（名前空間 `corewars:`）。
名前の末尾の版番号は中身を直すたびに上がる。最新は
`tools/mapview` を実行すると出力される（[spec/08](spec/08-map-authoring.md)）。

```
**コアは構造物内オフセット (20, 32, 20)。** 41x41 のちょうど中心。

> **白コンクリートはコア専用にした。**
> リスポーン地点の目印と同じブロックだったため、探すときに紛れていた。
> いまは**ワールド中の白コンクリート＝コア**なので、
> ジェネレータと同じく「ブロックが正」で扱える（2-3 と同じ考え方）。

### 距離感

```
    拠点A            中央            拠点B
   x=900           x=1000          x=1100
     |───── 100 ─────|───── 100 ─────|
     |←──────────── 200 ────────────→|
```

- **拠点間は 200 ブロック**
- **中心から各拠点まで 100 ブロック**

### この距離が意味すること

**奈落を渡るので、100 ブロックは橋を架けながらだと相当に遠い。**

- 資源を持ち帰る往復が長い → **持ち歩くか預けるかの判断が重くなる**（[01-rules.md](01-rules.md) 4-5）
- 攻め込むには準備が要る。思いつきで突撃できない
- 死んで拠点に戻されると、**復帰に時間がかかる**

> 島の大きさとの関係:
> 中央島は 81、拠点島は 41。
> 中央島の縁から拠点島の縁までは、およそ 100 - 41 - 20 = **40 ブロック程度**。
> ここが橋を架ける距離になる。

## 2-A. 奈落があることの意味

**これはマップの飾りではなく、ゲームの根幹を変える。**

### 2-A-1. ブロックが移動手段になる

**島を渡るには橋を架けるしかない。**
ブロックは防衛設備であると同時に、**足そのもの**になる。

- ブロックが尽きる＝動けなくなる
- 買い物でブロックを買う優先度が跳ね上がる
- **橋を架けている最中がいちばん無防備**

### 2-A-2. 落とす＝一撃必殺

**ノックバックが最強の攻撃手段になる。**
体力を削り切らなくても、押し出せば勝ち。

- 相手を突き落とす道具の価値が非常に高い
- **橋の上での戦闘が主戦場**になる
- 橋を壊して退路を断つ、という戦い方が生まれる

### 2-A-3. 落としたアイテムが消える

**奈落に落ちたアイテムは戻らない。**

[01-rules.md](01-rules.md) 4-4 で「死んだら落ちる。倒した側が拾える」と決めたが、
**奈落の上で倒すと、落ちた物ごと消える。**

つまり倒し方で結果が変わる。

| どこで倒すか | 結果 |
| --- | --- |
| 島の上 | **拾える。** 稼ぎになる |
| 橋の上・奈落の上 | **消える。** 相手に損をさせるだけ |

**これは面白い分岐。** 資源を奪いたいなら島へ追い込む必要があり、
ただ妨害したいだけなら突き落とせばいい。

> **決める必要がある:** これを仕様として認めるか、
> それとも落下死のアイテムは拠点に戻すなどの救済を入れるか。
> **今は「消える」を採用しておく。** 奈落の緊張感がそのまま活きるため。

### 2-A-4. 人数不定との相性

**奈落は人数差を緩和する方向に働く。**

橋は狭く、一度に渡れる人数が限られる。
**15人いても橋の上では数人ずつしか戦えない。**
少人数側が橋の出口で待ち構えれば、数の差をある程度打ち消せる。

**これは「人数不定」という前提と噛み合っている。**

## 2-B. 拠点の構成（確定 / 2026-08-22）

**浮島の上に、2階建ての城。**

```
        ┌──────────────┐
   2階  │  バルコニー   │  ← 開けている。ジェネレータ
        │  （壁で囲わない）│
        ├──────────────┤
   1階  │ ショップ・チェスト│  ← 浮島と同じ高さ
        │ エンダーチェスト  │     リスポーン地点
        │ ジェネレータ     │
        └──────────────┘
        ══════════════════
              浮島
```

### 1階（浮島と同じ高さ）

**地面の高さがそのまま1階。** 段差なしで入れる。

| 置くもの |
| --- |
| ショップ |
| チェスト（チーム共有・表に置く・奪われる） |
| エンダーチェスト（個人・安全） |
| ジェネレータ |
| **リスポーン地点** |

### 2階（バルコニー）

**開けた空間。壁で囲わない。** ジェネレータを置く。

### 縦の動線

**2階へ上がる手段は3つ。** 1つに絞らないことで、守り手が塞ぎきれないようにする。

| 経路 | 性格 |
| --- | --- |
| **1階からの階段（2本）** | 正規の経路。守り手が押さえる場所 |
| **外付けの階段** | 建物の外側から。守りを迂回できる |
| **下から横へブロックで侵入** | 攻め手が自分で足場を作る。**囲わないから成立する** |

> **3つ目が効く。** 2階を壁で囲わないと決めたので、
> 攻め手はブロックを積んで横から入れる。
> 守り手は「入口を守る」だけでは足りず、**面で守る**必要が出る。

### 拠点には「正面」がある（確定 / 2026-08-22）

**プレイヤーは基本的に中央（敵拠点）方向へ向かう。**
拠点はその方向を意識して作る。

| | 向き | 性格 |
| --- | --- | --- |
| **正面** | **中央（敵拠点）側** | 攻め手が来る方向。人の流れが集まる |
| **背面** | 中央と反対側 | 安全な側 |

#### 1階→2階の階段は背面に付ける

**中央と反対側**に取り付ける。

> **なぜか。** 正面に付けると、攻め込んだ相手がそのまま駆け上がれてしまう。
> 背面にあれば、攻め手は**建物を回り込むか、中を突っ切る**必要がある。
> 守り手は下がりながら上がれる。**攻守で移動の向きが逆になる。**

#### 設計上の決めごと

**設計データは「+Z 側が中央方向」として書く。**
実際の配置では、島の位置に応じて回転させる。

### 見た目

| | 決め |
| --- | --- |
| 基調 | **木造 + 石レンガ。** 葉も使う |
| 印象 | **砦ではなく「城」。** 無骨さより、整った美しさ |
| ブロックの置き方 | **まばらに散らす。** 一色でベタ塗りしない |

> **「まばらに配置」が要点。**
> 同じブロックで面を塗ると、大きさだけが目立って安っぽくなる。
> 近い色の別ブロックを散らすと、面に質感が出る。

## 3. 拠点に置くもの

| もの | 決まっていること | 未定 |
| --- | --- | --- |
| **コア** | コンクリート。壊されても即再生 | 位置、周りの地形、防衛のしやすさ |
| **拠点ジェネレータ** | 鉄・金が湧く | 位置、個数 |
| **チェスト** | **表に置く。** チーム共有・敵に奪われる | 位置、個数、増やせるか |
| **エンダーチェスト** | 個人の金庫。安全 | 位置、最初からあるか |
| **買い物の入口** | ブロック・武器・ツルハシ等 | 形（NPC か別の手段か）、位置 |
| **リスポーン地点** | 5秒後に復活 | コアからの距離 |

### 配置で決まること

**「コア」「チェスト」「ジェネレータ」の距離が、拠点の守りやすさを決める。**

- 3つが固まっていれば、守りは楽だが**一度崩されると全部持っていかれる**
- 散らばっていれば、守りは薄く伸びるが**全滅しにくい**

**チェストを表に置くと決めた以上、ここは意図して設計する。**

## 4. 島ごとの役割

**3つの島に何を置くかで、人の流れが決まる。**

| 島 | 役割 | 未定 |
| --- | --- | --- |
| **拠点**（×2） | コア・チェスト・買い物・復活地点・拠点ジェネレータ | 配置 |
| **中央**（×1） | ダイヤ・エメラルド。最大の奪い合い | ジェネレータの位置 |

**横の6島を無くしたので、「何を置くか未定の島」も無くなった。**
決めるべきことが減っている。

### 島の繋がり方

**どの島とどの島が橋で繋げられるか**も決める必要がある。

- 隣接する島だけか、斜めにも渡れるか
- 距離は均一か、経路によって違うか

**距離が経路の性格を決める。** 短い橋は架けやすく攻めやすい。
長い橋は資源を食い、架けている間に狙われる。

## 5. 建築の保存

**手で建てたものは `world/structures/` に `.mcstructure` で保存する。**
ワールドが壊れても建て直せるようにするため。

対称マップなので、**片側を作って複製する**のが基本になる。
