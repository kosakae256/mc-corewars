# 決定: 拠点の構成を「四隅の塔 + 壁 + 中庭」にする

2026-08-22 / **採用**

参考: [delphic/vorld-fort](https://github.com/delphic/vorld-fort)
（[itch.io](https://delph.itch.io/fort-generator) で公開されている手続き型の砦生成器）

## 決めたこと

**拠点を「単体の天守」ではなく、「四隅に塔・それを繋ぐ壁・中は中庭」にする。**

```
   塔━━━━━━━壁━━━━━━━塔
   ┃                    ┃
   壁      中庭        壁
   ┃                    ┃
   塔━━━━━門(アーチ)━━塔
```

## なぜ

### 1. Core Wars の要件に、そのまま噛み合う

| 砦の要素 | Core Wars での役割 |
| --- | --- |
| **中庭** | **開けた戦闘空間。** ジェネレータを置く場所 |
| **壁の上（歩ける通路）** | 中庭を見下ろす防衛線。縦の戦いが生まれる |
| **四隅の塔** | 守り手が籠もる拠点。攻め手が排除すべき点 |
| **門（アーチ）** | **攻め手が抜けるべき一点。** 攻防の焦点 |
| 塔の最上部 | **コアの置き場所** |

**「2階は開放的」という要件が、中庭という形で自然に満たされる。**
壁で囲うのではなく、**囲いの内側が広場**になる。

### 2. 単体の建物より、戦いの場所が増える

これまでの案（天守1棟）は、攻め手の選択肢が「入って登る」しかなかった。
砦なら**壁を越える・門を抜く・塔を潰す**と経路が分かれる。

### 3. 参考実装から得た具体的な作り方

読んで分かった、そのまま使える手法:

| 手法 | 内容 |
| --- | --- |
| **胸壁（battlement）** | 1つ飛ばしにブロックを置く（`i % 2 == 1`）。これだけで城壁に見える |
| **階の高さ** | 1階＝高さ4 + 天井1 = **5**。最上階だけ+2して見せ場を作る |
| **塔の装飾柱** | 塔の四隅に、本体より1マス外へ張り出す柱を通す。輪郭が締まる |
| **窓と扉の配置** | 中間階は窓、**壁の上と同じ高さの階は扉**。→ 壁の上から塔へ入れる |
| **地面** | 円形に、深くなるほど半径を縮める。**浮島の絞りと同じ考え方** |
| **門** | 壁の中央にアーチ。幅は「壁の長さ-2」と6の小さい方 |

**とくに「壁の上と塔が扉で繋がる」が重要。**
動線が閉じないための具体的な答えになっている。

## 捨てた案とその理由

| 案 | なぜ捨てたか |
| --- | --- |
| 天守1棟（これまでの案） | 攻め手の経路が1つしかない。中庭が作れず「開放的な階」が窮屈 |
| `.vox` モデルを取り込む | **これは生成器であってモデル集ではなかった。** 取り込む対象が無い |
| このコードをそのまま移植 | ブロックの種類も座標系も違う。**考え方だけ借りる方が速い** |

## この判断が崩れる条件

- 中庭が広すぎて、守り手が守り切れないと分かったとき
- 塔が4つでは多すぎる／少なすぎると分かったとき
- **1v1 で砦が広すぎると分かったとき**（人数不定という前提が効いてくる）

## 影響

- `tools/mapview/designs/base.mjs` を書き直す
- 胸壁・アーチ・塔を作る補助関数を `voxel.mjs` に足す
- コアの置き場所を「屋上」から「**中央の塔の最上部**」へ変える可能性がある

## 追記（2026-08-24）: 建物の中に柱を立てない

**撤去した。** 隅櫓に 7x7=49 本、天守に 120 本の原木の柱が立っていた。

もともとは「空洞の上に床を張ると宙に浮く」ため入れたもの。
だが結果として**部屋が林になり、戦闘の邪魔**になった。
[game/00-concept.md](../00-concept.md) の「戦闘において邪魔にならないデザイン」に反する。

**Minecraft ではブロックは落ちない。** 支えが無くても成立する。
見た目の「支え」は壁と胸壁が担う。

支えの無いブロックは 290 → **1877** に増えたが、これは受け入れる。
**遊びやすさを、物理的なもっともらしさより優先する。**

橋を支える柱（建物の外・168本）は残す。
**空中に架かる橋は、支えが無いと明らかに不自然に見える**ため。
