# 決定: ワールド単位でディレクトリをまとめる

2026-08-24 / **採用**

## 決めたこと

**1つの世界を作る材料を、`worlds/<ワールド名>/` に集める。**

```
worlds/core-wars/
├── docs/     設計（企画・ルール・マップ・仕様・決定記録）
├── packs/    パックのソース（game / kit）
└── world/    ワールドデータ（手動 export した .mcworld）
```

`addons/` は**実験専用**にする。ゲーム本体は置かない。

## なぜ

### 1. 材料が散らばっていた

変更前は、Core Wars を作る材料がこう分かれていた。

| もの | 場所 |
| --- | --- |
| 企画・ルール・マップ | `docs/game/` |
| 技術仕様 | `docs/spec/07〜09` |
| 決定記録 | `docs/decisions/` |
| ゲーム本体 | `addons/game/` |
| 制作の道具 | `addons/kit/` |
| 構造物 | `world/structures/` |

**6箇所。** どれがこの世界のもので、どれが実験の名残かが、
ディレクトリを見ただけでは分からない。

### 2. 実験と本体が同じ棚に並んでいた

`addons/` には `hello` `leveler` `bots_cmd` `exp` という
**過去の実験**が並んでいて、その中に `game` と `kit` が混ざっていた。
名前を見ても、どれが遊ぶ人に届くものか区別が付かない。

### 3. 丸ごと持ち運べる

ワールド名のフォルダにまとまっていれば、
**そのフォルダだけ渡せば作り直せる。**
2つ目の世界を作るときも、同じ形を複製すればよい。

## 分け方の基準

**ワールド固有か、どのワールドでも効く知識か。**

| | 場所 | 例 |
| --- | --- | --- |
| ワールド固有 | `worlds/<名>/docs/` | ルール、マップの座標、拠点の構成 |
| **共通の知識** | `docs/` | Script API の挙動、`/reload` の限界、BDS の立て方 |

**調査結果は共通側に置く。** ワールドを捨てても、
「調べて分かった事実」は次の世界でそのまま効くため。

## 捨てた案とその理由

| 案 | なぜ捨てたか |
| --- | --- |
| `worlds/<名>/` の中も `addons/` と呼ぶ | **`addons/` は実験用**と決めたので、同じ名前だと意味が衝突する。`packs/` にした |
| パックごとにソースと成果物を同居（`packs/game/{src,bp,rp}`） | ワールドに入れるとき集める処理が要る |
| ワールドデータを展開して commit | `.mcworld` のまま置くことにした。手順が単純 |

## この判断が崩れる条件

- 2つ目の世界を作ったとき、`packs/` の中身がほとんど同じだと分かったとき
  → 共通部分を切り出す必要が出る
- `.mcworld` が大きくなりすぎて、リポジトリが太ったとき
  → 展開して commit するか、Git LFS に移す

## 影響

- `docs/game/` → `worlds/core-wars/docs/`
- `docs/decisions/` → `worlds/core-wars/docs/decisions/`
- `docs/spec/07〜09` → `worlds/core-wars/docs/spec/`
- `addons/{game,kit}` → `worlds/core-wars/packs/`
- `world/structures/` の生成物は **`packs/kit` 側に一本化**（二重に持っていた）
- 相対リンクが 19 箇所壊れたので、**[tools/check-links.mjs](../../../../tools/check-links.mjs) を作った**
