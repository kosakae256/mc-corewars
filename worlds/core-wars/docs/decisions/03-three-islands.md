# 決定: 島を 9 から 3 に減らす

2026-08-24 / **採用**

## 決めたこと

**横の6島（拠点左右 ×4・中央左右 ×2）を無くす。**
マップは **中央 1 + 拠点 2 = 3島** の一直線になる。

```
   自拠点 ──── 中央 ──── 敵拠点
   x=900      x=1000     x=1100
```

## なぜ

### 1. 6島とも「何を置くか未定」のままだった

[game/02-map.md](../02-map.md) 4章に、こう書いてあった。

> **「拠点左右」と「中央左右」に何を置くか。** ここが未定のままだと、
> 6つの島がただの通り道になってしまう。

**半年経っても埋まらない欄は、要らない欄である可能性が高い。**
役割を思いつけないまま置いても、通り道にしかならない。

### 2. 作る量が 3 分の 1 になる

島を1つ作るのに、設計・下絵・物理検査・分割・配置の一巡が要る。
**6島ぶんの手間が丸ごと消える。**

作り手（Claude）はゲーム画面を見られないので、
島が増えるほど「見ないまま作った変なもの」が増える。
[spec/08](../spec/08-map-authoring.md) 0章の問題がそのまま効いてくる。

### 3. 決めるべきことが減る

橋の繋ぎ方（どの島とどの島を繋げられるか）も、
3島なら「拠点↔中央」の2本しかない。**組み合わせが爆発しない。**

## 捨てたもの

| 捨てたもの | 惜しくない理由 |
| --- | --- |
| 迂回路 | そもそも何を置くか決まっていなかった |
| 複数箇所での奪い合い | **中央1点に集中する方が、人数が少ないときに成立しやすい** |
| 拠点の前哨としての横島 | 拠点そのものに正面/背面の区別を付けてあるので、役割が重複していた |

## この判断が崩れる条件

**経路が1本しかないので、守りが固まると膠着しやすい。**

- 中央を取った側が一方的に有利になり、逆転が起きなくなったとき
- 橋の出口で待ち構えるだけの試合になったとき

> そうなったら、まず**中央の四方の門**で経路を分岐させることを試す。
> それでも足りなければ島を足す。**足す方が、あとから減らすより安い。**

## 影響

- [game/02-map.md](../02-map.md) の全体図・島の役割・未確定欄を書き換えた
- [spec/08-map-authoring.md](../spec/08-map-authoring.md) の進め方「9島そろったら」を直す
- **`tools/mapview` に横島の設計は作らない**
- 橋は「拠点↔中央」の2本だけを考えればよい
