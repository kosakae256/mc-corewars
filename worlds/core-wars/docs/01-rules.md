[00-concept.md](00-concept.md) の企画を、遊べる形まで落とす。

> **この文書には「確定」と「一般的にこうなっている（＝候補）」が混在している。**
> 候補は **要検討** と印を付けてある。決めたら印を外す。

## 1. コア

### 1-1. 確定していること

- コアは**ブロック（コンクリート）**
- **ツルハシ等で破壊**する
- **100 回**壊されたチームが負け
- **壊されたら即座に再生する**

### 1-2. 「即再生」が意味すること

**コアは実質「殴った回数を数えるブロック」になる。**
穴が開いたままにならないので、掘り進んで奥へ入るような攻め方は生まれない。

代わりに、**コアの前にどれだけ張り付けるかの勝負**になる。

- 攻め手は、殴り続けられる時間を作りたい
- 守り手は、そこから引き剥がしたい
- **戦闘と防衛設備の価値が上がる**（相手をコアから離す手段だから）

> **試合時間はここで決まる。**
> 1回殴るのに掛かる時間 × 100 が、張り付き続けた場合の最短時間。
> 例えば1回1秒なら最短100秒。
> **道具で破壊速度が変わるなら、経済が試合時間に直結する。**

### 1-3. 決める必要があること

| 論点 | 選択肢 | 備考 |
| --- | --- | --- |
| 誰でも壊せるか | 素手可 / ツルハシ必須 | 「ツルハシ等」とあるので**道具は要る**前提 |
| 道具で速さが変わるか | 変わる / 一定 | 変わるなら、良い道具＝攻め手の強さになる |
| 自陣のコアを壊せるか | **不可にすべき** | 事故と嫌がらせを防ぐ |
| 連打の扱い | 制限する / しない | 即再生なので、道具次第では高速で削れる |

### 1-4. コアの周りの防衛

一般に、この種のゲームでは**コアの周りを自分で要塞化できる**。

- ブロックを買って積み、殴りに来た相手を足止めする
- 相手はツルハシで掘って進む

**要検討:** 建築を許すか。許すなら、置けるブロックに制限を設けるか。

## 2. 通貨とジェネレータ

### 2-1. 確定していること

- **鉄・金・ダイヤ・エメラルド**の4種
- **ジェネレータ**という場所から湧く

### 2-2. 一般的な構成（要検討）

この形式のゲームでは、ジェネレータは**2種類に分かれている**のが定番。

| 種類 | 置き場所 | 出るもの | 性質 |
| --- | --- | --- | --- |
| **拠点ジェネレータ** | 各チームの自陣 | 鉄・金 | 安全。放っておいても溜まる |
| **中央ジェネレータ** | マップ中央や中間地点 | ダイヤ・エメラルド | **奪い合いになる。ここが戦場** |

**この分け方が、戦いを起こす仕掛けそのもの。**
自陣に籠もれば鉄と金は溜まるが、ダイヤとエメラルドは手に入らない。
強くなりたければ出て行くしかない。

### 2-3. ジェネレータは「置いたブロック」で決まる（確定 / 2026-08-22）

**ジェネレータの位置を、設定ファイルや座標で持たない。**
**ワールドに置かれたブロックそのものを正とする。**

| 置くブロック | 湧くもの | 間隔 |
| --- | --- | --- |
| 鉄ブロック | 鉄 | **3 秒**（2026-08-28 変更。1.5 秒 → 3 秒） |
| 金ブロック | 金 | 6 秒 |
| ダイヤブロック | ダイヤ | 30 秒 |
| エメラルドブロック | エメラルド | 45 秒 |

**鉄が溜まる速さが、買い物の間隔をそのまま決める。**
半分にすると、**装備が揃うまでの時間が倍**になる。

#### 頭上の案内（2026-08-28 変更）

**種類と、次が湧くまでの秒数だけ。**

```
鉄 2s
```

| | |
| --- | --- |
| 出す相手 | **16 マス以内に居る人** |
| 試合中でないとき | **秒数を出さない**（進まない秒数は嘘になる） |
| **落ちている数** | **出さない**（2026-08-28 変更） |

拾えば済む数を頭上に出しても、**やることは変わらない。**
数えるために足元を見るくらいなら、**拾ってから考える。**

**書き換えで更新する。作り直さない**——
作り直すと**消えるのと出るのが同じ tick に重なり、ちらつく**
（[15-presentation.md](spec/15-presentation.md) 7-3-A と同じ理由）。

**ブロックの上から、対応する資源が湧く。**

#### なぜこうするか

**微調整を、ゲーム内で完結させるため。**

ジェネレータの位置は「実際に遊んでみて動かす」ことが何度も起きる。
座標を設定に書く方式だと、**動かすたびにコードを直して配置し直す**ことになる。

ブロックを正にすれば、**ゲーム内でブロックを置き直すだけ**で済む。
マップそのものが設定になる。

#### いつ読み直すか

**毎 tick 探さない。** 重いうえ、そこまでの即時性は要らない。

**`/reload` などの起動時に一度だけ探し、見つけた結果を明示する。**

```
[gen] 鉄 x4 / 金 x4 / ダイヤ x2 / エメラルド x2 を検出
```

**何を見つけたかを必ず出す。** 黙って動くと、
置き直したのに反映されていない状態に気づけない。

### 2-4. 決める必要があること

| 論点 | 備考 |
| --- | --- |
| 各通貨の湧く間隔 | 鉄は数秒、エメラルドは数十秒、が一般的 |
| 中央ジェネレータの数 | ダイヤ・エメラルドで何箇所ずつか |
| 拾い方 | 地面に湧いて拾う / 自動で入る |
| 上限 | 地面に溜まり続けると重い。上限や消滅時間が要る |
| **強化できるか** | 一般には**ジェネレータの速度を上げる強化**がある（後述） |

## 3. 買い物

### 3-1. 一般的な構成（要検討）

**通貨は使い道が無ければ意味がない。** この形式では買い物が中心にある。

| 場所 | 何を買うか | 使う通貨 |
| --- | --- | --- |
| **アイテムショップ** | ブロック・武器・防具・道具・消耗品 | 鉄・金・エメラルド |
| **チーム強化** | チーム全体に永続で効く強化 | **ダイヤ** |

**「個人の装備」と「チームの強化」で通貨を分ける**のが定番。
ダイヤをチーム強化専用にすると、中央の奪い合いに意味が生まれる。

### 3-2. 一般的なチーム強化（要検討）

| 強化 | 効果 |
| --- | --- |
| ジェネレータ強化 | 自陣の鉄・金が湧く速度が上がる |
| 防具強化 | チーム全員の防具に耐性が付く |
| 道具強化 | 採掘・攻撃が速くなる |
| **罠** | 自陣に侵入した最初の敵に効果（盲目・採掘速度低下など） |

**罠は使い捨て**（発動したら買い直し）にするのが一般的。

### 3-3. 決める必要があること

- 買い物の入口をどうするか（NPC / メニュー / コマンド）
- 何を売るか、値段はいくらか
- **持ち物は死んだら失うか**（失うなら買い物が繰り返し発生する）

---

## 3-A. 味方への攻撃（確定 / 2026-08-22）

**味方同士は殴り合えない。**

チーム戦なので当然だが、明示しておく。
奈落があるマップでは、**事故と嫌がらせの被害が特に大きい**
（押し出せば一撃で落とせてしまう）。

> ノックバックも通さない。ダメージだけ止めても、
> 押し出せるなら意味がない。

## 3-B. 満腹度は減らない（確定 / 2026-08-25）

**どのプレイヤーも、いかなる場合も満腹度が減らない。**

| | |
| --- | --- |
| 満腹度 | **常に満タン** |
| 自然回復 | **入れたまま**（`naturalRegeneration` は on） |

### なぜ

**食料の管理はこのゲームの遊びではない。**

コアを削り、資源を取り、立体機動で動き回る——
そこに「腹が減るから食べる」を足しても、
**手を止める理由が 1 つ増えるだけ。**

食料を買う・拾う・持ち歩く手間は、**ショップの選択肢を薄める。**

### 自然回復は残す

満腹度を消費して体力が戻る仕組みは**残したい。**
戦闘の合間に体力が戻らないと、**一度削られたら下がり続ける**だけになる。

満腹度を満タンに保てば、**回復は常に働く。**
「消費して回復する」という仕組みはそのままで、消費した分をこちらが埋める。

### 速さ（2026-09-01 変更）

**自然回復そのものはバニラの仕組み**（飽和度を食って戻る）で、
**速さをこちらから設定する口が無い。** 増やすには足すしかない。

| | |
| --- | --- |
| バニラ | **そのまま動かす**（飽和度がある間、少しずつ戻る） |
| **足す分** | **2 秒ごとに 1**（`features/hunger`） |

> ### 倍速は速すぎた（2026-09-01）
>
> 0.5 秒ごとに 1 を足して**ほぼ倍速**にしていたが、**削り合いが成立しなくなった。**
> **細く足すだけ**に戻す。

**倒れている人には触らない**——復活のときに満タンで戻る。
**上限は超えない**（金のリンゴで増えている分まで押し上げない）。

## 3-C. 最大人数は 20（確定 / 2026-09-01）

| | |
| --- | --- |
| 上限 | **20 人** |
| どうやって | **起動から 2 秒後に `setmaxplayers 20` を 1 度送る**（`features/session/maxplayers.ts`） |

**毎回手で打たない。** 既定のままだと入れない人が出るため。

**2 秒待つのは、起動直後はコマンドが通らないことがある**から。
失敗しても遊びは続く（ログにだけ残す）。

## 4. 死亡とリスポーン

### 4-1. この設計の勘所

**コア 100 回という長い勝利条件は、「死んでも復帰できる」ことが前提。**
一度死んだら終わりでは 100 回に届かない。

### 4-2. 確定していること

| 項目 | 決め |
| --- | --- |
| リスポーン | **死亡から 5 秒後**、自陣に復活 |
| 持ち物 | **持ち歩いていたものは全ロスト**（預けたものは残る。4-3） |
| 落ちるか | **落ちる。** 倒した側が拾える |
| 敗退 | **無い。** コアが尽きるまで何度でも戦える |

### 4-3. 保管手段がある

**死んで失うのは「持ち歩いていたもの」だけ。** 預けたものは残る。

| 手段 | 誰のものか | 安全か | 置き場所 |
| --- | --- | --- | --- |
| **エンダーチェスト** | **本人だけ** | **安全**（奪われない） | — |
| **チェスト** | **チーム共有** | **奪われる** | **表に出す** |

**チェストは敵に開けられる。** そして**隠さず表に置く。**

この2つで、性質のはっきり違う金庫が2種類そろう。

| | エンダーチェスト | チェスト |
| --- | --- | --- |
| 長所 | 絶対に奪われない | **仲間が使える** |
| 短所 | **自分しか使えない** | 攻め込まれたら奪われる |

**「安全だが独り占め」と「共有できるが危険」の二択。**
チームで戦うゲームなので、**仲間に使わせたいなら危険を受け入れる**ことになる。

### 4-4. 落ちる

**死んだ場所にアイテムが落ちる。** 消滅ではない。

倒した側が拾えるので、**戦闘そのものが稼ぎになる。**

### 4-5. これが作る駆け引き

**「持ち歩くか、預けるか」が常に問われる。**

- 中央でダイヤを取った → **持ったまま戦い続けるか、拠点へ帰って預けるか**
- 持ち歩けば、そのまま使える。ただし死ねば**相手の手に渡る**
- 預ければ安全。ただし**取りに戻る往復が要る**

**倒す価値が高くなる。** 相手が何を持っているか分からないが、
中央から帰る途中の相手は「積んでいる」可能性が高い。
**帰り道が危険地帯になる。**

> **前に書いた「溜め込む意味が無い」は誤りだったので取り消す。**
> 保管手段があるので、貯蓄は成立する。
> 消えるのは持ち歩き分だけで、**預けたものは資産として積み上がる。**

### 4-6. 「表に置く」が作るもの

**拠点を攻める理由が2つになる。**

1. コアを削る（勝利に直結）
2. **チェストを漁る（相手の資産を奪う）**

コアを削れない状況でも「稼ぎに行く」選択肢が残るので、**攻めが死なない。**
守る側も「コアを守る」だけでなく「金庫を守る」必要が出て、**守りが薄く伸びる。**

**表に出ていることが効く。** 隠せるなら、上手い人は見つからない場所に置いて
リスクを消してしまう。**表に固定することで、誰もが同じ危険を負う。**

### 4-7. 決める必要があること

| 論点 | 備考 |
| --- | --- |
| エンダーチェストは最初からあるか | 買わせるなら、序盤の投資判断になる |
| チェストは自分で増やせるか | 増やせると分散して隠せてしまう。**固定の方が狙いに合う** |
| 落ちたアイテムの寿命 | 放置が溜まると重い。消滅時間が要る |
| 落とすものに例外はあるか | 例えば「買ったツルハシは落とさない」など |

> **参考にした形式との違い。**
> ベッド系のゲームは「ベッドを壊されたら復活できなくなる」が中心にある。
> Core Wars は**コアに100の残数がある**ので、
> 「復活できなくなる」ではなく「削り切る」ゲームになる。
> **敗退の概念を持ち込まない方が、企画の狙い（削り合い）と噛み合う。**

### 4-8. まだ決めていないこと

- リスポーン地点（コアの隣か、少し離れた場所か）
- 復活直後の無敵時間を設けるか（自陣を攻められている間に湧き潰されないため）

## 5. 試合の流れ（要検討）

```
開始
  ↓ 準備時間（あるなら）
資源が湧き始める
  ↓
自陣で装備を整える / 中央へ出てダイヤ・エメラルドを取る
  ↓
相手陣へ攻め込み、コアを削る
  ↓ （死んだら復活してやり直し）
どちらかのコアが 0 になる → 決着
```

### 5-1. 時間制限

**設けない。ただし内部的には 999 分として持つ**（[00-concept.md](00-concept.md) 4章）。
後から制限を付けられるよう、**最初から設定値にしておく**。

### 5-2. 途中参加

**あり。** 進行中のゲームに人が入ってくる。

| 論点 | 備考 |
| --- | --- |
| どちらのチームに入れるか | **人数 → 不利さ → 運**の順に決める（[11-match.md](spec/11-match.md) 5-A） |
| 何を持って入るか | 裸で入ると、育った相手に何もできない可能性がある |
| 参加を締め切るか | 決着間際に入れても意味が薄い |

**要検討: 途中参加者の初期装備。**
全ロスト前提なので「死んだ直後の人」と同じ状態にするのが自然だが、
それで成立するかは実際に遊んでみないと分からない。

### 5-3. 決める必要があること

- 開始直後に無防備な時間を作るか（準備時間）
- 途中参加者の扱い（上記）

## 6. 未確定のまとめ

**先に決めたい順。**

1. **ジェネレータの配置と湧く速度** — 戦いが起きる場所と頻度が決まる
2. **買い物で何が買えるか** — 通貨の意味が決まる。基本はブロック・武器・ツルハシ
3. **コアを壊す道具で速さが変わるか** — 試合時間に直結する
4. 途中参加者の初期装備
6. 準備時間・復活直後の無敵時間の有無

**決まったもの:** チーム構成（2チーム・1〜15人・不定・途中参加あり）、
コアは即再生、リスポーンは5秒・持ち歩き分は全ロストして地面に落ちる、
エンダーチェスト（個人・安全）とチェスト（チーム共有・表に置く・奪われる）で
貯蓄できる、時間制限なし（999分）。
