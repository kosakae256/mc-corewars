## 1. 何を変えるのか

> ### 刺した点に引っ張られるのではない。
> ### **視点の方向へ自分が加速する。**

ワイヤーは**動力ではなく、曲げるもの**になる。

| | v1（いま） | **v2** |
| --- | --- | --- |
| ワイヤーの役割 | **引く力を出すもの** | **進む先を曲げるもの** |
| 進む向き | **刺した点の方向** | **視点の方向** |
| 動きの形 | 直線的に吸い寄せられる | **刺した点を回り込む** |
| 終わり方 | 手前まで来たら自動で切れる | **押すのをやめるまで続く** |
| 押し続けると | — | **最後は壁に張り付く** |

### なぜ変えるのか

**v1 は「どこに刺すか」で結果がほぼ決まる。**

刺した点へまっすぐ引かれるので、飛んだ先も速さも**撃った瞬間に決まっている。**
飛んでいる間にできることが少ない。

v2 は**飛んでいる間が操作になる。**
同じ場所に刺しても、**どこを向くか・いつ放すか**で行き先が変わる。

## 2. 操作

| 回 | すること |
| --- | --- |
| **1 回目** | **刺す。** まだ動かない |
| **2 回目（長押し）** | **動く。** 押している間ずっと |
| **離す** | **外れる。** そのままの勢いで飛んでいく |

**離した瞬間が唯一の終わり方。**
v1 のような「近づいたら自動で切る」「角度を外れたら切る」は持たない。
**いつ放すかが操作そのもの**なので、こちらで切ってはいけない。

> 押しっぱなしにすれば**壁に張り付いて止まる。**
> 放さない限り外れないので、**張り付きは「放さなかった結果」**になる。

### 長押しの取り方

`minecraft:use_modifiers` を付けると、`itemStartUse` / `itemStopUse` が飛ぶ
（[docs/research/12-item-hold.md](../../../../docs/research/12-item-hold.md)）。

## 3. 動きの決まり

**押している間、毎 tick この順で計算する。**

| | 何をするか |
| --- | --- |
| **1. 推進** | **視点の向き**へ加速 |
| **2. 引き** | **刺した点の向き**へ加速。**推進の 1.5 倍** |
| **3. 重力** | **かけない**（3-4） |
| **4. ひも** | **長さより外へは出さない**（これが円運動） |
| **5. 縮み** | **近づいたぶんだけ、ひもも短くする** |

### 引きは推進より強い

**推進（ガス）よりも、引かれる力のほうが 1.5 倍強い。**

同じか弱いと、**吹かし続ければ振り切れてしまう。**
強くしておけば、押している限り**必ず内側へ寄っていく。**

### 3-1. 推進は視点の向き

**見ている方へ進む。** ワイヤーの向きは関係しない。

#### 近づくほど弱くなる（2026-08-25 追加）

**刺した点に近いほど、推進が効かない。**

| 距離 | 推進 |
| --- | --- |
| **3 マス以下** | **0** |
| 3 〜 12 マス | **その間で真っ直ぐ減る** |
| 12 マス以上 | **そのまま** |

近くでは**ワイヤーに強く引かれるだけ**になる。

> **終わりぎわに暴れさせない。**
> 手元まで来てから吹かせると、
> **張り付く直前に振り回されて**、どこへ行くか分からなくなる。
>
> 遠くでは自分で行き先を決め、**近づいたらワイヤーに任せる。**

12 マスという境目は**まだ当てずっぽう。** 飛んでみて決める。

### 3-2. ひもは「長さを保つもの」（2026-08-25 修正）

**刺した点へ引く力**として作ったが、それでは**吊られない。**

> 前を向いて撃つと、引く向きはほぼ水平になる。
> **上を支える力がどこにも無いので、そのまま落ちる**（2026-08-25 の「下行くね」）。

ひもは力ではなく**拘束**として書く。

> ### ひもの長さより遠くへは、行けない。

**「引き戻される」ではなく「行けない」。**

ばねとして書くと**伸びる**（2026-08-25 の「紐伸びすぎかも」）。
縮んでいくひもに body が付いていけず、**いつまでも張り付かない。**

毎 tick、こう決める。

1. 刺した点へ向かう向きの速度を見る
2. **ひもの長さちょうどに来るのに必要な速さ**を出す
3. 足りなければ、**足りないぶんだけ足す**

これで**外へは出ない。** 遠ざかる速度は消え、
残るのは**円に沿った速度だけ**——落ちる勢いが横へ振れる勢いに変わる。

**速さの上限より、ひもが優先。**
上限で丸めてからひもを掛ける。丸めるほうが後だと、
**縮むひもに追いつけない。**

### 3-3. ひもは勝手に縮む

**縮むだけで、伸びない。**

近づいたら、**その距離が新しい長さ**になる。
一度詰めた分は戻らないので、**振り戻されても外へは出られない。**

引き（3-2A）が推進より強いので、押している限り距離は詰まっていく。
詰まればひもも短くなり、**最後は張り付く距離まで縮みきる。**

> **縮む速さを別に決めない。**
> 「どれだけ近づいたか」がそのまま縮む量なので、
> **引きの強さだけで張り付くまでの時間が決まる。** 調整するつまみが 1 つで済む。

> 「だんだん引っ張られて、最後は壁に張り付く」は**これで起きる。**
> 引く力を強めていくのではなく、**ひもが短くなる。**

### 3-4. ワイヤーがかかっている間、重力は 0

**押している間は落ちない**（2026-08-25 変更）。

毎 tick こちらから速度を与えるので、**ゲームの重力は上書きされる。**
そのうえで**下向きの加速を足さない。**

> 振り子として落とす形も試したが、**下向きが強すぎた。**
> ひもが縮む前に落ち切ってしまい、**回り込む前に地面に着く。**
>
> 落ちる勢いが要らないのは、**推進が視点の向きだから。**
> 下を向けば自分で落とせる。**落ちるかどうかも操作にする。**

離した瞬間から重力は戻る。**飛び出したあとは普通に落ちる。**

## 5. 作り

| | |
| --- | --- |
| アイテム | **`game:grapple_v2`** |
| 置き場所 | `features/grapple2/` |
| ガス | **v1 と共用**（`features/grapple/gas.ts`） |
| 配り方 | **支給品に足す。** v1 と 2 本持って持ち替える |

### v1 に入れる手は 1 つだけ

**ガスの回復を止める判断だけ、共通の置き場所に出す。**

v1 は「自分のワイヤーが無ければ回復させる」と書いてあるので、
**v2 で飛んでいる間も回復してしまう。**

`features/grapple/busy.ts` を作り、**どちらの装置を使っていても分かる**ようにする。
v1 側の変更はここを見にいく 1 行だけで、**動きは変わらない。**

### 分かっていること（v1 から）

| | |
| --- | --- |
| テレポートで動かす | **壁を貫通する。** 使わない |
| 速度を毎 tick 置き換える | **がたつく** |
| `applyKnockback` の縦 | **上向き前提。** 負の値は素直に効かない |

v2 は**下向きにも素直に加速させたい**ので、
`applyKnockback` の縦が壁になる。**ここを最初に確かめる。**
