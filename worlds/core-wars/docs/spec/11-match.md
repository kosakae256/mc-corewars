# 仕様: 試合の進行

**試合を始め、終わらせ、後片付けをする。**

ルールは [01-rules.md](../01-rules.md)。この文書は「どう作るか」。

---

## 1. 状態は3つ

```
              /game:start                /game:stop・運営主が落ちた
   非開始 ───────────────→ 開始 ←──────────────────┐
     ↑                      │                        │
     │                      │  /game:resume          │
     │                      └────────────────────────┘
     │                              一時停止
     │                                  │
     └──────────────────────────────────┘
        /game:abort ・ コアが 0（決着）
```

| 状態 | 意味 | 続きから再開できるか |
| --- | --- | --- |
| **非開始** | 何も走っていない | — |
| **開始** | 試合中 | — |
| **一時停止** | 止まっているが、**試合は生きている** | **できる** |

### 一時停止とは何か

**「止めただけ」。捨てていない。**

| 残るもの | 消えるもの |
| --- | --- |
| セッション番号 | （何も消えない） |
| **コアの残り回数** | |
| 所属チーム | |
| 盤面（置かれたブロック・チェストの中身） | |
| 持ち物 | |

`/game:resume` で**そのまま続きから**始まる。

> **これが要点。** 再開でコアが 100 に戻ったら、それは再開ではない。

### 再開のときに持ち物を空にしない

**参加処理（`joinMatch`）は持ち物を空にする。** 新規参加では正しい。
だが**再開で全員を空にすると、集めた資源が消える。**

だから再開では:

| 相手 | 何をするか |
| --- | --- |
| **既に所属がある人** | 無敵と支給品の確認だけ。**持ち物は触らない** |
| 所属が無い人（停止中に入ってきた） | 通常の参加処理（持ち物を空にする） |

### `/game:start` は一時停止中に使えない

**間違えて押すと試合が消える。**
一時停止中は拒否し、`/game:resume` を案内する。

新しく始めたいなら、先に `/game:abort` で捨てる。

## 2. 試合の中身（セッション）

**1回の試合を「セッション」と呼ぶ。** 開始時に番号を振る。

セッション番号は**途中で抜けた人を元のチームに戻す**ために使う。
番号が変われば別の試合なので、前の所属は無効になる。

```
セッション 7 で赤に入った
  → 抜けた → 戻った → セッション 7 のままなら **赤に戻る**
  → 抜けた → 戻った → セッション 8 になっていたら **入り直し**
```

### 保存先

| もの | どこに | なぜ |
| --- | --- | --- |
| 状態・セッション番号・コアの残り | **ワールドの動的プロパティ** | 少数・単純・変化が遅い（[09-state-management.md](09-state-management.md)） |
| 所属チーム・所属セッション | **プレイヤーの動的プロパティ** | 抜けても残る。戻したときに読める |
| 設置されたブロック | **メモリ** | 量が多い。試合が終われば捨てる |

> **設置ブロックだけメモリに置く。**
> 数万マスになりうるので動的プロパティには入らない。
> `/reload` で消えるが、そのときは後片付けが不完全になるだけで、
> 試合そのものは壊れない。

## 3. コマンド

| コマンド | 権限 | 何をするか |
| --- | --- | --- |
| `/game:start` | 運営 | 試合を始める（**一時停止中は拒否**） |
| `/game:resume` | 運営 | **続きから再開する** |
| `/game:stop` | 運営 | 一時停止。**片付けない** |
| `/game:abort` | 運営 | 強制終了。**片付ける** |
| `/game:status` | 運営 | いまの状態を出す |
| `/game:clean` | 運営 | 後片付けだけを行う |
| `/game:build` | オペレーター | **自分だけマップを壊せる**ようにする／戻す |
| `/game:setlobby` | 運営 | **いま立っている場所を待機所にする**（[15-presentation.md](15-presentation.md) 1章） |
| `/game:resetlobby` | 運営 | 待機所を初期値へ戻す |
| `/game:price` | オペレーター | **ショップの値段を変える**（[12-shop.md](12-shop.md) 5章） |
| `/game:shop` | 誰でも | ショップを開く（**試合中・所属あり**のときだけ） |
| `/game:regen` | 運営 | ジェネレータを探し直す |
| `/game:remember` / `/game:repair` | 運営 | マップを覚える／戻す |
| `/game:team <内容>` | **誰でも** | **味方だけに話す** |

### 名前空間は `game:` で揃える（2026-08-25 追記）

**カスタムコマンドは名前空間が必須**で、さらに
**1 つのアドオンの中では名前空間を揃えなければならない**
（`CustomCommandErrorReason.NamespaceMismatch`）。

だから遊ぶ人向けのコマンドも `/game:team` になる。
素の `/team` で登録していたので**登録に失敗し、存在しなかった。**

> **`/game:` = 運営専用、ではない。**
> 誰が使えるかは上の表の「誰が」の列で決まる。

**`/game:` で始まるものはほとんどが運営専用。**
`/game:shop` も**コマンドからは開けない**（2026-08-24 修正）。
店員に触るか、看板を押すことでしか開かない。

> **コマンドで開けると、拠点に戻る意味が消える。**
> 戦場のどこからでも買えてしまう。

`/game:clean` を分けてあるのは、**手で盤面を戻したいことがある**ため。

## 4. 後片付け

**3つを順に行う。**

| 順 | 何を | どうやって |
| --- | --- | --- |
| 1 | **設置されたブロック** | 試合中に記録した位置を空にする |
| 2 | **チェストの中身** | 範囲内のチェスト・エンダーチェストを空にする |
| 3 | 持ち物 | 全員の持ち物を消し、木の剣を配り直す |

### 4-1. 設置ブロックの記録

`playerPlaceBlock` で置かれた位置を覚える。**試合中だけ。**

> **マップを消さないために、記録した位置しか触らない。**
> 「羊毛を全部消す」のような種類での一括削除にすると、
> マップに羊毛を使った瞬間に破綻する。

### 4-2. エンダーチェスト

**エンダーチェストは中身がプレイヤーに紐づく。** ブロックを空にしても消えない。
プレイヤーごとに開いて空にする必要がある。

> **未確定:** Script API からエンダーチェストの中身を触れるか。
> 触れないなら `/clear` 相当をプレイヤーに対して行う手段を探す。

## 5. 戦闘まわり

### 5-1. 味方を殴れない

`entityHurt` の前で、**攻撃した側と受けた側が同じチームなら打ち消す。**

**同じ判断を 3 つに使う**（2026-08-25 追加）。

| 何が | どうなる |
| --- | --- |
| 味方を殴る | **通らない** |
| **味方の機体を壊す** | **通らない**（[23-drone.md](23-drone.md) 5-B） |
| **味方が点けた TNT の爆風** | **当たらない** |

> **試合の外は全部「味方」とみなす。**
> 所属は試合中にしか無い（6-Y）ので、
> 「所属が無いなら分からない」にすると**非開始中は素通り**する。

#### 味方の TNT では倒れない

TNT は**置いた瞬間に着火する**（[03-content.md](../03-content.md) 1-4）。
攻め込む味方の足元へ置けば、それだけで**味方を吹き飛ばせる。**

**ただし、点けた本人だけは食らう。**

> **投げ手側の危うさは残す。**
> 逃げ場の無い所で使えば自分が飛ぶ——
> どこで使うかという判断が消えては、ただ撒くだけの道具になる。

**誰が点けたかは、湧かすときに実体へ書く**（`features/special/tnt.ts`）。
置いた分もドローンから落とした分も同じ。
**印の無い TNT は、これまでどおり全員に当たる。**

### 5-2. 復帰直後は無敵（ノックバックはする）

**耐性（resistance）の効果を最大で 5 秒付ける。**

> **damage を打ち消す方法は採らない。** 打ち消すとノックバックまで消える。
> 奈落へ突き落とす戦術（[02-map.md](../02-map.md) 2-A-2）が
> 復帰直後の相手に効かなくなってしまう。
>
> 耐性なら**ダメージだけが 0 になり、押される力は残る。**

いつ付けるか: **開始時・途中参加時・リスポーン時。**

### 5-3. 壊れない木の剣

**独自アイテムにする。** 耐久度を持たせない。

| なぜバニラの木の剣でないか |
| --- |
| 耐久度が減って壊れる。試合中に丸腰になる |
| 攻撃力を調整できない |

- **捨てられない・素材にできない**（`ItemLockMode.inventory`）
- **枠は動かせる**（2026-08-25 変更）
- **死んでも消えない**（`keepOnDeath`）
- 配る場所は**持ち物の左端。** ただし**そこに縛らない**

> **枠ごと固定するのはやめた**（`ItemLockMode.slot`）。
> 禁じたいのは**移動手段を失うこと**だけで、
> **どの枠に置くかは持つ人の好み。**
>
> 掛け替えは**配るときに古い鍵を見つけて直す**（`features/loadout`）。
> 「既に持っている」で素通りするので、そこで直さないと一生変わらない。

いつ配るか: **開始時・途中参加時・リスポーン時。** 5-2 と同じ場面。

## 5-A. チームの決め方（2026-08-25 追加）

**開始時と途中参加で、決め方が違う。**

### 開始時は完全に運

**参加者を混ぜてから、交互に配る。**

以前は「人数の少ないほうへ」を 1 人ずつ適用していた。
これは**入室順で組が決まる**ということで、

> **毎回同じ顔ぶれが同じ組になる。**
> いつも一緒に入る 2 人は、いつも別の組（あるいは同じ組）に落ちる。
> 実力の偏りが**固定される。**

**誰がどちらへ行くかは運。** ただし**人数は必ず均等にする。**
奇数のときに余る 1 人がどちらへ付くかも、運で決める。

### 途中参加は順に見る

| 順 | 見るもの | 入れる先 |
| --- | --- | --- |
| 1 | **人数** | **少ないほう** |
| 2 | 同数なら **コアの残り** | **少ないほう**（負けている側） |
| 3 | それも同じなら | **運** |

**遅れて入る人は、傾いている側を起こす側に回す。**
人数が同じでも、削られている側は**押され続けている**ということなので、
そちらに足す。

> 3 番目を「常に赤」にしていた。
> **開始直後は必ず同数・同点**なので、
> 最初の途中参加者はいつも赤に入っていた。

## 6. 演出の余地

**いまは作らない。だが後で足せる形にしておく。**

進行の要所で**空の関数を呼んでおく。**

```
onMatchStart()   試合開始の瞬間
onMatchEnd()     決着の瞬間
onTeamWin()      勝ったチームが決まった瞬間
```

中身は今は通知だけ。あとでここにタイトル表示・音・花火を足す。

> **呼び出し口を先に用意しておく。**
> 後から差し込もうとすると、進行の途中に処理を挿すことになり、
> 状態の管理が壊れやすい。

## 6-A. アリーナ（会場）

**同じマップを別の座標にもう1つ作る可能性がある**（2026-08-24）。
そのため**座標をコードに直接書かない。**

`lib/arena.ts` に会場を並べる。**座標を書くのはここだけ。**

```
ARENAS = [
  { id: "main", label: "本会場",
    cores:   { blue: (900,0,1000), red: (1100,0,1000) },
    islands: [拠点A, 拠点B, 中央],     ジェネレータを探す範囲
    cleanup: 後片付けの範囲 }
]
```

### コアは位置で判定する

**種類（赤/青コンクリート）だけで見ない。**
装飾に同じ色を使った瞬間に誤爆する。

コアは**1ブロックで位置が決まっている**ので、位置がぴったり一致したときだけ
コアとして扱う。**どのアリーナのコアかまで分かる。**

### 増やすときに残る作業

コアの残り回数は**既にアリーナごと**に持たせてある。
足りないのは「**どのアリーナが試合中か**」だけ。
いまは試合の状態が世界に1つしかない。

## 6-B. `/reload` で壊れないようにする（重要）

**コマンドの `/reload` を打っても破綻しないこと。** これからの実装すべてに適用する。

### なぜ壊れるのか

`/reload` はスクリプトを読み直す。**メモリに持っていた値は消える。**
一方、ワールドの動的プロパティと構造物は残る。

さらに `system.beforeEvents.startup` と `world.afterEvents.worldLoad` は
**`/reload` では発火しない**（[research/02](../../../../docs/research/02-hot-reload.md)）。
そこに起動処理を置くと、**読み直したあと何も動かない。**

> 実際にこれで**マップの柵が燃えて消えた。**

### 3つの規則

| # | 規則 |
| --- | --- |
| **R-1** | **起動はトップレベルで行う。** `worldLoad` の中に置かない |
| **R-2** | **消えて困る値は動的プロパティか構造物に置く** |
| **R-3** | **メモリの値は、読み直したときに作り直せるようにする** |

### いま持っている値と、その扱い

| 値 | どこに | `/reload` で | 対処 |
| --- | --- | --- | --- |
| 開始/非開始・セッション・コアの残り | 動的プロパティ | **残る** | — |
| マップの記憶 | 構造物 | **残る** | — |
| ジェネレータの位置 | メモリ | 消える | **読み込み時に探し直す**（R-3） |
| 設置されたブロック | メモリ | 消える | **種類での掃き取りを併用**（下記） |
| 通知の間隔・実行中フラグ | メモリ | 消える | 消えても困らない |

### 設置ブロックの取りこぼしをどう埋めるか

位置の記録は数万件になりうる。動的プロパティには入らない。

**種類での掃き取りを併用する。**

```
1. 記録した位置を消す        （正確。記録が残っていれば完全）
2. アリーナの範囲内にある
   「守らないブロック」を消す （記録が消えていても効く）
```

2 が安全なのは、**ショップで売るものとマップの素材を重ねない**と
決めてあるため（[10-block-protection.md](10-block-protection.md) 2-4）。
マップに使われている素材は「守らないブロック」に入っていないので、
掃き取りで消えることがない。

> **記録が正、掃き取りが保険。** 両方やって困らない。

## 6-C. ティッキングエリア（試合中だけ張る）

**マップの範囲を、試合中だけ読み込み続ける。**

### なぜ要るのか

読み込まれていないチャンクでは、**時間が進まない。**

| 困ること | いつ起きるか |
| --- | --- |
| **ジェネレータが湧かない** | 誰もその島に居ないとき |
| **ジェネレータが見つからない** | 起動直後。走査しても 0 個になる |
| 後片付けが飛ばされる | 離れた場所のブロックとチェスト |
| マップの記憶が撮れない | `/game:remember` が失敗する |

> **一番まずいのは 2 つ目。** 起動時に 0 個だと、そのあと一生湧かない。

### なぜ常時張らないのか

**張りっぱなしは常に負荷を掛ける。** 誰も遊んでいない間もチャンクが動き続ける。
制作中や待機中に払う理由が無い。

**試合中だけ張る。**

```
/game:start
   ↓
ティッキングエリアを張る（3島ぶん）
   ↓
チャンクが読み込まれるのを待つ
   ↓
ジェネレータを探し直す        ← ここで初めて正しく見つかる
   ↓
参加処理・試合開始

/game:stop /game:abort /決着
   ↓
後片付け
   ↓
ティッキングエリアを外す
```

### やり方

`Dimension.runCommand` から `/tickingarea` を叩ける。
**restricted-execution では呼べない**ので、`system.run` の中で行う
（[imp.md](../../../../docs/imp.md) 5.1）。

```
tickingarea add <from> <to> <名前> true
tickingarea remove <名前>
```

名前は**アリーナごとに決める**（`cw_<arenaId>_<番号>`）。
外すときに名前で消せるので、消し残しが起きない。

### 待つ必要がある

**張った直後はまだ読み込まれていない。**
すぐ走査すると 0 個になる。

**見つかるまで数回やり直す。** 一定回数で諦めて、そのことを報告する。
黙って 0 個で進むと、湧かない理由が分からなくなる。

### `/reload` との関係

ティッキングエリアは**ワールドに保存される**ので `/reload` では消えない。
だが**試合中かどうかはスクリプトが持っている。**

読み直したときに試合中なら、**張り直す**（同じ名前で add し直せば重複しない）。
試合中でなければ**外す**。これで状態と実体が必ず一致する
（[6-B](#6-b-reload-で壊れないようにする重要) / R-3）。

## 6-D. 運営主が落ちたら一時停止する

**ワールドが落ちた／運営主が抜けたら、試合は勝手に止まる。**

再開したときに試合中のままだと、**誰も居ない状態で時間だけが進む。**
戻ってきた人が状況を把握できないまま試合が続いてしまう。

### 誰が運営主か

**名前では見分けない。** 名前は変わりうる。

**`/game:start` を打った人を運営主として覚える。**
プレイヤーの id（変わらない）をワールドの動的プロパティに入れる。

> 試合を始めた人が運営している、という前提。
> これなら名前が変わっても、別の人が始めても、正しく追える。

### 2つの経路で止める

| 起きたこと | どう検知するか |
| --- | --- |
| **ワールドが落ちて再起動した** | **`system.currentTick` が小さい**うちに「試合中のまま」なら止める |
| **運営主だけが抜けた**（サーバーは生きている） | `playerLeave` の id が運営主と一致したら止める |

### `/reload` では止めない（重要）

**`world.afterEvents.worldLoad` は `/reload` でも発火する。**

> 当初「`/reload` では発火しない」と書いていたが、**間違いだった。**
> そのため**スクリプトを直すたびに試合が止まっていた。**

見分けるのに `system.currentTick` を使う。**世界が動いている限り増え続ける値。**

| | `currentTick` |
| --- | --- |
| 世界が起動した直後 | **小さい**（0 から数え直す） |
| `/reload` した | **大きい**（世界は動き続けている） |

**小さいとき（10 秒以内）だけ**「落ちて再起動した」とみなす。


### 止め方は `/game:stop` と同じ

**後片付けはしない。** 盤面はそのまま残す。
運営主が戻ってきて `/game:start` すれば続きから始められる。

> 落ちたことと、試合を捨てることは別。**勝手に消さない。**

## 6-E. 再参加したときの扱い

**場所はそのまま。テレポートで動かさない。**
ただし**戦線から抜けたのなら、死亡として扱う。**

| 状況 | どうするか |
| --- | --- |
| **一時停止中に戻ってきた** | **自陣へテレポート。殺さない** |
| 試合中・**自拠点の中**に居た | **そのまま。** 持ち物も触らない |
| 試合中・**自拠点の外**に居た | **死亡させる** |
| チームが無い（新規参加） | 通常の参加処理（持ち物を空にする） |

### なぜ拠点の外だと死亡させるのか

**負けそうになったら抜ければいい、が成立してしまう。**

戦っている最中に切断して、落ち着いてから戻れば無傷で済む。
それを許すと、**劣勢のときに抜けるのが最適手**になる。

**拠点の中に居たなら、逃げたのではなく普通に居ただけ。** そのままでよい。

### なぜ一時停止中は殺さないのか

**止まっている間の出入りに罰を与える理由が無い。**
ただし場所はばらばらなので、自陣へ戻す。

### 自拠点の範囲

**拠点の島そのもの**（`lib/arena.ts` の `bases`）。
座標をここに持たせてあるので、会場が増えても付いてくる。

## 6-F. 戦闘範囲（ワールドボーダー）

**プレイヤーが行ける範囲を区切る。**

| 軸 | 範囲 |
| --- | --- |
| x | **850 〜 1150** |
| z | **930 〜 1070** |
| y（上限） | **50** |

下限は設けない。**奈落へ落ちるのはゲームの一部**（[02-map.md](../02-map.md) 2-A）。

### 上は頭で判定する

**座標は足元を指す。** 上限を足元で見ると、
**体のぶん（約 1.8 マス）まるごと天井の外に出られる。** 実際にそうなった（2026-08-24）。

y 50 は「**体のどこも 50 を超えない**」という意味にする。
足元の上限は 50 ではなく、**背丈を引いた位置**になる。

> 横の壁では起きない。体の幅は細く、多少ずれても見た目に出ない。
> **高さだけが問題になる。**

### Bedrock にワールドボーダーは無い

**組み込みのコマンドが存在しない。** 自分で作る。

| 案 | 採否 |
| --- | --- |
| バリアブロックで壁を作る | **不採用。** 300 x 140 の壁は数万ブロックになる |
| 出たら中へ戻す | **採用。** 判定は 6 回の比較で済む |
| 近づいたら粒子を出す | **採用。** バニラと同じ見た目にできる |

### 見た目はバニラと同じものを使う

`minecraft:rising_border_dust_particle` は
**バニラのワールドボーダーが使っている粒子そのもの。** 引数も要らない。

> 自前で作らない。**見慣れた見た目のほうが、境界だと伝わる。**

近づいたときだけ出す。**遠くから壁が見えていると視界が悪い。**

### 出てしまったら

**押し戻す。** テレポートで中へ移動させる。

> **殺さない。** 事故で出ることがあるし、
> 奈落へ落ちる以外で死ぬ理由を増やしたくない。

### 掃除の範囲もここに合わせる

後片付け・エンティティ掃除の範囲を、**この戦闘範囲と同じにする。**

**別々に持つと必ずズレる。** 範囲外に置かれたブロックが片付かない、
という事故が起きる。**同じ数値を 1 箇所から参照する。**

## 6-G. ブロックを置けない場所

**2 種類ある。**

| どこ | 範囲 | なぜ |
| --- | --- | --- |
| **拠点の中** | 赤 x1086〜1113 / 青 x887〜914、y -9〜6、z 985〜1015 | 埋めるとリスポーン地点やショップが塞がる |

> **内側の端は 2026-08-24 に 3 マス狭めた。** 広すぎて、
> 拠点のすぐ外まで置けなくなっていた。
> **赤と青は鏡写し**（中心 1000 から等距離）にしてある。片方だけ直さない。
| **ジェネレータの真上** | 目印を中心に 3x3、**上 4 マス** | 埋めると湧いた資源が取れなくなる |

> ジェネレータを塞ぐのは、**相手の資源を止める嫌がらせ**として強すぎる。
> 壊せば済む話にしない。

### TNT だけは拠点でも置ける（2026-08-25 追加）

**拠点で禁じたいのは「埋めて塞ぐ」こと。**

TNT は**置いた瞬間に実体になる**（[03-content.md](../03-content.md)）ので、
**ブロックとして残らない。** 塞ぐ手段にはならない。

以前は**拠点に入り込んだ TNT を消していた**が、やめた。

> **攻める側に、拠点を崩す手段を 1 つ渡す。**
> 守り一辺倒だと、拠点が「入っても何もできない場所」になる。

#### コアは爆発では消えない

コアは**守るブロックではない**（壊すことが目的）ので、
そのままだと**爆発で消し飛ぶ。**

それでは**削った回数が数えられないまま、盤面から消える。**

**爆発の対象から外す。** コアを削るのは**殴ったときだけ。**

### 置かせない。消すのは保険

置いてから消すと、**置いた本人には一瞬置けたように見える。** 手応えが嘘になる。
だから**置く前に打ち消す**のを本筋にする。

だが **`playerPlaceBlock` に `before` が無い。**
代わりに **`playerInteractWithBlock`**（＝ブロックに向けて何かを使った瞬間）を捕まえ、
触った面から**どこへ置かれるか**を計算して打ち消す。

計算が外れる場合（草など置き換え可能なブロックに重ねる）があるので、
**置かれた後に消す保険**も置く。**普段は打ち消しで止まる。**

### 編集中の人は素通り

`/game:build` で編集モードに入っている運営は、ここも通す。
**マップを直せなくなると困る。**

## 6-H. クラフトを禁止する

**作業台と手持ちのクラフトを使えなくする。** ただし**はさみだけは作れる**。

### なぜ禁止するのか

**資源はジェネレータから出て、ショップで交換する。** これが経済の骨格
（[01-rules.md](../01-rules.md)）。

クラフトができると、**ショップを通さずに物が手に入る。**
値段設定が意味を失い、経済の設計が丸ごと崩れる。

### やり方

**バニラのレシピを、同じ識別子で上書きする。**

レシピの `tags` は「どこで作れるか」を表す。
**空にすると、どこでも作れなくなる。**

```json
{
  "minecraft:recipe_shaped": {
    "description": { "identifier": "minecraft:acacia_boat" },
    "tags": []        ← ここを空にする
  }
}
```

対象は **`crafting_table` タグを持つ 1180 件**。

| 手段 | 採否 |
| --- | --- |
| ゲームルール `doLimitedCrafting` | **不採用。** 「解放済みのレシピだけ作れる」であって、禁止ではない |
| 作業台を触れなくする | **不採用。** 手持ちの 2x2 が残る |
| **レシピを上書きする** | **採用。** 作業台も 2x2 も同時に塞げる |

### はさみだけ残す

`minecraft:shears` は上書きしない。

> **なぜ必要か決めていない。** 使い道が決まったら、ここに理由を書く。

### 生成する

手で 1180 件は書けない。**`tools/gen-no-craft.mjs` が作る。**

バニラのレシピを読み、**識別子と種類だけを写して `tags` を空にする。**
Minecraft の版が上がってレシピが増えたら、**動かし直すだけ**で追従できる。

## 6-Y. 所属があるのは試合中だけ（2026-08-25 追加）

**開始していないときは、誰もどのチームにも所属していない。**

| いつ | 所属 |
| --- | --- |
| 非開始（ロビー） | **無い** |
| 開始処理の途中（チーム分け以降） | **決まる** |
| 試合中・一時停止中 | ある |
| **通常終了・強制終了**のあと | **無い** |

途中参加したときも、その場で決まる。

### ロビーの見張りは「非開始」の間だけ

**チーム分けから開始までの 10 秒は、まだ「非開始」扱い**（7 章）。
その間もロビーの見張り（`features/lobby`）を回していた。

見張りは**帽子を「前の試合の名残り」と見なして**持ち物ごと戻すので、
**所属まで消えていた。** 開始の瞬間には無所属になっていて、
**戦場へ送られなかった**（2026-08-25 の「試合開始してもテレポートしない」）。

**開始処理に入ったら、ロビーの世話はしない。**
そこから先は `features/match` の持ち場。

| 状態 | ロビーの見張り |
| --- | --- |
| `idle` | **回す** |
| `preparing` / `running` / `paused` / `finished` | **回さない** |

### 読むところで断つ

**覚えている値を消すだけでは足りない。**

抜けている間に試合が終わった人は、次に入ってきたときに
**古い所属を持ったまま**になる。実際、
**ロビーに居るのにチームが赤**になっていた（2026-08-25 の指摘）。

`teamOf` が**非開始なら必ず `undefined` を返す。**
消し忘れの経路があっても、読む側から見れば所属は無い。

### 戦績には控えを持つ

所属が消えると、**終わったあとの戦績に色が付かない。**

数えた時点の所属を `lib/stats.ts` が別に控えておく。
**表示のための記録**であって、所属そのものではない。

## 6-Z. フェーズ（2026-08-25 追加）

**試合は 2 つの段に分かれる。**

| | 長さ | コア破壊 |
| --- | --- | --- |
| **フェーズ 1** | **5 分** | **禁止** |
| **フェーズ 2** | **終わりなし** | **許可** |

### なぜ分けるのか

**開幕から削りに行けると、資源を集める意味が薄い。**

始まってすぐ相手のコアへ突っ込むのが最適手になると、
ジェネレータもショップも**使う前に試合が動いてしまう。**

**最初の 5 分は、整える時間。**
資源を集め、装備を買い、位置を取る。
そのうえで削り合いに入る。

### 数え始め

**戦場へ送った瞬間**から数える。
カウントダウンの間は含めない（まだ動けない）。

### 知らせ方

| いつ | どうするか |
| --- | --- |
| 常時 | **サイドバーに残り時間**を出す |
| 残り 60 秒 / 30 秒 | **チャットに 1 行**（2026-08-25 追加） |
| 切り替わり | **タイトルと音**。「コアを削れます」 |

**黙って切り替えない。** 削れるようになった瞬間が試合の山場なので、
全員が同時に気づく必要がある。

#### 画面は割り込ませない（2026-08-25 変更）

**5〜1 秒のカウントダウンはしない。**

以前は残り 5 秒から画面いっぱいの数字と音を出していたが、やめた。

> **試合の最中に割り込む。**
> フェーズ 1 は資源を集めて位置を取る時間で、
> **プレイヤーは手を動かしている最中。**

**残り時間は常にサイドバーに出す**
（[15-presentation.md](15-presentation.md) 5 章）。
知りたい人はいつでも右を見れば分かる。

**チャットは 60 秒前と 30 秒前の 2 回だけ**（2026-08-25 追加）。
サイドバーを見ていない人にも、**そろそろだと伝わる必要がある。**
チャットは手を止めさせないので、**この 2 回は割り込みにならない。**

切り替わりの瞬間だけは、タイトルと音で知らせる。
**そこは全員が同時に知る必要がある**ので、割り込む価値がある。

### 禁止のされ方

**削ろうとしたら理由を出す。**
[13-grapple.md](13-grapple.md) 7 章の「移動直後は削れません」と同じ形で、
**あと何秒でフェーズ 2 になるか**を添える。

黙って効かないと、**壊れていると思われる。**

### 一時停止したら

**止まっている間は数えない。** 再開したところから続く。

## 7. 開始の流れ

**打った瞬間に始めない。** プレイヤーから見える順番を決める。

```
[ロビー] 「ゲームを開始します」＋ 目的をチャットに流す
    ↓  10 秒          ← この間なら参加・非参加を切り替えられる
チーム分け                    ← ここで「参加した」ことになる
           ＋ 誰がどちらかをチャットに出す
    ↓  5 秒
5 … 4 … 3 … 2 … 1
    ↓  （合わせて 10 秒）
「スタート」 ＋ 同時に自陣へテレポート
```

### 7-A. 前後に 10 秒ずつ置く

**押した瞬間に締め切らない**（2026-08-25 変更）。

以前は 1 秒でチーム分けしていたので、
**開始が押されたことに気づいた時にはもう決まっていた。**
参加するつもりが無いのに入る、入りたいのに入れない、が起きる。

| 区間 | 長さ | 何のための時間か |
| --- | --- | --- |
| 開始 → チーム分け | **10 秒** | **参加・非参加を選び直す** |
| チーム分け → スタート | **10 秒** | 自分のチームと相手を確かめる |

後半の 10 秒のうち、**最後の 5 秒がカウントダウン**になる。
5 カウントの見せ方は変えない。

### 7-B. チーム分けした瞬間に名簿を出す

**誰がどちらに入ったかを全体チャットへ出す。**

自分の所属は本人に伝わるが、**相手が誰かは全体に出さないと分からない。**
チーム分けの瞬間に一度だけ、青・赤の順に人数と名前を並べる。

### 7-0. 参加ルールは流さない

**同意は入室時と参加の切り替え時に済ませてある**
（[16-participation.md](16-participation.md) 1-3）。

毎回流すと**読み飛ばされるだけ**で、同意の重みも薄れる。
代わりに**この試合で何をするか**を、いちばん最初（猶予の始め）に出す。

### 7-1. 「チーム分け」が参加の瞬間

**この時点で参加処理が全部走る。**

| 走るもの | なぜここか |
| --- | --- |
| チームの割り当て | — |
| **エンダーチェストを空にする** | 持ち込みを許さない |
| 持ち物を空にする | 同じ |
| **サバイバルに直す** | 下記（2026-08-25 追加） |
| ~~支給の資源~~ | **ここでは配らない。** 戦場へ着いてから |
| **ジェネレータの探索** | **テレポート後だと湧き始めが遅れる** |
| **ショップの店員を立てる** | 同じ |
| 帽子を着せる | — |

#### モードを直す（2026-08-25 追加）

**アドベンチャーのまま試合に入ってくる人が居る。**

アドベンチャーでは**ブロックを壊せず、置けない。**
資源も集められず、ショップで買った建材も使えない——
**戦場に立っているだけで何もできない。**

本人は気づかない。**何をしても効かないだけ**で、理由がどこにも出ない。

| 入るときのモード | どうするか |
| --- | --- |
| サバイバル | そのまま |
| **アドベンチャー** | **サバイバルに直す** |
| **スペクテイター** | **サバイバルに直す**（倒れたまま抜けた人） |
| クリエイティブ | **そのまま**（運営が意図して入っている） |

**クリエイティブだけは触らない。**
運営が見ながら回していることがあり、勝手に落とすと**そちらの邪魔になる**
（[19-admin-menu.md](19-admin-menu.md) 3 章と同じ扱い）。

**テレポートしてから始めると、着いた瞬間に何も動いていない。**
先に動かしておけば、着いたときには揃っている。

### 7-2. テレポートは「スタート」と同時

**カウントダウン中はロビーに居る。**
先に戦場へ送ると、始まる前に動けてしまう。

#### 配るのは着いてから

**3D Maneuver Gear も、支給の資源も、テレポートの後。**

ロビーで装備が揃うのは順番がおかしいし、
カウントダウン中に持っていると**始まる前に飛び出せる。**
着いた瞬間に手元が整うほうが、始まった感じが出る。

### 7-3. 抜けた人が戻ったら

**チーム分けの後に抜けた人は、戻ったときに戦場へ送る。**

所属はセッションに紐づいている（2章）ので、
**同じセッションなら元のチームに戻る。**
違うセッションなら所属は自然に外れる。

### 7-4. 支給の資源

| | 量 |
| --- | --- |
| 鉄 | **32** |
| 金 | **16** |

**開始から居た人だけ。** 途中参加は受け取らない。
遅れて入るほうが得になってはいけない。

### 7-5. 掃除が終わっていなければ始めない

**前の試合の後片付けが動いている間は開始を拒否する。**

途中で始めると、**始めたあとに片付けが走って新しい試合の物を消す。**

## 8. 後片付けで消すもの

**プレイヤーが置けるブロックだけを消す。**

| 消す | 消さない |
| --- | --- |
| ショップで買えるブロック | **マップのブロック全部** |
| **アイテムが生む**ブロック（支柱弾など） | 運営が直したブロック |

### なぜ一覧で決めるのか

以前は「置けそうなブロックの種類」で掃き取っていたため、
**運営が編集したブロックまで消えていた**（2026-08-24 の指摘）。

**置ける物の一覧は既にある**（[12-shop.md](12-shop.md) の品揃え）。
そこから作れば、**買える物が増えても自動で追従する。**

## 9. マップの常時読み込み（手で設定する）

**戦闘範囲を丸ごと常時読み込む。** これが無いと後片付けもジェネレータも壊れる。

### 打つコマンド

```
/tickingarea add 850 0 930 1009 0 1070 cw_main_0 true
/tickingarea add 1010 0 930 1150 0 1070 cw_main_1 true
```

`/game:ticking` を打てば、**いまの座標から組み立てて表示する。**
手で書き写して食い違うことがない。

| | |
| --- | --- |
| y | **0 でよい。** チャンクの柱ごと読むので高さは関係ない |
| 末尾の `true` | preload。ワールド起動時から読み込まれる |
| 保存 | **ワールドに残る。** 一度打てば済む |

### スクリプトからは作れない

**`Dimension.runCommand("tickingarea add ...")` は作らない**（2026-08-25 実測）。

**例外も投げず、`successCount` も 0 より大きい値を返すのに、実際には作られない。**
同じコマンドをプレイヤーが手で打つと作られる。

> ここで長く時間を溶かした。**「例外が出ない」は成功の証拠にならない。**
> 現物（`/tickingarea list`）を見るまで、張れたと判断してはいけない。

### `tickingarea list` に何も出ないとき

**`sendCommandFeedback` が切れている。**

| 種類 | false のとき |
| --- | --- |
| エラー（「既に存在する」など） | **出る** |
| 成功時の出力（`list` の一覧） | **出ない** |

```
/gamerule sendcommandfeedback true
```

「エラーは出るのに一覧が出ない」なら、まずこれを疑う。

### 島だけでは足りない

以前は 3 つの島だけを張っていた。**島の外が読み込まれず、**

- 後片付けが素通りする（チェストの数が毎回変わる）
- ジェネレータの数が `/reload` のたびに変わる

**読めない場所は「何も無い」と同じ扱いになる。**
数えた結果が毎回違うなら、まず読み込みを疑う。

### 部分的な結果は結果ではない

読めなかったマスを**数えて、残っていればやり直す。**

| 処理 | やり直し |
| --- | --- |
| 後片付け | 3 回まで。3 秒待って再走査 |
| ジェネレータの探索 | 見つかる**かつ**全部読めるまで |

---

| --- |
| ジェネレータが見つからない | 外している間はチャンクが読み込まれていない |
| 張った直後も見つからない | 読み込みが間に合わない |
| 「1 つも見つかりません」が流れ続ける | 自動で探し直すたびに 0 個 |

**張りっぱなしなら、いつ探しても見つかる。**
3 つの島ぶんの負荷は、この確実さと引き換えにする価値がある。

> これで 6-C の「試合中だけ張る」は撤回。
> **状態と実体を合わせる必要も無くなった**（常に張っている）。

## 10. 再開は募集ではない

**`/game:resume` は、所属のある人を戻すだけ。**

以前は所属の無い人もその場で参加させていたが、
**止まっている間にロビーで見ていただけの人まで引き込んでいた**
（2026-08-24 の指摘）。

入りたい人は[ロビーの `[参加]` 看板](16-participation.md)から入る。
**参加は必ず本人の操作で始まる。**
