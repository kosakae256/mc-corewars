# 仕様: 遊べる状態に仕上げる

**ルールは動いている。足りないのは「伝わること」。**

いま何が起きたのか、次に何をすればいいのかが、
**画面を見れば分かる**状態にする。

関連: [11-match.md](11-match.md)（進行）・[14-death.md](14-death.md)（死亡）

---

## 1. 待機所

**試合をしていないとき、どこに居るか**を決める。

| 状態 | 居場所 |
| --- | --- |
| 非開始 | **待機所** |
| 開始した瞬間 | **自陣のリスポーン地点へ移す** |
| 一時停止中 | 自陣の建物の中（[11-match.md](11-match.md) 6-H） |

### なぜ要るのか

決めておかないと、**前の試合が終わった場所に散らばったまま**になる。
相手の拠点の中に居座ることもできてしまう。

### ロビーは戦場の外

**初期スポーン地点は (0, 100, 0)。**

戦場（x 850〜1150）とは離れた場所に置く。
**同じ島の上に置くと、試合をしていない間も戦闘範囲の中に居ることになり、
外へ出られない。**

| 状態 | 行ける範囲 | 外に出たら |
| --- | --- | --- |
| 試合中 | 戦闘範囲（x 850〜1150 / z 930〜1070 / y ≤ 50） | **押し戻す** |
| 一時停止中 | 自陣の建物の中 | 自陣へ戻す |
| **非開始** | **ロビーの周り**（x/z −50〜50 / y 0〜300） | **ロビーへ送る** |

> **上は 300 まで**（2026-08-25 変更）。
> 150 だと**ワイヤーで少し上がっただけで範囲の外**になり、
> ロビーへ引き戻されていた。**ロビーは練習する場所でもある**
>（[13-grapple.md](13-grapple.md) 6 章）。

### 領域は 2 つ同時に存在する

**試合中でも、場に居る人と居ない人が同時に居る。**

| 状態 | 所属 | 領域 | 外に出たら |
| --- | --- | --- | --- |
| 試合中 | あり | 戦闘範囲 | 押し戻す |
| **一時停止中** | あり | **自陣の建物の中** | 自陣へ戻す |
| 準備中 | あり | **ロビー** | ロビーへ送る |
| いつでも | なし | **ロビー** | ロビーへ送る |

**一時停止中も「戦場に居る」扱い。**
盤面を残したまま止めるのが一時停止なのだから、
**人も残っていなければ意味が無い。**

> ここを `isRunning()` だけで見ていたため、
> 一時停止した瞬間に全員がロビーへ飛ばされていた（2026-08-24）。
> 運営が落ちて自動で止まったときも同じ。

### 所属の有無では決めない

**「戦場へ送り出したか」で決める。**

チーム分けは開始の 1 秒後、戦場へのテレポートは 7 秒後。
**その間、所属はあるがロビーに居る**という状態がある。

ここで「所属がある = 戦場に居る」と決めつけると、
**ロビーに居る人に戦闘の境界が当たり、端へ飛ばされて落ちる。**
実際にそれで死んだ（2026-08-24）。

> 状態ではなく**事実**を持つ。
> 送り出した瞬間に立て、ロビーへ戻した瞬間に下ろす。

### 支給品は試合中も配る（2026-08-25 修正）

**ロビーに居て、試合に出ていない人には、いつでも支給品を配る。**

以前は**試合が始まった時点でロビーの世話をやめていた。**
そのせいで、

| 誰 | どうなっていたか |
| --- | --- |
| **試合中にワールドへ入ってきた人** | ロビーに居るのに**手ぶら** |
| **観戦から戻った人** | 同じく**手ぶら**（[20-spectate.md](20-spectate.md)） |

ロビーの装備は**練習のためのもの**（[13-grapple.md](13-grapple.md) 6 章）。
**試合をしているかどうかとは関係が無い。**

#### 止めたかったのは「出ている人に手を出すこと」だけ

やめた理由は、`preparing`（チーム分けから開始までの 10 秒）で
**帽子を「前の試合の名残り」と見なして所属ごと消していた**こと
（[11-match.md](11-match.md) 6-Y）。

**時間で外すのではなく、所属で外す。**

- **所属がある人**（＝試合に出ている人）には触らない
- **名残りを落とす**のは非開始のときだけ。
  試合中に落とすと、**運営がスペクテイターで見て回っている**のを
  名残りと見なして生存に戻してしまう

### 非開始は押し戻さない

**ロビーの外には何も無い。** 際で止めても意味が無いので、
**ロビーへ送り返す。**

戦闘中は「際で止める」のが正しい。戦っている最中に飛ばされると、
何が起きたか分からないまま位置を失う。
**外に何もない場所では、逆に送り返すほうが親切。**

### 場所は後から決められる

**座標を決め打ちにしない。**
`/game:setlobby` で、いま立っている場所を待機所にできる。

> マップを見ずに座標を決めると、**壁の中や奈落の上**を指しかねない。
> 実際に立ってから決めるほうが確実。

初期値は中央島の上空。**必ず設定し直すこと。**

## 1-B. 遊び方の絵（2026-08-25 追加）

**ロビーの壁に、画面の見かたを描いた絵を掛ける。**

実物は [`docs/images/lobby-guide.png`](../images/lobby-guide.png)。
実際の画面を撮ったものに、番号付きで説明を書き足してある。

| | 何を指しているか |
| --- | --- |
| ① | ワイヤー射出装置（1 枠目） |
| ② | ガスの残り（足元の行） |
| ③ | 撃ったワイヤー |
| ④ | コアの残り（右のスコアボード） |
| ⑤ | ロビーの看板 |

### なぜ文字ではなく絵なのか

**どれがどれか、が伝わらない。**

看板（[16-participation.md](16-participation.md) 4 章）は文章なので、
「足元の水色のゲージがガス」と**書いても、画面のどこかは分からない。**

**指させるのは絵だけ。**

### どうやって出すか（2026-08-25 変更）

> ### 絵画をやめた。**ブロックで建てる。**

**絵画はサバイバルで壊せた。**

絵画は**ブロックではなく実体**なので、ブロックの保護が届かない。
ダメージを打ち消す形で守ったが、**それを通らずに消える経路があった。**

| 試したこと | 結果 |
| --- | --- |
| ダメージを打ち消す | **効かない** |
| 実体の削除を打ち消す | **打ち消せない**（そういう仕組みが無い） |
| 絵画の定義を差し替える | **バニラに定義が無い** |

**ブロックなら掘れなくできる。** 遊ぶ人に壊されようが無い。

#### 1 つの種類に、32 の状態

絵を **8 × 4 に切って**、タイルごとに違う面を出す。

**種類を 32 個作らない。** 状態（`game:tile`）で出し分ける。
種類を増やすと、**足すたびに定義が増えて追えなくなる。**

| | |
| --- | --- |
| ブロック | `game:guide` |
| 大きさ | **横 8 マス × 縦 4 マス** |
| 絵 1 枚あたり | 128 × 128 |
| 掘れるか | **掘れない**（`destructible_by_mining: false`） |
| 爆発 | **壊れない** |

#### 建てるのはコマンドから

**`/game:guide`**（運営のみ）。

**立っている場所の 3 マス前**に、**見ている向きへ正対して**建つ。
向きは東西南北に丸める（斜めには建てない）。

32 枚を手で並べるのは現実的でないので、**一息に建てる。**

## 2. 試合開始のカウントダウン

```
3 … 2 … 1 … 開始！
```

**開始のコマンドを打った瞬間に始めない。**

打った人以外は、いつ始まったか分からない。
**全員が身構える時間**を作る。

| 秒 | 何が出るか |
| --- | --- |
| 3・2・1 | 大きく数字。**音が鳴る** |
| 0 | 「開始！」・**高い音** |

数える間は、**自陣から動けるが攻撃は当たらない**（無敵のまま）。

## 3. 倒れてから戻るまで

**5 秒を数える**（[14-death.md](14-death.md)）。

| 見えるもの | |
| --- | --- |
| 大きく残り秒数 | **あと何秒か**が一目で分かる |
| 誰に倒されたか | 副題に出す |
| 音 | 1 秒ごとに低い音、復活で高い音 |

**待たされている時間を、待っていると分かる形にする。**
何も出ないと「固まった」と思われる。

## 4. 手応えを出す

### 4-1. 倒した / 倒された

| | 倒した側 | 倒された側 |
| --- | --- | --- |
| 音 | **高く短い音**（当てた実感） | 低い音 |
| 画面 | **「☠ 相手の名前 を倒した」** | 「§c倒された」 |
| その場 | — | **粒子が弾ける** |

**誰をどう倒したのかを出す**（2026-08-25 変更）。
「倒した」だけでは、**乱戦で誰を倒したのか分からない。**

| 倒し方 | 出るもの |
| --- | --- |
| 殴った | 「を倒した」 |
| 奈落 | 「を奈落に落とした」 |
| 落下 | 「を落とした」 |

名前は相手の所属の色にする。チャットのキルログと**同じ見た目**にして、
見比べなくても同じ出来事だと分かるようにする。

### 4-1-A. 連続で倒したら知らせる（2026-08-25 追加）

**5 人続けて倒すごとに、チャットに出す。**

```
⚔ ばーど 5キルストリーク！
```

**名前と数だけ。**（2026-08-25 変更）
以前は「が 5 連続で倒しています」という文にしていたが、
**流れるチャットの中では長い。** 数が主役なので、そこだけ残す。

#### なぜ

**止められていないことを、止められる側に伝える。**
誰が荒らしているのか分からないままだと、**誰も止めに行かない。**

**区切りでだけ出す。** 毎回出すとキルログと二重になる。

#### 引き継がない

| | |
| --- | --- |
| 倒された | **0 に戻る** |
| 試合が変わった | **0 に戻る** |

セッション番号に紐づけて持つ（[stats](11-match.md) と同じ作り）。
**メモリには持たない。** `/reload` で消えると、
**試合の途中で全員のストリークが飛ぶ。**

### 4-2. コアを削った

**削るたびに音と粒子。** 手応えが無いと、削っている実感が湧かない。

| 残り | 何が起きるか |
| --- | --- |
| 毎回 | 音・粒子・削った本人に残り回数 |
| **50 / 25 / 10 / 5** | **全体に告知** |
| **1〜3** | **全体に告知＋警告音** |

**節目でだけ全体に出す。** 毎回出すと流れて読めない。

### 4-3. 決着

**4 段構えで見せる**（2026-08-24 決定）。

```
コアが 0 になる
  ↓  すぐ
勝敗をタイトルで表示・音・大爆発
  ↓  3 秒
マップ中央（1000, 20, 1000）付近へ全員テレポート（8 マスほど散らす。**全員が勝った側の拠点を向く**）
勝った側から花火を大量に打ち上げる
**花火の間に、戦績を 1 塊ずつチャットへ流す**
  ↓  10 秒
ロビーへテレポート
```

#### なぜ中央へ集めるのか

**勝った側と負けた側が同じ場所に立つ。**
拠点に散らばったまま終わると、勝った実感も負けた実感も出ない。

**散らす**のは、重なって埋まるのを避けるため。

#### 花火は勝った側から上がる

**誰が勝ったかを、文字を読まずに分かるようにする。**

##### 花火は自前で作る（2026-08-25 変更）

**`fireworks_rocket` を湧かせても何も起きない。**

バニラの花火の実体は `physics` を持つだけで、
**飛ぶのも開くのも、打ち上げたときのアイテムの中身が決めている**
（`reference/bedrock-samples/behavior_pack/entities/fireworks_rocket.json`）。
素で湧かせると**その場に落ちるだけ**で、開かない。

粒と音で組み立てる。

| | |
| --- | --- |
| 昇る | 拠点のコアの 10 マス上から、**28 マスを 20 tick で昇る** |
| 筋 | `sparkler_emitter` ＋ `glow_particle` |
| 開く | 球状に 36 粒。**青は `blue_flame_particle`、赤は `basic_flame_particle`** |
| 明るさ | 3 粒に 1 粒を色の粒、残りを `totem_particle`。**色だけだと遠くから見えない** |
| 音 | `firework.launch` → `firework.large_blast` ＋ `firework.twinkle` |

###### 全員が勝った側を向く（2026-08-25 追加）

中央へ集めるとき、**勝ったチームの拠点のほうを向かせる。**

円状に散らすので、向きを揃えないと**全員がばらばらの方を見ている。**
花火が上がるのも勝った側の拠点なので、
**そちらを向いていれば、振り向かなくても目に入る。**

拠点そのものではなく**少し上**（+24）を向かせる。
拠点は 100 マス以上先にあるので、真っ直ぐ向くとほぼ水平になり、
**花火が上がる高さが画面の外に出る。**

###### 尾に煙を使わない（2026-08-25 変更）

はじめは焚き火の煙を尾に敷いていたが、
**灰色の塊が浮いているだけ**に見えた。

火花と光の粒に替える。どちらも**明るく、すぐ消える。**
**尾として残らない**ので、「昇っている」ことだけが伝わる。

**中央（y 20）から見上げられる高さまで昇らせる。**
拠点は 100 マス離れているので、低いと島に隠れて見えない。

### 4-4. 戦績

**花火が上がっている間に、チャットへ 1 塊ずつ流す**（2026-08-25 変更）。

| 出すもの | |
| --- | --- |
| 両チームのコア残数 | どれだけ competitive だったか |
| **コアを削った回数** の上位 | 攻めた人 |
| **倒した数** の上位 | 戦った人 |
| **K/D** の上位 | 落ちなかった人 |
| **MVP** | 上の 3 つを合わせた点 |

#### なぜ 1 塊ずつなのか

**まとめて出すと、15 行が一気に流れて誰も読まない。**

塊（勝敗 → コア破壊 → キル → K/D → **MVP**）の単位で、
**1.5 秒おきに 1 つずつ**出す。次が来たことに気づけるよう、
1 つごとに通知音（`random.toast`）を鳴らす。
**MVP と締めだけ `game.levelup`** に変えて、そこが終わりだと分かるようにする。

> **`random.levelup` は黙らせてある**（2026-08-26）。
> マナを経験値の段に出しているので、**戻るたびに鳴ってしまう**ため。
> **同じ音の実体を `game.levelup` として別に持っている**
>（`resource_packs/game/sounds/`）。

順番は**盛り上がる順。** MVP を最後に置く。

#### タイトルには出さない

**画面の真ん中に順番に出すと、前のものを上書きして消える**（2026-08-25 変更）。
読み逃したら戻れない。**チャットなら遡れる。**

ロビーへ戻ったあとは出し直さない。二重になるだけなので、
`/game:result` で見返せることだけ伝える。

#### MVP の決め方

**コア 3 点・キル 1 点・デス −1 点。**

コアを削るのが勝利条件なので、**そこに最も重みを置く。**
キルは手段でしかない。

### 4-5. 前の試合の戦績はロビーの掲示板に出す

**サイドバーには出さない**（2026-08-25 変更）。

以前はロビーのサイドバーに前回の上位 6 人を並べていたが、

> **試合が始まっても残っていた。**
> 行を消さずに書き足していたので、コアの残りと前の試合の戦績が
> **同じ盤面に混ざる。**
>
> そもそも**個人の点数はここに出すものではない。**
> サイドバーは**いま何が起きているか**を出す場所。

**振り返りは掲示板に出す**（下の 4-6）。

### 4-6. ロビーの掲示板（2026-08-25 追加）

**ロビーの空中に、前回の各部門の 1 位を並べる。**

```
        ─── 前回の記録 ───

   ★ MVP      ばーど      コア 12 ・ キル 8 ・ デス 3
   コア破壊    ばーど      12 回
   キル       あかね      15
   K/D        そら        4.50
```

| | |
| --- | --- |
| 場所 | **`0.5, 112, -12`**（マスの中央に置く。高さは 110 では低すぎた） |
| 読む位置 | **`0, 110, 0`** から見える |
| 中身 | **部門ごとの 1 位。** チャットに流す戦績と同じ部門 |

#### なぜ空中に浮かせるのか

**看板では入らない。** 看板は 4 行しか書けず、色も付かない。

**ブロックを積んで作る手も採らない。**
文字を作るには面積が要るし、直すたびに建て直すことになる。

`DebugText`（`@minecraft/debug-utilities`）なら、
**壁越しに描け、遠くから読め、書き換えるのは文字列の差し替えだけ。**
頭上の表示（7-3-A）で既に使っている仕組みをそのまま使う。

#### 向きは固定する（2026-08-25 変更）

**`x, z = 0, 0` の方を向いたまま動かない。**

一度はカメラ追従（常に読む人のほうを向く）にしたが、やめた。

> **板ではなく、ついて回る文字になる。**
> 掲示板は**そこに掛かっているもの**で、
> 近づくと向きが変わるのでは、掛かっているように見えない。

裏に回ると読めないが、**掲示板とはそういうもの。**
読む場所は `0, 110, 0` 側だと決まっている。

`DebugText` の `useRotation` を立て、`rotation` の向き（yaw）で決める。

#### 箱は 1 つ（2026-08-25 変更）

**行ごとに 1 つ作らない。** 改行を含めた 1 つの文字列にする。

行ごとに作っていたので、**板が行数ぶん並んでいた。**
間隔も自分で決めることになり、詰まったり離れたりする。

##### 無理にそろえない（2026-08-25 変更）

**空白を足して頭をそろえようとしない。**

一度は各行の幅を空白で埋めてそろえていたが、やめた。

> **字の幅が等幅ではない**（7-3-A の「幅をそろえる」と同じ事情）。
> 全角 2・半角 1 として数えても**そろわない。**
> そろえたつもりの空白だけが残る。
>
> **全角空白は表示そのものが崩れる。** 使わない。

**そのまま並べる。** 箱の中で各行がどう寄るかは、向こうに任せる。

#### いつ書き換わるか

**試合が終わった瞬間。**

その時点の各部門の 1 位を**世界に控えておく**（`cw:last_awards`）。
次の試合が始まると個人の戦績は 0 に戻るので、
**控えておかないと、始まった瞬間に掲示板が空になる。**

`/reload` でも消えない。控えたものから描き直す。

#### 何も無いとき

**まだ 1 試合も終わっていないなら、その旨を出す。**
黙って何も出さないと、**壊れているのか、まだ無いのかが分からない。**

## 5. 常に見える表示

**サイドバーにコアの残りを出す。**

```
     ── Core Wars ──
     フェーズ2まで  187
     赤チーム       100
     青チーム        98
```

**試合中だけ出す。** 終わったら消す。

**ここに出すのはこの 3 行だけ。**（2026-08-25 変更）
個人の点数は出さない。**いま何が起きているか**を出す場所で、
振り返りを混ぜると、**どちらの数字なのか分からなくなる。**

> どちらが優勢かを、**聞かなくても分かる**ようにする。
> これが無いと、削った本人しか状況を知らない。

### フェーズ 2 までの残り秒（2026-08-25 追加）

**フェーズ 1 の間だけ、残り秒数の行を出す。**
フェーズ 2 に入ったら**行ごと消す**（0 が残っていると、まだ何かを待っているように見える）。

> ここが**残り時間を知る唯一の場所**になった。
> チャットの読み上げもカウントダウンもやめた
>（[11-match.md](11-match.md) 6-Z「数え上げない」）ので、
> **出しっぱなしのこれが無いと、いつ削れるようになるのか誰にも分からない。**

**行の並び順は点数で決まる**（多いほうが上）。
残り秒はコアの残り（最大 100）より大きいところから減るので、
**残り 100 秒を切ると、チームの行より下に移る。**
これは Bedrock のサイドバーの仕組みで、避けられない。
順番を固定するには秒数を点数として出すのを諦めるしかないので、**数字が読めるほうを取る。**

## 5-A. 裏方の報告は運営にだけ出す（2026-08-25 追加）

**遊ぶ人のチャットに、道具の都合を流さない。**

片付けの進み具合、走査した数、読めなかったマス数——
これらは**運営が様子を見るためのもの**で、遊ぶ人には意味が無い。

> 流れていると**画面が汚い。**
> 大事な報せ（コアが削られた、誰が倒れた）が押し流される。

### どちらに出すか

| 中身 | 誰に |
| --- | --- |
| 試合の出来事（コア・撃破・勝敗・開始と終了） | **全員** |
| 裏方の報告（片付け・走査・復元・読み込み） | **運営だけ** |

「運営」は**オペレーター権限を持っている人**。名前では決めない
（[11-match.md](11-match.md) 6-D の教訓）。

### 頼んだ人には必ず返す

`/game:clean` のようにコマンドで頼んだ場合は、
**頼んだ本人に返す**（運営でなくても）。押した反応が無いほうが困る。

| 誰が起こしたか | 出す先 |
| --- | --- |
| コマンドで頼まれた | **頼んだ本人だけ** |
| 自動で走った | **運営全員** |

### 読み込みの報せ

`/reload` とワールド読み込みの報せは**両方に出す。分ける。**

| 誰 | 中身 |
| --- | --- |
| 遊ぶ人 | `Core Wars 読み込みました` だけ |
| 運営 | 状態の確認方法まで（いまのまま） |

**動いていることは全員に伝える。** 黙って切り替わると、
直っているのかどうかが分からない。

## 7. プレイヤーの見た目

### 7-1. 名前を出さない

**頭の上の名前を消す。**

名前が見えると、**壁の向こうの相手まで分かってしまう。**
隠れる意味が無くなり、位置取りが成立しない。

> **運営は常時表示に切り替えられる**（2026-08-28 追加）。
> 設定メニュー → ルール調整 → **頭上の表示を常に出す**
>（[19-admin-menu.md](19-admin-menu.md) 9-A）。
> **普段は切**。少人数での確認や、教えるときのためのもの。

### 7-2. 帽子でチームを示す

**常に自陣の色の帽子をかぶる。**

| | |
| --- | --- |
| **防御力** | **+5**（2026-08-26 変更。0 から） |
| 落ちるか | **落ちない** |
| 外せるか | **外せない** |
| 他の頭装備 | **着けられない** |

> **守りに関係しない、はやめた**（2026-08-26）。
> 頭の枠は帽子で埋まっていて**兜を買えない**ので、
> **その枠のぶんだけ、全員が薄い**状態だった。
>
> 帽子に持たせれば、**買う防具は胴・脚・足の 3 点**という前提のまま、
> 頭のぶんが戻る。

名前が無くても**色で敵味方が分かる。**

#### 専用の装備を作る（2026-08-25 変更）

**革の帽子を染めたものでは条件を満たせない。**

| 困ること | |
| --- | --- |
| 防御力が 1 で固定 | **こちらで決められない**（いまは +5 にしてある） |
| **耐久がある** | 殴られ続けると**試合中に壊れて消える** |
| 色が濁る | 染料の色は暗く、遠くから見分けにくい |

だから**独自アイテムにする。**

| | |
| --- | --- |
| id | `game:hat_red` / `game:hat_blue` |
| 防御力 | `minecraft:wearable` の `protection`（**いまは 5**） |
| 耐久 | **`minecraft:durability` を付けない** = 無限 |
| 色 | `minecraft:dyeable` の `default_color`（赤 `#FF1A1A` / 青 `#2A5CFF`） |
| 見た目 | **バニラの革の帽子をそのまま借りる** |

> **attachable が無いと、着けても何も見えない。**
> 独自アイテムは「装備できる」だけで、
> **描き方は resource pack 側で別に指定する必要がある。**
> プレイヤー用（`geometry.player.armor.helmet`）も併せて置く。

##### 形はバニラから借りる（2026-08-25 修正）

**自前でテクスチャを描かない。**

はじめは 64x32 の防具テクスチャを生成していた。
だが**兜の形は「頭の箱」ではなく、どこを透明にするかで決まる。**
顔の開口や面ごとの陰影を手で当てても、
**革や鉄の兜とは微妙に違う形**にしかならなかった。

**革の帽子は、もともと色を変えられるように作ってある。**
借りれば、形はバニラそのものになる。

| | 何を使うか |
| --- | --- |
| テクスチャ | `textures/models/armor/leather_1`（**バニラのもの**） |
| 素材 | `armor_leather` / `armor_leather_enchanted` |
| 色 | `minecraft:dyeable` の `default_color` が上から掛かる |
| 持ち物の絵 | `leather_helmet`（**バニラのもの**。同じ色が掛かる） |

> **染め直される心配は無い。**
> 帽子は頭の枠に固定されている（`ItemLockMode.slot`）ので、
> **作業台へ持っていけない。**

#### 装備は 3 点になる

頭が固定されるので、**買える防具は胴・脚・足の 3 点。**
[03-content.md](../03-content.md) 1-2 の値段もそれに合わせる。

### 7-3. 見つけた相手が頭上に出る

**出るのは試合中だけ**（2026-08-28 追加）。

> **消す処理も試合中しか回っていなかった**（2026-08-28 修正）。
> 試合が終わると見張りは**記録だけ消して帰っていた**ので、
> **画面に出ていたものがそのまま残った。**
> 表示は相手に貼り付いている（`attachedTo`）ので、**ロビーまで付いてくる。**
>
> **帰る前に消す。**

所属が外れるのは演出の最後（[11-match.md](11-match.md) 4-C）なので、
**決着してから片付くまでの十数秒、敵味方の色で名前が浮かんだままだった。**
見る人には**まだ試合が続いているように見える。**


**敵の視界に 0.2 秒入り続けると、その相手の頭上に名前と残量が出る。**

| 条件 | |
| --- | --- |
| 角度 | 視点から**左右 60 度**（合わせて 120 度） |
| 時間 | **0.2 秒以上**続けて |
| 距離 | **30 マスまで** |
| 遮蔽 | **視線が通っていること**（[7-3-B](#7-3-b-壁の向こうは見えない2026-08-25-変更)） |

#### なぜ要るのか

**地図の代わり。**

名前を消したので、相手の位置を知る手がかりが無くなった。
だが「**見ている方向に居るなら見えている**」のは自然な話。

**探す行為に意味を残しつつ、見つけた相手を見失わないようにする。**

#### どうやって出すか（2026-08-25 変更）

**光らせるのはやめた。**

`glowing` 効果は **Bedrock に無い**（`addEffect("glowing")` は例外を投げていた）。
代わりに殻をかぶせて光らせたが、**やめた。**

| 試したこと | どうなったか |
| --- | --- |
| `addEffect("glowing")` | **効果が存在しない。** 例外を投げて何も起きない |
| 殻をかぶせて発光させる | スキンが隠れる。縁だけ塗って直したが、**壁は越えない** |
| 材質で `DisableDepthTest` | **材質は足せない**（下記） |

> **材質は足せない。**
> `materials/entity.material` を置くと**同じ名前のファイルごと置き換わり**、
> バニラの材質が全部消える（実際に帽子が消えた）。
> RenderDragon 以降、写す元の `entity.material` も配られていない。
> 1.16.100 以降は継承もできない。

**光る必要はなかった。**
目的は「見つけた相手を見失わないこと」であって、光ることではない。

### 7-3-A. 頭上に出す

`@minecraft/debug-utilities` の `DebugText` を使う。

| | |
| --- | --- |
| `depthTest = false` | **壁越しに描く** |
| `attachedTo` | **相手に貼り付く。** 位置を追いかけなくてよい |
| しゃがみ | **無関係。** 名札ではないので隠されない |

> **beta モジュール。** ジェネレータの案内で既に使っている。

名札（`nameTag`）ではこれができない。**しゃがむと消える**ので、
隠れている相手ほど見えなくなる。

#### 出すもの

```
   名前                    ← チームの色
   ||||||||||||||| 016     ← 体力
```

### マナとロールは出さない（2026-08-28 変更）

一度は両方出したが、**やめた。**

| 出していたもの | なぜやめたか |
| --- | --- |
| **マナ** | **跳べるかどうかまで読める。** 追う側が待つだけで有利になる |
| **ロール** | **間合いを詰める前に答えが出ている。** 何をしてくる相手かは、動きで分かるべき |

> **どちらも相手の手の内。** 頭上に常に出るものではない。

頭上に残すのは**誰が、どれだけ削れているか**だけ。
自分のマナは**経験値の段と帯**に出る（[13-grapple.md](13-grapple.md) 2-E）。

**体力とガスは行を分ける**（2026-08-25 変更）。
横に並べると、**どちらの目盛りを読んでいるのか分からない。**
**数も同じ色にする。** 別の色にすると、目で追う必要が出る。

#### 書き換える。作り直さない（2026-08-28 修正）

体力もマナも**毎秒変わる**ので、出し直しは事実上ずっと走っていた。

> **作り直すと、消えるのと出るのが同じ tick に重なる。**
> 間に合わないと消え、間に合いすぎると二重に見える——
> **これがちらつきの正体。**

`DebugText` には **`setText`** がある。**同じ実体のまま書き換える。**

| 変わったもの | どうするか |
| --- | --- |
| 文字（体力・マナ） | **`setText`** |
| 見せる相手 | `visibleTo` を差し替え |
| どちらも同じ | **何もしない** |

**作り直すのは「まだ出していない人」だけ。**

#### 幅をそろえる（2026-08-25 追加）

**桁数が変わると行ががたつく。**

| | 取りうる値 | 桁 |
| --- | --- | --- |
| ガス | 0〜100 | **3** |
| 体力 | 0〜99（金のリンゴで増えうる） | 2 |

**多いほうに合わせて 3 桁にし、足りない桁は 0 で埋める。**
埋めた 0 は暗くして、値と読み違えないようにする。

> **空白で埋めても揃わない。**
> Minecraft の字は等幅ではなく、**空白と数字で幅が違う。**
> 0 なら数字なので、必ず同じ幅になる。

目盛りは **15 本**。10 本では短くて、**残りの差が読み取りづらかった。**

#### 増えている分はピンク（2026-08-25 追加）

金のリンゴなどで体力が 20 を超えている間は、
**増えた分を左からピンクで出す。**

```
   ||||||||||||||| 020     ふつう
   ||||||||||||||| 024     金のリンゴ（左の 3 本がピンク）
   └ 吸収
```

| | |
| --- | --- |
| 目盛り | **上限で割る。** 上限 20 で吸収 16 なら**ピンクは 8 割** |
| 数 | **体力 + 吸収**。増えている間は数もピンク |

**「体力 + 吸収」で割らない**（2026-08-25 修正）。
そうすると**増えるほど目盛り 1 本が表す量が変わる。**
上限で割れば、**1 本の重みは増えていても増えていなくても同じ。**

#### 増えている分は自分で数える（2026-08-25 修正）

**API から読めない。**

| 試したこと | 駄目だった理由 |
| --- | --- |
| 吸収の部品を読む | **`@minecraft/server` に無い**（2.9.0 で確認） |
| `minecraft:health` の実値 | **吸収は入っていない。** 上限のまま |
| 効果の段（`absorption` の `amplifier`） | **食べるたびに積み上がるが、段は I のまま。** 金のリンゴ 4 つで +16 でも段は I |

**食べた分を足し、受けた分を引く**（`lib/absorb.ts`）。

| | |
| --- | --- |
| 金のリンゴ | +4 |
| エンチャントの金のリンゴ | +16 |
| 受けた | **体力が減らなかったぶん**を引く（吸収が肩代わりした量） |
| 効果が切れた | **0 に戻す** |
| 倒れた | **0 に戻す** |

> **数え間違えても溜まり続けない。**
> 吸収の効果が切れた時点で必ず 0 に戻る。

#### 透明なら敵には出さない（2026-08-25 追加）

姿を消しているのに**頭上の名前で位置が割れる**のでは、
透明になる意味が無い。

**味方には出す。** 味方から隠れたいわけではない。

| | |
| --- | --- |
| 名前 | **チームの色で出す。** 色だけで敵味方が分かる |
| 体力 | 目盛り。6 割超 §a緑 / 3 割超 §e黄 / それ以下 §c赤 |
| ガス | 目盛り。**水色**（[13-grapple.md](13-grapple.md) 2章） |

#### いつ消えるか

| | |
| --- | --- |
| 距離 | **30 マスを超えたら**見つけていないことになる |
| 遮蔽 | 壁に隠れれば積み上げが止まり、やがて消える |

**80 マスにしていたが遠すぎた**（2026-08-25 変更）。
マップの向こう端の相手まで暴かれると、**近づく前に位置が割れている。**

#### 誰に見せるか

**表示は 1 つ。見せる相手だけを切り替える。**

| 相手 | いつ見えるか |
| --- | --- |
| **味方** | **常に** |
| **敵** | **その組の誰かが見つけている間**（2026-08-26 変更） |
| **本人** | **見せない** |
| **観戦中の人** | **その人の表示は出さない** |

##### 見つけたら、組の全員に見える（2026-08-26 変更）

> **見つけた情報を、本人だけに留める理由が無い。**
> 声で伝えれば済むことを、**画面が伝えないだけ**になる。

一度は「誰か 1 人でも見つければ全員」から
「**見つけた本人だけ**」へ戻した（2025-08-25）が、**また全員に戻した。**

迷ったのは**壁の裏まで見えるのが強すぎないか**という点。
だが**見つけ続けないと消える**ので、
居場所を握り続けるには**誰かが見ていなければならない。**

> **ドローンの値打ちが変わる**（[23-drone.md](23-drone.md) 3 章）。
> 「組で共有できること」ではなく、**高さと射程**になった。

`DebugShape.visibleTo` に見せる相手を並べる。
**2 つの機能ではなく、1 つの表示の見せ先の違い。**

##### 本人には見せない

上を向いたときに自分のが見えても意味が無い。**邪魔なだけ。**

##### 味方は常に

**味方の残りが分かれば、助けに行くか下がるかを決められる。**
声で聞くしかないのでは、間に合わない。

##### 観戦中は出さない

倒れて復活を待っている 5 秒間は観戦者になる（[14-death.md](14-death.md)）。
**そこに居ない人の体力が浮いていても、読めるのは嘘だけ。**

- 目盛りは **`|`**。細い字のほうが本数を読み取りやすい
- 埋まっている側と空いている側で**同じ字を色だけ変える。**
  字を変えると幅が揃わず、**目盛りが伸び縮みして見える**
- **数字を読まなくても危ないと分かる**ようにする。
  追い込んだかどうかは一瞬で判断できる必要がある

#### 名前は出す（2026-08-25 変更）

[7-1](#7-1-名前を出さない) で名前を消したのは、
**壁の向こうの相手まで分かってしまう**からだった。

**見つけた相手なら話が別。**
見つけている間だけ名前が出るのは、7-1 の目的と食い違わない。
色が付いていれば、**どちらのチームかが一目で分かる。**

### 7-3-D. 見つかった側の画面（2026-08-25 追加）

**見つかっていることを、見つかった本人が知らない。**

相手の頭上に表示が出ても、それは**相手の画面の話。**
自分が晒されているかどうかが分からないと、
隠れ直すのか、そのまま突っ込むのかを選べない。

> **画面の縁がうっすら赤く染まる。**
> 濃くしない。**知らせるためであって、妨害するためではない。**

#### 既存の効果では出せない

失明も吐き気も**画面全体を潰す**もので、「縁がうっすら」は作れない。

**リソースパックで HUD に絵を足す**（`ui/hud_screen.json`）。
`root_panel` に画像を 1 枚差し込む。

画面いっぱいに広げるのに、**2 つ引っかかった。**

| 症状 | 原因 |
| --- | --- |
| 真ん中に小さな枠が出る | **差し込む要素に `size` を書いた。** 書くと親の大きさを継承しない。大きさを持たないパネルで包み、**中の画像だけを `100%`** にする |
| **上下は端まで、左右が余る** | **`keep_ratio` の既定が `true`。** 正方形のテクスチャが正方形のまま描かれる。`false` にする |

引き伸ばすので `bilinear` も入れて、境目が階段にならないようにしてある。

#### 合図の渡し方

HUD の絵は**スクリプトから直接は触れない。** 出す・消すを伝える道が要る。

**タイトルの文字を合図に使う。**
JSON UI は `#hud_title_text_string` を読めるので、
**決めた文字と一致したときだけ絵を出す。**

| | |
| --- | --- |
| 出すとき | `§r` を送る |
| 消すとき | `§r§r` を送る（一致しなくなる） |

どちらも**書式記号だけで、字が 1 つも無い。**

**そのうえでタイトルの枠ごと隠す。**
`hud_title_text/title_frame` に
「この 2 つのどちらかなら見せない」を足してある。

> **字が無いだけでは足りなかった。**
>
> | 試したこと | 出たもの |
> | --- | --- |
> | 合図を `§r§k§r` にした | **`§k` は文字を化けさせる指定。** 謎の文字が出た |
> | 消すのに空白を送った | **中央に空のタイトルの枠が出た** |
>
> 字を消しても**枠は出る。** 枠ごと隠して初めて何も見えなくなる。

### 7-3-B. 壁の向こうは見えない（2026-08-25 変更）

**遮蔽を見る。**

以前は「角度と距離だけで決める。壁は見ない。これが正しい」としていた。
**逆だった**（2026-08-25 の指摘）。

> **見えていないのに見つけたことになるのはおかしい。**

見つける条件に**視線が通っていること**を足す。

| 条件 | |
| --- | --- |
| 角度 | 視点から左右 60 度 |
| 時間 | 0.2 秒以上続けて |
| 距離 | **30 マスまで** |
| **遮蔽** | **胴までの視線にブロックが無いこと** |

#### 広すぎたので狭めた（2026-08-25 修正）

| 直したもの | なぜ |
| --- | --- |
| 狙う先 頭 → **胴** | **壁の上に頭だけ出ていれば通ってしまう。** 覗いている相手を見つけたいわけではない |
| 相手の**ごくわずか手前**で止める | 終点ちょうどのマスを拾わないための余裕。**0.5 マスにしたら、近いほど壁を飛び越した**（距離 2 で 0.5 引けば厚さ 1 の壁がまるごと範囲外）。狙う先の胴はそもそも空気なので、長く切る必要が無い |

> **角度は狭めない。**
> 一度 45 度まで狭めたが、戻した（2026-08-25）。
> 120 度は画面の外まで含んでいるように見えるが、**遊んでみると合っている。**
> 広すぎたのは角度ではなく、**遮蔽の当て方**だった。

**見つけたあとは壁越しでも見える。** それが「見失わない」ということ。
壁に隠れれば 0.2 秒の積み上げが止まり、やがて消える。

## 8. 決めたこと・残したこと

### 壁越しでも光る（これが正しい）

**角度と距離だけで判定する。** 壁は見ない。

当初は「壁の向こうで光るのは不正確」と考えたが、**逆だった**（2026-08-24）。

**これは地図の代わり。**
壁の向こうに居る相手の位置が分かることこそが目的で、
遮蔽を見てしまうと**地図として機能しない。**

> 副産物として軽い。遮蔽を見るには視線の走査が要り、
> **人数の 2 乗ぶん走る**（15 人で 210 回）。毎 tick やる処理ではない。

### 帽子は枠の印で固定する

`ItemLockMode.slot` を付ける。**外せず、捨てられず、入れ替えられない。**

毎秒かぶせ直しているのは**取りこぼしの受け皿**であって、
止めているのはこの印。
