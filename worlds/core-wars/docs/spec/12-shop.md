# 仕様: ショップ

**ジェネレータで得た資源を、道具と交換する場所。**

ルールは [01-rules.md](../01-rules.md)、品揃えは [03-content.md](../03-content.md)。

---

## 1. どう見せるか

**チェストの見た目の格子で並べる。**

```
        鉄で買えるもの  →  ■ ■ ■ ■ ■ ■ ■ ■ ■
        金で買えるもの  →  ■ ■ ■ ■ ■ ■ ■ ■ ■
      ダイヤで買えるもの →  ■ ■ ■ ■ ■ ■ ■ ■ ■
    エメラルドで買えるもの→ ■ ■ ■ ■ ■ ■ ■ ■ ■
```

**通貨ごとに横一列。** 値段が縦に揃うので、
「いま何が買えるか」を持ち物と見比べるだけで分かる。

### なぜ一覧（縦並び）ではないのか

縦に並べると、**通貨の違いが読み取れない。**
鉄で買える安物とエメラルドの高級品が同じ列に混ざり、
毎回テキストを読んで判断することになる。

**位置で意味を持たせる**ほうが速い。

## 2. 種別

**6つ。**

| 種別 | 中身 | 単位 |
| --- | --- | --- |
| **ブロック** | 建材 | **物によって違う**（羊毛16個、合成鋼4個 など） |
| **武器** | 剣 | 1本 |
| **防具** | 一式 / 部位ごと | 下記 |
| **ツール** | ツルハシなど | 1本 |
| **ポーション** | 効果 | 1本 |
| **特殊アイテム** | 仕掛け | 物による |

### 防具は2通りの買い方がある

| 買い方 | 何が起きるか |
| --- | --- |
| **一式** | 頭・胴・脚・足をまとめて。**安いが選べない** |
| **部位ごと** | 1箇所だけ。**高いが必要な所だけ強化できる** |

## 3. 作り方

### 3-1. Script API に「容器を開く」手段は無い

調べた結果（2026-08-24）:

| 手段 | 可否 |
| --- | --- |
| `player.openInventory()` のような API | **無い** |
| チェストのブロックを script から開かせる | **無い** |
| **`ActionFormData` の見た目を JSON-UI で作り変える** | **できる** |

**リソースパックの `ui/server_form.json` を改造して、
フォームをチェストの格子に見せる。**
コミュニティで確立した手法（`bedrock-wiki/json-ui/modifying-server-forms`）。

### 3-2. 自前で書くのはやめた

**一度、自分で書いて失敗している**（2026-08-24）。

| 試したこと | どうなったか |
| --- | --- |
| 差し込み（factory）を足す | **バニラの一覧がそのまま出た。** 隠す必要があると分かった |
| バニラを隠し、マスを 36 個並べる | **それでも出なかった。** 原因を絞れなかった |

JSON-UI は**壊れても理由がログに出ない。** 出るか出ないかしか分からず、
どこが悪いのかを二分探索するしかない。**時間の使い方として割に合わない。**

### 3-3. 配布されているものを使う

**[Chest-UI](https://github.com/Herobrine643928/Chest-UI) を取り込む。**
広く使われていて、こちらが欲しかったものがそのまま入っている。

| 取り込む先 | 何 |
| --- | --- |
| `resource_packs/game/ui/` | 盤面の定義 |
| `resource_packs/game/textures/ui/` | マスの絵 |
| `scripts/vendor/chest-ui/` | フォームを組み立てるコード |

**`vendor/` の中は編集しない。** 元の版に追従できなくなる。
必要な違いは、呼ぶ側（`features/shop/`）で吸収する。

> **例外として `_global_variables.json` だけは触る。**
> これは設定ファイルであり、**使う盤面の型を選ぶためのもの**。
> 使わない型を有効のままにすると、開くたびに重くなる。

#### 盤面の型

**5 行 x 9 マス（45）。**

| 行 | 何 |
| --- | --- |
| 1 行目（0〜8） | 鉄で買えるもの |
| 2 行目（9〜17） | 金で買えるもの |
| 3 行目（18〜26） | ダイヤで買えるもの |
| 4 行目（27〜35） | エメラルドで買えるもの |
| **5 行目（36〜44）** | **操作。** 戻るは 40 |

**空きマスは空けたままでよい。** 置かないマスは何も描かれない。
自前で書いていたときは空きもボタンで埋める必要があったが、その制約は無くなった。

型を変えるときは、**スクリプトの `CHEST_SIZE` と
`_global_variables.json` の両方**を直すこと。片方だけだと出ない。

#### 通貨は色ではなく位置と文字で示す

**当初は行ごとにマスの背景を染めるつもりだった。**
取り込んだ盤面はマスの絵が共通なので、そのままではできない。

いまは**位置**（何行目か）と、**説明文**（`§f鉄§r x4` のような表示）で示す。
さらに、**買えるかどうかを説明文の色で出す**（買えるなら緑、足りなければ赤）。

> **色分けは後回しにした。** 盤面の定義に手を入れればできるが、
> それは `vendor/` を編集することになる。
> **実際に遊んで、位置と文字で足りないと分かってからにする。**

#### 持ち物が下に出る

取り込んだ盤面は、**下に自分の持ち物を並べて見せる。**
通貨をいくつ持っているかを、画面を閉じずに確認できる。

**押しても何も起きない**（品揃えのマスではないので無視する）。

## 4. 値段は必ず「1 個あたり」

**まとめ買いで安くしない。**

払う額は `1 個あたりの値段 × 個数`。
単位違い（羊毛 x16 / x64 など）を並べるのは**押す回数を減らすため**であって、
得をさせるためではない。

> 安くすると**「まとめ買いが常に正解」**になり、選ぶ意味が消える。
> 少しだけ欲しいのに大量に買わされるのは、選択ではなく作業。

**防具の一式も同じ。** 4 個ぶん払う。

盤面には合計を出し、2 個以上のものには**単価も併記する。**
得だと誤解させないため。

### 4-A. 単価は小数でよい（2026-08-25 追加）

**1 個あたりの値段に小数を使える。**

まとめ買いの単位があるので、**整数だけでは刻めない。**

> 羊毛 x16 を鉄 8 個にしたい——単価は **0.5。**
> 整数しか使えないと、1（合計 16）か 0（ただ）しか選べない。

**払う額は必ず整数。** 単価 × 個数を**切り上げる。**

| 単価 | 個数 | 払う |
| --- | --- | --- |
| 0.5 | 16 | **8** |
| 0.3 | 8 | **3**（2.4 の切り上げ） |
| 0.5 | 1 | **1**（0.5 は切り上げて 1） |

**切り上げるのは、ただで配らないため。**
最低でも 1 個は払う。

## 4-B. エンダーチェストからも払える（2026-08-25 追加）

**持ち物とエンダーチェストの両方から払う。**

マイセットだけがそうなっていて、**普通の購入は持ち物しか見ていなかった。**

エンダーチェストは奪われない金庫（[01-rules.md](../01-rules.md) 4-3）。
**そこに貯めた資源を使うのに、いちいち取り出させる理由が無い。**

**持ち物から先に取る。** 手元にあるぶんを使い切るほうが自然で、
**金庫は最後の砦**として残る。

> **同じ規則を 2 か所に書かない。**
> マイセットと普通の購入で払い方が違うと、
> 「マイセットなら買えるのに単品だと買えない」が起きる。

## 5. 値段と通貨はゲームの中から変える

**アドオンを触らずに変えられるようにする。**

値段の調整は**遊びながら何度もやる作業**で、
そのたびにビルドして配布して読み込み直すのは現実的でない。

### どこに持つか

| | どこ | 変わるか |
| --- | --- | --- |
| **初期値** | `lib/shop-items.ts` | 変わらない。**設計としての値段と通貨** |
| **変更後の値** | ワールドの動的プロパティ | **ゲーム内から変えられる** |

**初期値は消さない。** いつでも戻せるようにしておく。
変更が無い品物は初期値をそのまま使う。

> 動的プロパティなので、**`/reload` でもワールドを閉じても残る。**

### どう変えるか

**`/game:price` で、ショップと同じ盤面を開く。**

品物を押すと、**値段と通貨**を決める画面が出る。
**運営だけが使える**（遊ぶ人が値段を変えられてはいけない）。

同じ並びなので、**普段見ている位置のまま直せる。**
別の一覧を覚え直す必要が無い。

### 5-A. 通貨も変えられる（2026-08-25 追加）

**何の鉱石で買うかも、ゲームの中から変える。**

値段だけでは釣り合いを取りきれない。

> **鉄 60 個**にするより、**金 8 個**にしたほうが早いことがある。
> 通貨が固定だと、**その品物が「序盤のもの」か「終盤のもの」かを動かせない。**
> 値段を上げ下げするだけでは、**手に入る資源の種類**が変わらないため。

#### 並びは動かない

**盤面の位置は、初期の通貨で決まったまま。**

通貨を変えても**その品物は同じマスに居続ける。**

> 位置が動くと、**直すたびに探し直すことになる。**
> 「普段見ている位置のまま直せる」という利点のほうが大きい。
>
> 通貨は**その品物の説明に出ている**ので、行で見分ける必要が無い。

#### 戻すときは値段と一緒

**値段を空にして決定すると、通貨も初期値に戻る。**
「その品物を初期状態に戻す」操作は 1 つでよい。

### 戻す

| 操作 | 何が起きるか |
| --- | --- |
| 値を空にして決定 | **その品物だけ初期値に戻る**（値段も通貨も） |
| `/game:price reset` | **全部初期値に戻る**（値段も通貨も） |

## 6. 誰が開けるか

**3つとも満たした人だけ。** ひとつでも欠けたら開かない。

| 条件 | なぜ |
| --- | --- |
| **試合中である** | 一時停止中や非開始中に買えると、開始前に装備が揃う |
| **チームに所属している** | 所属が無いと、渡すブロックの色が決まらない |

> **所属していない人はそもそも拠点に来られない想定。**
> それでも見る。**来られない想定が崩れたときに、静かに壊れてほしくない。**

**「自チームの店員か」は条件から外した**（2026-08-26 変更）。下記 6-B。

## 6-B. 敵陣では、手持ちだけ（2026-08-26 追加）

> ### 敵の店は使える。だが持って入ったものしか払えない。

| | 敵陣で |
| --- | --- |
| **ショップ** | **使える** |
| 支払い | **手持ちのみ。** 金庫もエンダーチェストも覗けない |
| **エンダーチェスト** | **開けない** |
| マイセット | 使える（**払いは同じく手持ちのみ**） |

### なぜ店は開けるようにしたのか

以前は**店員の所属で弾いていた。**

だが攻め込んだ先で買えないというのは、
**攻めた側だけが補給を絶たれる**ということで、
**拠点に踏み込む理由をひとつ削っていた。**

### なぜ金庫とエンダーチェストは覗けないのか

どちらも**奪われない置き場所**（[22-vault.md](22-vault.md)・[01-rules.md](../01-rules.md) 4-3）。

敵陣でもそのまま使えるなら、**攻め込んだまま補給し続けられる。**
死んでも落とさない資源を、**相手の拠点の真ん中で取り出せてしまう。**

**敵陣で使えるのは、持って入ったものだけ。**
何を持って攻め込むかが、そのまま判断になる。

### 弾いたら、必ず言う

**押しても何も起きないのは、壊れているのと区別が付かない。**

```
敵陣のエンダーチェストは使えません
```

足元の行に出すだけ。**音は鳴らさない。**

> **知らせは次の tick に出す。**
> before イベントの中は restricted execution で**画面に書けない**
>（`docs/imp.md` 5.1）。
> そのまま呼ぶと例外が握り潰され、**黙って弾かれる。**

### なぜエンダーチェストだけ開けなくするのか

**店は「そこへ行かないと買えない場所」**なので、踏み込む理由になる。

エンダーチェストは**どこにでもある同じ箱**で、
敵陣にあること自体には意味が無い。**開ける理由が「そこにあるから」しかない。**

### 見出しにも出す（2026-08-26 修正）

**敵陣では、盤面の見出しに金庫の残高を出さない。**

| どこで開いたか | 見出し |
| --- | --- |
| 自陣 | `ショップ  鉄12 金3`（金庫の残高） |
| **敵陣** | **`ショップ  敵陣・金庫は使えません`** |

払えないのに残高だけ出ていた。

**最初の画面（種別を選ぶところ）にも同じ見出しを出す**（2026-08-26 修正）。
品揃えの画面にだけ出していたので、
**開いた直後はいくら持っているか分からず、敵陣かどうかも 1 枚めくるまで分からなかった。**

> **使えない数字を出すのは、嘘をついているのと同じ。**
> 数が合わない理由が、そこに書いていなければ分からない。

マイセットの画面も同じ。

### 判定は立っている場所（実装）

**誰の店を開いたかは覚えない。** 自分が**敵の拠点の箱の中に居るか**だけを見る。

> 覚えて持ち回る形だと、**画面をまたぐたびに渡し直す**ことになる。
> **立っている場所は、いつ見ても同じ答えを返す。**

### 渡すものはチームの色になる

羊毛・天然石・合成鋼は**チームによって色が違う**（[01-rules.md](../01-rules.md)）。
品揃えには代表を 1 つだけ書き、**渡すときに差し替える。**

| 品揃えの表記 | 青が受け取る | 赤が受け取る |
| --- | --- | --- |
| `white_wool` | 青の羊毛 | 赤の羊毛 |
| `prismarine` | 天然石(青) | 天然石(赤) |
| `raw_iron_block` | 合成鋼(青) | 合成鋼(赤) |

**盤面に出る絵も差し替える。** 買う前と買った後で色が違うと混乱する。

### 盤面の絵は、当てにならないことがある（2026-08-26 追記）

**盤面（`vendor/chest-ui`）はアイテム id を番号に直して絵を引く。**
その対応表が**手元の版より古い**ので、

> **新しいアイテムは番号がずれて、別の絵が出る。**
> 木の槍が**石のツルハシ**になっていた。

#### 直し方は 2 通り

| 症状 | 直し方 |
| --- | --- |
| **絵の名前が id と違う** | **絵の道を書く**（例: `minecraft:golden_pickaxe` → `textures/items/gold_pickaxe`） |
| **対応表に無い / ずれている** | **16x16 を 1 枚描いて置く**（例: 木の槍） |

**どちらも盤面だけの話。** 手に持った見た目はバニラのまま。

> 金の道具は**絵の名前が `gold_`**（id は `golden_`）。
> 新しめのアイテムは**対応表そのものが追いついていない。**

## 7. どこで開くか

**拠点の中に立っている店員に触ると開く。**

### 位置

**各チーム 4 体。** 拠点の四隅に近い位置。

| チーム | 座標（y はすべて -9） |
| --- | --- |
| **青** | (906, 990) (908, 990) (906, 1010) (908, 1010) |
| **赤** | (1092, 990) (1094, 990) (1092, 1010) (1094, 1010) |

座標を書くのは [arena.ts](../../packs/game/scripts/lib/arena.ts) だけ。
**会場を増やしても、ここに 1 項目足せば付いてくる。**

### 試合中しか居ない

| 状態 | 店員 |
| --- | --- |
| 試合中 | **居る** |
| 一時停止中 | **居ない** |
| 非開始 | **居ない** |

一時停止中に消すのは、**止まっている間に買い物が進むのを防ぐ**ため。
再開すれば戻る。

### 見張って直す

**居るべき数を、一定間隔で確かめて合わせる。**

置いて終わりにしない。以下で簡単に消える。

- 試合開始時の**エンティティ一掃**（場内の実体を消す処理）
- チャンクが読み込まれていない間の湧き損ね
- `/reload`（位置の記憶はメモリにしかない）

**あるべき姿を毎回作り直すほうが、消えた原因を数えるより確実。**
ジェネレータの再走査やティッキングエリアと同じ考え方
（[11-match.md](11-match.md) 6-B / R-3）。

### 店員の作り

**専用のエンティティ**（`game:shopkeeper`）を作る。バニラの村人は使わない。

| バニラの村人 | 困ること |
| --- | --- |
| 歩き回る | 位置が決まらない |
| 殺せる | 買えなくなる |
| 触ると取引の画面が出る | 本来の画面と競合する |

専用に作れば、**そもそもその機能が無い。** 消す手間も要らない。

- **動く仕組みを入れない**（移動も経路探索も持たせない）
- **触ったら取引ではなくショップを開く**（スクリプトで横取りする）
- **常に会場の中央（コアの z）を向く**。背中を向けた店員を作らない

### 殴っても何も起きない

**二重に止める。**

| 手段 | 役割 |
| --- | --- |
| スクリプトで**ダメージを取り消す** | 本命。**経路に依らず必ず止まる** |
| 定義側の `damage_sensor` | 受け皿。**スクリプトが止まっている間**を守る |

定義側だけでは死んだ（2026-08-24）。
**定義は「どう扱うか」の宣言で、通る経路が版によって変わる。**
ダメージそのものを取り消すほうが確実。

> **振りかぶりの動作までは消せない。** 殴る仕草は出る。
> だが**減りも死にもしない**ので実害は無い。

見た目はバニラの村人を借りる。
**モデルもテクスチャもバニラのものを指すだけ**なので、こちらには持たない。

> **見慣れた見た目のほうが「店だ」と伝わる。**
> 境界の粒子と同じ判断（[11-match.md](11-match.md) 6-F）。

## 8. 買うときの決まり

### 4-1. 払う元は 3 つ（2026-08-26 更新）

**通貨は持ち物にあるアイテムそのもの**（鉄・金・ダイヤ・エメラルド）。
スコアボードで数を持たない。

> **持ち物が正。** 落としても、奪われても、そのまま反映される。
> 死んで落とした資源を相手が拾えば、相手が買える。
> [01-rules.md](../01-rules.md) の「アイテムは落ちる」と噛み合う。

払う順は **金庫 → 持ち物 → エンダーチェスト**（[22-vault.md](22-vault.md) 3 章）。

| 払う元 | 自陣 | **敵陣** |
| --- | --- | --- |
| 持ち物 | 使う | **使う** |
| 金庫 | 使う | **使えない** |
| エンダーチェスト | 使う | **使えない** |

**敵陣では手持ちだけ**（6-B）。
数え方も払い方も**同じ 1 箇所**（`lib/purse.ts`）に置いてある。

### 4-2. 足りなければ買えない

**理由を出す。** 何が何個足りないかまで言う。

### 4-3. 買ったものは持ち物へ

いっぱいなら**買わせない。** 足元に落とすと事故で失う。

### 4-4. 防具は買った直後に着る

**買っただけでは強くならない。着るまでが買い物**（2026-08-25 追加）。

戦闘の合間に持ち物を開かせない。買った瞬間に、
**持っている中でいちばん硬いものを着る。**

| 部位 | |
| --- | --- |
| 胴・脚・足 | **持っている中で最も硬いもの** |
| 頭 | **触らない**（チームの帽子で固定。[15-presentation.md](15-presentation.md) 7-2） |

いま着ているほうが硬ければ、そのまま。外したものは持ち物に残す。**捨てない。**

> **着せ方は [17-myset.md](17-myset.md) 4章と同じ規則**で、
> 実装も `lib/armor.ts` の 1 箇所に置く。
> 買う経路が 2 つ（店員・マイセット）あるので、
> **2 箇所に書くと必ず食い違う。**

### 4-5. マイセットの入口を店員に置く

**読み込み（まとめ買い）は店員から**（[17-myset.md](17-myset.md) 2章）。

種別を選ぶ画面の下段に `マイセット` を置く。
**戻り先を渡してあるので、買ったあとショップへ戻れる。**

払う元は**単品購入と同じ**（金庫 → 持ち物 → エンダーチェスト。4-1）。
1 つずつ買うほうは 4-1 のとおり**持ち物からのみ。**
