# 仕様: マップのブロックを守る

**マップを構成するブロックは、オペレーター以外は壊せない。**
プレイヤーが自分で置いたブロックは、これまでどおり壊せる。

調査は [docs/research/10](../../../../docs/research/10-custom-block-replacement.md)。

**2段構えにしてある。**

1. 立方体 14 種は**独自ブロック** `game:map_parts_*` に置き換えた（種類で区別）
2. 置き換えられないもの（階段・柵・チェスト等）は**座標とスクリプト**で守る

---

## 1. 何を解くのか

### 1-1. 守りたい理由

Core Wars では**ブロックが足そのもの**（[02-map.md](../02-map.md) 2-A-1）。
橋を架け、拠点に登り、壁を作る。**ブロックを壊す行為はゲームの中心**にある。

だが**マップそのものが壊せてしまうと、試合が成立しない。**

- 拠点の床を抜かれると、リスポーン地点ごと奈落へ落ちる
- 中央の城を掘り崩せば、守りの意味が消える
- 一度壊れると**次の試合まで直らない**（マップは固定）

### 1-2. 難しいのは「区別」

**プレイヤーが置いた石と、マップの石は、同じブロックである。**

立方体 24 種は独自ブロック `game:map_parts_*` に置き換えた。
種類そのものが「マップの一部」を意味し、プレイヤーは入手できない。

階段・柵・板ガラス・ツタ・ランタン・葉・はしご・チェストは置き換えていない。
組み込みモデルが `minecraft:geometry.full_block` しかなく、
形・向き・繋がる挙動を自作することになって割に合わないため
（[research/10](../../../../docs/research/10-custom-block-replacement.md)）。

---

## 2. 判定のしかた

**既定は「守る」。守らないものだけを列挙する。**（2026-08-24 確定）

```
守らない一覧に載っている？
    載っている  → 壊せる
    載っていない → 守る
```

**座標は一切見ない。ブロックの種類だけで決まる。**

### 2-1. 守らないもの（現時点）

| ブロック | 理由 |
| --- | --- |
| `blue_concrete` `red_concrete` | **コア。壊すことが目的** |
| `red_wool` `blue_wool` **`white_wool`** | ショップで売る建材 |
| `prismarine` `prismarine_bricks` | 天然石（見た目だけ差し替え） |
| `raw_iron_block` `raw_copper_block` | 合成鋼（同上） |
| `obsidian` | ショップで売る建材 |
| `tnt` | 置いた瞬間に実体になる |
| `game:pillar_red` `game:pillar_blue` **`game:pillar_white`** | 支柱弾で生えた足場 |
| `air` | 守る対象ではない |

**これ以外はすべて守られる。**

> **白は入れ忘れていた**（2026-08-28 修正）。
> 試合では**チームの色に差し替えて渡す**ので、
> 白のまま置かれるのは**ロビーで試すとき**だけ
>（[25-practice.md](25-practice.md)）——
> そこを作るまで、白が置かれる場面が無かった。
>
> 守る側に入っていたので、**掘れないうえに、後片付けでも消えずに残っていた。**
> **一覧に無いものは掃除もされない**（[11-match.md](11-match.md) 8 章）。

### 2-2. なぜこの向きなのか

逆（守るものを列挙する）にすると、
**列挙し忘れたブロックが黙って壊せるようになる。**
マップに素材を足すたびに列挙が必要で、忘れても誰も気づかない。

この向きなら、忘れたときに起きるのは
「自分で置いたブロックが壊せない」であって、**その場で分かる。**

> **気づけない失敗より、気づける不便を選ぶ。**

### 2-3. 座標をやめた経緯

当初は「マップの範囲の中か」を座標で見ていた。

だが**マップは手で作り直され、範囲がずれた。**
その結果**ランタンや柵がサバイバルで普通に壊せてしまった。**

座標はマップを直すたびに合わせ直す必要があり、
**合わせ忘れると黙って守られなくなる。** まさに避けたい失敗の形だった。

### 2-4. ショップとの約束

**ショップで売るブロックは、必ず「守らない一覧」に足す。**
足し忘れると「買ったブロックを置いたら回収できない」が起きる。

逆に**マップの素材を一覧に足してはいけない。** マップが壊せるようになる。

> [03-content.md](../03-content.md) が正。
> **あちらを直したら、必ず `lib/protection.ts` も直す。**

## 3. 壊れ方を全部塞ぐ

**採掘と爆発以外にも、ブロックは壊れる。**
そして**スクリプトで止められるのは、その2つだけ。**
`before` イベントが存在するのが `playerBreakBlock` と `explosion` しかない。

| 壊し方 | 独自ブロック | バニラの飾り |
| --- | --- | --- |
| プレイヤーが掘る | `destructible_by_mining: false` + `cancel` | **`cancel`** |
| 爆発 | `destructible_by_explosion: false` + 対象から除外 | **対象から除外** |
| **ピストン** | `movable: immovable` | **ゲームルールで防ぐしかない** |
| **炎** | `flammable: false` | **`doFireTick = false`** |
| **液体** | `liquid_detection: blocking` | **売らない** |
| **湧いた敵** | — | **`mobGriefing = false`** |

### 3-1. ゲームルールを固定する

**バニラの飾りには、これしか手が無い。** こちらでコンポーネントを付けられない。

```
doFireTick   = false   炎が燃え広がらない（葉・木の階段が燃えない）
mobGriefing  = false   クリーパー・エンダーマンがブロックを壊さない
```

ワールドロード時にスクリプトから設定する。**手で戻されても、次の入場で戻る。**

> どちらも**遊びの本筋を変えない。**
> 火で攻めるゲームではないし、湧いた敵にマップを削られる理由も無い。

### 3-2. 爆発は打ち消さない

**守るブロックだけを爆破対象から抜く。**

爆発そのものを消すとノックバックまで消え、
奈落へ突き落とす戦術（[02-map.md](../02-map.md) 2-A-2）が変わってしまう。

### 3-3. 液体とピストンを売らない

独自ブロックは定義で防いでいるが、**バニラの飾りは防げない。**
水・溶岩・ピストンを**ショップに置かない**ことで、試合に登場させない。

置きたくなったときは、**壊されたら戻す**仕組みが要る。いまは作らない。

## 4. 独自ブロックにしたもの（24 種）

`tools/gen-map-blocks.mjs` が生成する。

```
stone  cobblestone  stone_bricks  mossy_stone_bricks
andesite  polished_andesite  deepslate_bricks  deepslate_tiles
moss_block  oak_planks  dark_oak_planks  spruce_planks
oak_log  spruce_log
blue_terracotta  red_terracotta
blue_stained_glass  red_stained_glass
verdant_froglight  pearlescent_froglight
iron_block  gold_block  diamond_block  emerald_block
```

テクスチャは**バニラのキーをそのまま参照**する。画像は複製しない。

> `stone` のテクスチャキーは `stone` ではなく **`flattened_stone`**。間違えやすい。

### 特別な扱いが要ったもの

| ブロック | 追加した設定 |
| --- | --- |
| 色付きガラス | `render_method: "blend"` / `light_dampening: 0`。既定だと**不透明な板**になる |
| ヒカリゴケ | `light_emission: 15`。付けないと**光らない** |
| 丸太・ヒカリゴケ | 状態 `game:axis` と `transformation`。**横倒しの向きを保つ** |

### ジェネレータの目印

鉄・金・ダイヤ・エメラルドブロックも独自ブロックにした。

> **検出する側は必ず `game:map_parts_*` を見ること。**
> バニラを見ると、誰かが置いた鉄ブロックまで湧き口になってしまう。

## 5. 例外: オペレーター

**`playerPermissionLevel === Operator` なら、すべて壊せる。**

制作中はマップを直し続けるので、**作り手が止められては困る**。

```ts
if (player.playerPermissionLevel === PlayerPermissionLevel.Operator) return;
```

`@minecraft/server` 2.9.0 に存在する（stable）。

## 6. 塞ぐ経路

**手で掘る以外にもブロックは壊れる。**

| 経路 | 対処 |
| --- | --- |
| プレイヤーが掘る | `world.beforeEvents.playerBreakBlock` → `cancel = true` |
| 爆発 | `world.beforeEvents.explosion` → `setImpactedBlocks()` で守る分を除く |

> **爆発は「打ち消す」のではなく「対象から外す」。**
> 爆発そのものを消すとノックバックまで消え、[戦術](../02-map.md)が変わってしまう。
> **守るブロックだけを爆破対象から抜く。**

### 未対応（当面）

- ピストンによる押し出し・引き込み
- 液体による破壊

**いま塞がない。** ショップで売らなければ、そもそも試合に出てこない。
出てきたら塞ぐ。

## 7. 実行文脈（事故りやすい）

**`beforeEvents` は restricted execution。world を変更できない**（[imp.md](../../../../docs/imp.md) 5.1）。

- `ev.cancel = true` は**イベント自身の操作**なので可
- **プレイヤーへの通知は不可。** `system.run()` で次の tick に逃がす

```ts
world.beforeEvents.playerBreakBlock.subscribe((ev) => {
  if (!shouldProtect(ev.player, ev.block)) return;
  ev.cancel = true;
  system.run(() => notify(ev.player));   // ← 変更は次の tick で
});
```

## 8. 作り

[imp.md](../../../../docs/imp.md) の P-2（判定は純粋関数に切り出す）に従う。

```
packs/game/scripts/
├── lib/
│   ├── regions.ts        マップの範囲。02-map.md を写した定数
│   └── protection.ts     判定。純粋関数。イベントに依存しない
└── features/
    └── protection/
        └── index.ts      イベント購読。薄いディスパッチだけ
```

**判定はイベントを知らない純粋関数にする。**

```ts
export function isMapBlock(loc: Vector3, typeId: string): boolean;
```

座標と種類だけを受け取る。**これならテストも机上で追える。**

## 9. 通知

壊せなかったとき、**理由が分からないと不具合に見える。**

アクションバーに一行出す。チャットには出さない（試合中に流れると邪魔）。

```
マップのブロックは壊せません
```

**連打されるので、同じプレイヤーへは 1 秒に 1 回まで。**

## 10. どのパックに入れるか

**`game`。** 遊びのルールそのものなので、完成品に必ず要る。

`kit` は[完成品に同梱しない前提](../../../../CLAUDE.md)なので、ここには置かない。

## 5. 絵画は守りきれない（2026-08-25 結論）

**絵画はブロックではない。** ブロックの保護は届かない。

ダメージを打ち消す形で守ったが、**サバイバルで壊せた。**
実体の削除は打ち消せず、絵画の定義も差し替えられない。

> ### 守れないものは、使わない。

説明画は**ブロックで建てる**ことにした
（[15-presentation.md](15-presentation.md) 1-B）。
**掘れないブロックなら、壊されようが無い。**

### 後片付けからは外したまま

絵画を置く可能性は残るので、**消す対象から外す**設定はそのままにしてある。
守れないだけで、**置いてはいけないわけではない。**

## 6. 絵画を守ろうとした記録（2026-08-25）

**絵画はブロックではない。** ブロックの保護は届かない。

| | どうしていたか | どうしたか |
| --- | --- | --- |
| 殴ると壊れる | **壊れていた** | **傷つけようとしたら打ち消す** |
| 爆発で飛ぶ | 飛んでいた | 同上（爆風も「傷つける」を通る） |
| 後片付けで消える | **消えていた** | **消す対象から外す** |

### なぜ守るのか

**マップの一部だから。**

ロビーの説明画（[15-presentation.md](15-presentation.md) 1-B）は、
**絵画として壁に掛けてある。**
壊せると**遊ぶ人が読むものが消える**し、
後片付けで消えると**試合のたびに掛け直す**ことになる。

### 置くのは運営だけ

**絵画を置けるのはクリエイティブの人だけ。**
遊ぶ人は絵画そのものを持っていないので、増える経路が無い。
