# 仕様: ワールド制作の道具

ワールドを手で作る作業を支えるもの。ゲームの中身ではない。

## 1. バックアップ（`tools/mc.mjs`）

**手作業の建築は消えたら戻らない。** だから最優先で用意する。

| コマンド | すること |
| --- | --- |
| `backup [server] [--label 名前]` | ワールドを `world/backups/` へ丸ごとコピー |
| `backups` | 一覧（新しい順・容量つき） |
| `restore <名前>` | バックアップから戻す |

### 決めごと

- **稼働中は取らせない。**
  書き込み途中のファイルを掴むと壊れたバックアップになる。
  停止していなければエラーで止める
- **名前に日時を入れる。** `<ワールド名>_YYYYMMDD-HHMMSS[_ラベル]`。
  ラベルは任意（`--label 拠点できた` のように何をした時点かを書く）
- **`restore` は戻す前に今の状態も退避する。**
  戻した先が期待と違ったときに元へ戻せないと詰む

## 1-A. パックをワールドに付ける（`tools/attach-packs.mjs`）

ワールドフォルダの `world_behavior_packs.json` / `world_resource_packs.json` に、
パックの **UUID と版**を書く。ゲームはこの一覧を見てパックを探す。

| コマンド | すること |
| --- | --- |
| `node tools/attach-packs.mjs` | いまの状態を見る |
| `node tools/attach-packs.mjs --write` | 書き込む |

- **ワールドを閉じてから実行する。**
  開いたまま書き換えても、閉じるときにゲーム側の一覧で上書きされて消える。
  起動中は実行を拒否する

## 1-B. リソースパックの版（`tools/bump-rp.mjs`）

**参加者は、受け取ったパックを UUID と版で見分けて手元に貯める。**
版が同じなら、中身が変わっていても取り直さない。

> **上げないと、ホストにだけ見えて、他の人には見えない。**
> 経緯は [docs/research/02-hot-reload.md](../../../../docs/research/02-hot-reload.md) 7章。

### 手で叩くものではない

**配るたびに自動で上がる。**

`npm run local-deploy` と `npm run mcaddon` が、配置の直前に
`bump-rp` タスクとして呼ぶ（各パックの `just.config.ts`）。

| | |
| --- | --- |
| いつ | `package` / `createMcaddonFile` の直前 |
| どれだけ | patch（3 つ目）を 1 つ |
| 上げないのは | **RP の中身が前回と同じとき** |

**上げ忘れの壊れ方は、自分の画面からは見えない。**
手元では正しく動くので、誰かに言われるまで気づけない。
だから手順書ではなくビルドに埋める。

### 中身が同じかの見分け

`resource_packs/<名>/` を丸ごと数え上げた指紋で見る。
指紋は `<パック>/.rp-version.json` に置く。**git に入れる**
（手元にしか無いと、別の機械で必ず 1 回ずれる）。

`--watch` で TypeScript を直している間は RP が変わらないので、版も動かない。

### 手で叩くとき

| コマンド | すること |
| --- | --- |
| `node tools/bump-rp.mjs` | すべての RP の版を 1 つ上げる |
| `node tools/bump-rp.mjs game` | 指定したパックだけ |
| `node tools/bump-rp.mjs --dry-run` | 上げずに、どうなるかだけ見る |

### 決めごと

- **上げるのは RP だけ。**
  BP は参加者に配られない（サーバ側でしか動かない）ので、版を上げる意味が無い
- **header と modules の版を揃える。**
  片方だけ上げると、どちらを見ているのか分からなくなる
- **上げるのは patch（3 つ目）だけ。**
  意味のある区切りは人が決める。道具は勝手に minor を上げない
- **版を潰して指紋を取る。**
  版そのものを数に入れると、上げた次の回に「変わった」と見えて上がり続ける

## 2. `kit` アドオン（制作用）

**ゲームの中身は入れない。** 完成品に同梱しない前提で作る。

想定する機能（作るときに各項目を仕様化する）:

- 建築補助（範囲の埋め立て・複製・整地）
- 座標や状態の確認
- 進行のやり直し（テスト用に状態をリセット）
- 運営コマンド（参加者の移動・持ち物の付与）

`kit` は作り手しか使わないので、**壊れにくさより手数の少なさを優先**してよい。

## 3. `game` アドオン（ゲーム本体）

遊ぶ人が触るので、**壊れない作り**にする。
仕様は [docs/game/](../) が決まってから、別途 `docs/spec/` に書く。

## 4. やらないこと（今は）

- `.mcworld` への書き出し（配布が視野に入ってから）
- 自動バックアップ（手動で足りているうちは入れない）
